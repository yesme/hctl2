# 大修类任务的多 Harness 分工方法论

> 说明：所有者提出全库文档大修任务（去死文、收束集群、删繁为简、全局一致性），并给出两个候选 harness 的互补短板画像；本文记录由此导出的分工方法论、种子清单与任务卡级开工建议。讨论稿，未拍板。<br>
> 基线：main @ fdde842（草案 v0.15.0）<br>
> 去向：若所有者拍板启动大修，化为大修任务书（宪章模板 + 各 harness 任务卡）；方法论本体暂无规范去向

## 方法论的起点：先拆回路，再排人

已知失败模式："fable 写 → gpt 挑错 → fable 改不对/改不全 → 往复五六轮 → 挑错的 gpt 自己动手"。这不是人选问题，是回路设计问题：**挑错和修复是两种能力，被串进了一个循环**。reviewer 能找到问题，fix 权却在一个修不对的人手里。

由此得到一条通用规则：

> **发现问题的回路终点必须是"能修对的人"，不是"原来写的人"。**

落到本次：fable 永远不持有"以细节正确性为验收标准"的写作任务；gpt 永远不持有"需要自己判断该不该存在"的开放任务。

## 按能力剖面拆任务，而不是整体发包

大修的四个目标不是同一种活，拆开各自匹配能力：

| 子任务 | 能力要求 | 建议人选 |
| --- | --- | --- |
| 大修宪章：死文判据、负面清单保留判据、目标文件结构 | 大局观、架构感；**不涉及细节正确性** | fable-5 起草，所有者拍板 |
| 死文普查：对照 decision-history 逐版本核销（agentd、Conductor、Zellij、Room Event 等），产出带行号的删/存/留清单 | 证据驱动、逐条回源 | grok-4.6（逐对象审计同构）；K3 做跨文档一致性与禁令清单盘点 |
| 正文改写执行 | 一致性、不自由发挥 | gpt-5.6-sol，带笼子进场（见下） |
| 终验 | 机械检查 + 二读 | 机械脚本为主，GLM-5.3 二读，所有者终审 |

## 给细节型执行者的笼子

gpt 类执行者的病是抓细节失大局、在小事上叠床架屋。对策不是叮嘱"注意大局"，而是把大局冻结成它不可改的输入：

- **冻结的骨架**：宪章阶段拍板的文件结构与每节职能，执行者只能填肉，不能改结构；
- **行数预算**：每文件/每节设上限，超出必须砍，不能扩；
- **概念白名单**：只许使用现有核心产品词与合同词，禁止新增具名概念（复用设计地图现成的文档纪律）；
- **负面清单白名单**：哪些"一定不要"值得留下，由宪章阶段的判据定死——只有"特别容易犯"或"特别 tricky"**且无法机械覆盖**的才保留；执行者只按白名单删留，不自行判断。

## 能机械的绝不交给 LLM

"正确的路只有一条，错误的 case 无穷无尽"的另一半含义：罗列禁令不如让错误进不来。可机械化的项顺手建成 CI，比写进文档有效：

- **死名扫描**：decision-history 的归并对照表与各版清扫表就是现成的退休词表——出现在白名单文件（decision-history、.memo）之外即 fail；
- **禁令密度统计**：每文件"不得/不能/拒绝"计数，出报告不设卡；
- **链接/锚点/版本戳一致性检查**。

工具本身按 CONSTRAINTS 走：新工具进 PR 需论证，构建走 Buck2 原生目标。

## 顺序与闸口

1. fable 出宪章 + 骨架 → **所有者拍板**（唯一的方向闸）；
2. grok + K3 出普查清单（带行号）→ **所有者拍板删/存/留**；
3. gpt 按拍板清单与骨架执行改写，一轮成稿；
4. 机械检查 + GLM 二读 → 问题清单直接给 gpt 修（**不回给 fable**）；
5. 所有者终审，打包一个 PR。

复用设计地图已有纪律：**审计最多两轮**——大修一轮、回归一轮；第二轮若主要发现第一轮新造的问题，回滚而不是继续打补丁。

## 任务卡（开工建议的落细）

1. **fable-5 · 宪章与骨架**：输入为种子清单与四点目标；产出 = 死文判据、负面清单保留判据（特别容易犯 / 特别 tricky / 不可机械覆盖，三者至少居一才留）、目标文件结构树、每节职能一句话、行数预算。产出形态是大修宪章，不写任何正文。闸口：所有者拍板。
2. **grok-4.6 · 死文普查**：输入为 decision-history 全文 + 现行文档；产出 = 带文件与行号的删 / 存 archive / 留三栏清单，每条注明核销依据（哪次转向取代了它）。
3. **K3 · 一致性与禁令盘点**：产出 = 跨文档同一事实的不同表述清单、全部"不得/不能/拒绝"禁令的逐条清单（标注是否可被机械检查覆盖）。
4. **所有者**：拍板两份清单。
5. **gpt-5.6-sol · 正文改写**：输入为拍板后的宪章、骨架、删改清单；笼子是冻结骨架 + 行数预算 + 概念白名单 + 负面清单白名单；一轮成稿。
6. **机械检查 + GLM-5.3 二读**：死名扫描、禁令密度、链接/锚点/版本戳一致性；问题清单直接给 gpt 修，不回给 fable。
7. **所有者终审**，打包一个 PR。全程审计两轮封顶。

## 一句话

fable 管"应该长什么样"（骨架级，拍板后冻结），gpt 管"逐字写对"（清单驱动，笼子里执行），grok/K3 管"证据从哪来"，机械检查管"不许回潮"，所有者管三个拍板点。谁也别进自己不擅长的回路。
