## 裁决

**fable 起草开工方案（结构层主笔），gpt 做输入供应商（事实附录）；不是零和分工。若强迫纯二选一，选 fable。**

唯一投 gpt 的是 codex 的"只能选一个主笔就选 GPT"——但它说的是**执行主笔**，不是方案起草。开工方案的本质是裁决提案（什么死、什么合、什么留、判据长什么样），是大局判断的载体——fable 的强项、gpt 已知病最贵的那一层。

## 依据二：gpt 起草的形态风险有实证

codex 手册本身就是 audition（kimi-c 的论证成立）：351 行、9 阶段、10 个阶段产物、12 条机械验证、10 条完成定义——都对，但这是"给每个风险前置立法"的形状。方案层起手就这样，产物几乎必然是各家 memo 的并集：所有阶段全保留、所有清单全拼接，第七份方法论长文而非一张能拍板的表。

反向对照：claude（fable 侧）交 114 行最短，第一句切根因（"往复五六次不是能力差，是交接方向错了"），种子发现全部可核实（E2EE 七处复述、三条底线六处、delivery 一份文件十一件事）。

## 三个硬条件（盖住 fable 的细节病）

1. **输入冻结**：fable 不自己查事实。输入 = 已核实材料——kimi-b 宪章雏形、claude 逐文件初筛、glm 不一致账本、四份种子台账；**缺的那块（权威表/矛盾表/一页架构摘要）由 gpt 先补齐**（codex 手册阶段 0–2 的设计，正是 gpt 强项）。方案的结构层 fable 写，事实附录 gpt 写，合成一份。
2. **形态约束**：产出是方案表（文件|动作|理由|需拍板?）+ 判据 + 目标树，不是散文。表格化后 fable 的细节错误没有发作面——错廉价、显眼、可定点修（与 kimi-c §"为什么细节病在此可控"同判）。
3. **回路方向锁死**：gpt/grok 对 fable 方案的反馈**不回给 fable 改**——方向分歧由所有者 amend，事实错误由 gpt 直接改（grok 方案同款）。方案层尤其容易复发"5-6 轮往复"，此条是关键闸。

## 附带观察

- 六份方法论已高度收敛（fable 结构权无修补权 / gpt 执行权无目录权 / 核验只报不改 / 机械先行 / 两轮闸），**方法论不需要第七份**；真正缺的是阶段 0 产出物，而脚手架已在桌上（kimi-b 宪章 + claude 初筛 + gpt 事实表缺口 + glm 账本）。起草活不大：fable 一天内出方案表，拍板后 gpt 即可开工。
- 本轮评审本身是分工方法论的预演：两家（glm、kimi）独立同判且论证路径不同（收敛表 + 形态实证 vs audition 论证）——裁决稳健。
