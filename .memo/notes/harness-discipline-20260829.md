# Harness 共性工作方法病：溯源与机制化解法

> 说明：所有者观察到各 harness 的三类共性工作方法病，本文记录溯源与"不依赖阅读理解"的机制化解法；短版纪律在根目录 `AGENTS.md`。<br>
> 基线：main @ 6dfc0a8（草案 v0.13.1）<br>
> 去向：`AGENTS.md`、`CONSTRAINTS.md`、`CLAUDE.md`、`.github/pull_request_template.md`、`.github/workflows/code.yml` 的 `PR contract` job（已落地）

## 三个病（所有者原述）

1. **指令关系丢失**：human 指令是 consistent 且累积的（"考虑 A、也考虑 B，给出综合方案"），harness 却常把最新一条当替换，丢掉 full picture、钻牛角尖；只有 human 显式说"重来"（如 mac 上 chat server 用哪版 rustc 的讨论）才允许推倒既有前提。
2. **补丁摞补丁**（codex 尤甚，claude 也有）：把所有输入机械地当硬约束，为一个特别小的（甚至本可协商的）初始诉求不断叠床架屋，代码极度膨胀。正确做法是先 identify/locate 需求在整体 topic/architecture 里的位置，结合现状 rephrase/refine，抓大方向而不是具体接口——接口越来越是 for agent 的，自己设计自己用。
3. **重新发明轮子**：面对问题倾向用自己的方案而不查业界 best practice。案例：a) 多 harness 协作调研不足，案例多靠 human 直接提供；b) 用自建 script 绕过构建系统 native actions，一个 PR 因此被 abandon 重来；c) webserver 自己用 Rust 写了一个。

## 溯源

共同的根：**full picture 不在任何 harness 必经的路径上**。人类团队靠设计文档、需求台账、评审门槛把 full picture 制度化；harness 是会话级执行器，没有环节强迫它先过一遍全局。三个病是同一个根在三个环节的表现：

- **病 1 的机制**：指令被当成流水消费，没有被编译成活的约束集。模型的世界是上下文窗口，最新消息最显著，会话切换与压缩再丢一轮；"合取"退化成"最新覆盖"。
- **病 2 的机制**：字面服从 + 局部最小编辑偏好。用户文本被当 spec 而不是意图信号，不敢重述、不敢协商；在被抱怨的点上打补丁局部最省、全局纯增量，循环里没有东西给代码总熵定价，重设计又感觉像越权。病 1 丢了合取，病 2 保住了合取但把每项都冻成字面硬约束——互为镜像。
- **病 3 的机制**：对模型来说生成比检索便宜。写代码是本能、立刻有产出；调研要工具要时间、产出不确定，知识截止又让它对生态现状不自信；且它感受不到维护成本——自建的代价它一分钱不付。

一句话：病 1 丢了"指令之间"的图，病 2 丢了"需求与架构之间"的图，病 3 丢了"自己与业界之间"的图。

## 解法：把认知义务变成机械关卡

放文件里靠"阅读理解"不可靠。可靠性阶梯（弱→强）：散文 → 强制注入 → 强制产出物 → 机械关卡 → 独立评审。落地取后四层：

1. **强制注入替代主动阅读**：约束集落成 repo 文件 `CONSTRAINTS.md`（所有者维护、harness 只读），full picture 的权威源头不再在 agent 的记忆里；`AGENTS.md`/`CLAUDE.md` 被各家 harness 开工自动加载。
2. **强制产出物让跳步可见**：PR 模板三个必填节（定位与重述 / 当前生效约束集 / 业界方案调研）。LLM 对必填字段的服从率远高于对散文的服从率；填了敷衍内容也把违规变成可见、可查、可审的三小段文字——human 的审读杠杆从通读 diff 缩小到读三个字段。
3. **机械关卡完全不依赖理解**：CI `PR contract` 检查三节存在且非空；PR 新增脚本/工具/三方组件（`*.sh`、`src/build/tools/`、`src/third-party/`）而调研节只写"不适用"时直接红。
4. **独立评审席**：一个 harness 拿窄 checklist 查另一个的产出（约束集复述对不对、是叠补丁还是该重设计、调研真查了还是编的）——独立性替代自觉性。已在人肉跑，checklist 即三条纪律。

选 PR 边界做主关卡的原因：五家 harness 的 hook 机制各不相同，**PR 是所有 harness 的公共汇合点**，一次配置全体生效。

## 诚实的边界

- 机制保证"填了"，不保证"填得好"——字段可以被填进垃圾。human 的角色不消失，只是杠杆变了。
- `PR contract` 是 `code.yml` 里的一个 job，被已 required 的 `CI gate` 聚合，所以**不需要**另改 branch protection。代价：`pull_request` 触发加了 `edited` 类型，代码 PR 修改描述会整体重跑构建——改描述低频，接受这个代价换取"修完描述关卡自动转绿"。
- 新组件信号的模式（`*.sh` 等）是保守启发式，会漏不会误伤；宁可漏，避免为关卡本身叠床架屋（病 2 的教训适用于关卡自己）。
