## 一、样本与尺子

10-06 到 10-20，#363 到 #484，共 122 个 PR，其中 57 个有评审记录。每个 PR 谁写、谁审、审了几轮、谁找到了什么、谁在有挡合入问题的提交上写了「可合」、谁的证据后来被证明不对，按 PR 评论逐条整理过；要紧的几处主笔另对过代码。

四种能力：

- **统筹**：拿到任务书能自己推进——看懂开工书，照规矩读评论、处理评审，该报所有者的报、开工书里有答案的不报，报告和处理说明说的是真事。主笔这一席还包括排活、写开工书、做裁定。
- **编码**：首稿的质量（评审找出几条挡合入的问题），改得快不快、一轮能不能收住，改的时候会不会带进倒退。
- **找错**：坐找问题席时，能不能找到作者和别席都没看到的问题，有没有实跑反例，写了「可合」之后会不会被别人接住。
- **验收**：坐核验席、走查或照手册从零跑时，跑得真不真，结论可不可靠——会不会在有挡合入问题的提交上写「可合」。

每件活另按三样分：改动量；开放程度——**照单**（规格写清了照着做）、**半开放**（规格内要自己设计）、**开放**（要先调查、做取舍：调研、探针、排查、接一家没摸过的 harness）；难度——**高**（状态、并发、丢失后恢复、外部副作用只做一次、凭据、控制面），**中**（命令行、投影、测试设施），**低**（小修）。被挡的条数要放在这三样里看，也要看审它的是谁：同样的活，Codex 审出来的条数天然比只读代码的席位审出来的多。

额度（所有者 2026-10-20）：Claude、Codex、Antigravity 各 $200，Grok $100，都富余；DeepSeek 按量付费，可以放开用；GLM 约等于 5 个 Kimi，Kimi 约等于 Qwen；MiniMax 有额度但用不上（§二 第 51 条 ⑦）；Muse 不可用。卡人的不是额度，是同时开着的会话就这么几个，以及每一席都要所有者手发「继续」。

## 六、看出来的几件事

1. **「两席把关」常常只剩一席。** 核验席在找问题席挡了的提交上写「可合」十多次：有的是几十秒内并行写的，有的是没读到已有的「不可合」。表现最好的核验是 DeepSeek 在 #467 那样：先把找问题席报的问题逐条复现，再从零跑。
2. **区分各家最准的一条是证据诚不诚实。** 代码首稿的问题评审能接住；编造的 ID、不存在的名字、说改了而没改，会让评审白做。
3. **首稿的挡合入问题集中在状态、并发、丢失后恢复。** 丢确认、重试、进程在两轮之间死掉、多个槽位共用配置，各家都一样；能稳定抓到这类问题的是 Codex，Claude 两席次之。
4. **安装与环境这一层的问题只有从零装包实跑抓得到。** #399 的金样、#410 的安装路径、#423 被盖住的两个问题，都是走查或完整包抓出来的，代码评审全漏了。
5. **被挡的条数要看评审席强不强。** #464 只被挡 1 条，但找问题席是只读代码的 Grok；同类问题在 #467 被 Codex 判成 P1。H1 与 H3 的条数不能直接比。
6. **核验的漏判集中在难 PR。** GLM、Kimi 在简单 PR 上基本不出错；难 PR 不能让它们单独把关。
7. **开放的活谁接得住。** Claude 两席、Codex、Muse 接得好；Antigravity 能接但证据要盯；DeepSeek、GLM、Grok 碰到开放的活明显吃力，适合规格写清楚的活。

## 七、据此改的

所有者 2026-10-20「全都落下来」，落在 07 §二 第 53 条、§六 与 `AGENTS.md`：
