# 全库文档大修：多 Agent 分工方法论

> 说明：所有者提出全库文档大修任务（去死文 / 收束集群 / 删繁为简 / 严丝合缝），并给出 gpt-5.6-sol 与 fable-5 的历史行为画像，问如何安排。本文记录分工结构与判据；大修本身未开工，阶段 0 章程待立。<br>
> 基线：main @ 13504eb（草案 v0.15.0）<br>
> 去向：待大修章程立项时消化（`.memo/design/`）；方法论本身不进 `docs/design/`

## 一、输入：所有者原述

任务四要点：

1. **去死文**：演化遗留的过时内容，该删的删、该归档的归档；
2. **收束集群**：回到 big picture，内容结构与文件结构上找可整合、可拆进目录、跨域同构可合并的；
3. **删繁为简**："正确的路只有一条，错误的 case 无穷无尽"——『一定不要』列表要极谨慎，只有特别容易犯的、特别 tricky 的才落下来；可 mechanically cover 的也不必靠文档；
4. **严丝合缝**：全面大修，前后一致、整体性高。

Agent 画像与历史失败形态：

- **gpt-5.6-sol (xhigh)**：逻辑缜密、一致性强；但抓细节没有大局观，会钻牛角尖，在一两个细节问题上叠床架屋产生无效内容；
- **fable-5 (xhigh)**：愿景协作强、有架构意识；但细节老写不对。历史形态：fable 写 → gpt 挑错 → fable 改又没改对/改全 → 往复 5-6 轮 → 最后让挑错的 gpt 自己改完。
- 另可用：grok-4.6 (xhigh)、K3 (high)、GLM-5.3 (max)。

## 二、核心判断

**两个病各有触发条件，拆开阶段就能各自避开：**

- gpt 的病（钻细节、叠床架屋）只在**它拥有结构决定权**时发作；
- fable 的病（细节写不对）只在**它拥有改写权**时发作；
- 5-6 轮往复的根源是**作者 ≠ 修复者**：gpt 挑出的错由 fable 改，两个模型对文档的心智模型已经分叉，修补永远差半步。修法不是换人重试，是**评审者即修复者**——gpt 挑出的细节问题由 gpt 自己改。

因此：**fable 只做结构总图、不碰正文；gpt 只做执行改写、不发明结构；所有者只在两处便宜的控制点拍板（章程、总图）。**

## 三、分工表

| 阶段 | 谁做什么 | 产出与闸门 |
| --- | --- | --- |
| 0 · 立章程 | 所有者拍板（GLM 可代拟底稿）：冻结删除判据与负例判据 | 章程落 `.memo/design/`。删除判据原文引用现有文档纪律："精简只针对重复权威、无第一阶段用途的对象和补丁衍生对象；能够回答独立实现选择、交接、故障或权限边界的设计不得因篇幅被删除"（v0.8 删过头的教训，防过度精简的护栏） |
| 1 · 结构总图 | **fable**：只做 big picture——目标文件结构、合并/拆分/归档/删除台账，每条一行理由；**禁止改写任何散文** | 重排提案，状态"待拍板" |
| 2 · 拍板总图 | 所有者增删 amend；比较两份地图远比比较两版重写便宜 | 冻结的结构 |
| 3 · 分片执行 | **gpt**：按冻结图分 5-6 切片执行（根层 README → 设计层 → 合同层 → research → .memo 归档 → src 内文档），一切片一 PR，走 PR contract；每片自查清单，细节问题 gpt 自己改（评审者即修复者） | 一串 PR |
| 4 · 验收 | **机械：K3 + 脚本**（死链、词形一致、版本号一致、死名残留 grep：agentd/tmux/Zellij/Conductor/Electron）；**fable**：只读一遍，只问"作为整体是不是一个系统、有没有大东西丢了"（结构级，不挑细节）；**grok**：只抽审最危险的两片——合同层与负例清扫 | 核销记录 |

辅助角色：**GLM** 持"不一致账本"（刚完成全库交叉核对，手上有最新跨层差异图：根 README 陈旧、cleanup-backlog 过期、F1/F2/F11 无裁决等），并可代拟章程底稿。

## 四、负例三留原则（对应任务第 3 点）

仓库已裁决过一半（`notes/doc-cleanup-backlog-20260825.md` §1："把每条负例问一遍'正确道路写清了它还进得来吗'——进不来就删，进得来才说明正确道路没写清，改正面句而不是加禁令"）。完整原则：

只有三类『不要』留在文档里——

1. **特别容易犯的错**；
2. **特别 tricky 的错**；
3. **可机械化的**——转成 CT-* 契约测试用例。负例进了测试就不再占文档篇幅，还顺带获得可执行对偶，缓解"合同密度无可执行对偶"的旧病（kimi 0.10.2、gemini 同轮）。

其余一律改写成正面陈述或删除。

## 五、防叠床架屋的机械闸

- **每个切片限两轮评审**，沿用既有审计纪律："第二轮若主要发现第一轮新增内容的问题，则回滚该片而不是继续打补丁"；
- 总图冻结后 gpt 无结构决定权，想叠也没有落点；
- fable 不进入"照 gpt 意见改细节"的循环——那个循环就是历史失败的形态。

## 六、执行前提

1. **先机械后人**：链接/词形/版本/死名检查先做成 CI 脚本再动第一篇文档；LLM 评审面收窄到只有 LLM 能判的东西。负例如此，一致性校验更是如此（kimi 历史上纯机械检查抓到过真问题，不烧 xhigh）。
2. **素材已存在，不重新发现**：大修输入不从零调研——`doc-cleanup-backlog`（13 条过强断言 + 禁令清扫原则）、`review/20260830-v0.15.0/glm-20260830a.md` §三A（陈旧清单）、grok 同基线判断（PR #48）、v07-v012 复盘债务表，四份现成台账合并即为死文与收敛清单的种子。fable 的总图消费它们，不重新发明。
