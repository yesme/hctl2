## 挡演示的问题（先读）

### P1-1 · 安装包里没有 Agency 写入工具要求的 `libexec/hctl2/hctl2-tool`

- 现象：按手册装包（`install.sh --prefix …`）后走写入链，第一轮派工即失败，`invocation show` 报 `failed / Agency cannot fulfill this dispatch`；Agency 租户事件是 `cannot_fulfill {code: WRITE_TOOL_UNAVAILABLE}`。
- 依据：`src/agency/src/write.rs` 的 `tool()` 只认 `HCTL2_TOOL_BIN` 或 `HCTL2_INSTALL_ROOT/libexec/hctl2/hctl2-tool`；实际安装布局里工具在 `payload/bin/hctl2-tool`（`prefix/bin/hctl2-tool` 软链指向它），`libexec/hctl2/` 下只有八个依赖组件，没有 `hctl2-tool`。CI 与本仓测试都在 Buck 产物环境里跑，工具路径由测试环境供给，所以从没红过。
- 复现：装包 → `agency pair`/`accept`/`project select` → 发写入型调用 → 看 invocation 与 Agency 事件（`~/.hctl2/agency/tenants/*/tenant.sqlite` 或状态根对应库）。
- 走查中的绕法：给控制面与 Agency 设 `HCTL2_TOOL_BIN=$HCTL2_INSTALL_ROOT/bin/hctl2-tool` 后整条链恢复（下文 A/C 链即绕过后走通）。演示要么修安装布局、要么修 `tool()` 的查找路径。

### P1-2 · GitHub issues 任务源「建卡不绑卡」

- 现象：B 链（canary）`task create` 平台侧成功（issue [#20](https://github.com/yesme/hctl2-canary/issues/20) 建出），契约 `task adopt` 成功；但写入派工的预览报 `AGENCY_ERROR / SOURCE_UNAVAILABLE: Task has no bound card`。原命令重投 `task create`（幂等回读）与等待 60 s 后重试 preview 均无效。B 链至此走不通；E 段的手动只读探针与 F 段逃生口一的手动路径也被挡住（判定改以常驻用例为据，见下）。
- 复现：注册 GitHub 外部 repo → `task connect github_issues` → `task create`（建卡成功）→ `invocation preview`（no bound card）。修复在 #432。
- **勘误（2026-10-19，按 Claude 对 Codex #432 实录的只读核对）**：本实录原把此后的一串报错（A 链 Project 的 `project select` 连续 5 次 `VERSION_CONFLICT`、C 链 Project 的 select 冲突、A 链 repo 上 bare Task 的 `task_source not found`）记作「P1-2 的 source 污染」，**是记错了**。Codex 逐项核对了保留的输入：那三次 `project select` 声明的 `roster_version` 不是当时的版本（1 对应的名册已是 v3，另两次是 `null` 和不存在的 2）；裸 Task 用的 source 属于另一个 Repo。这些报错是**走查输入错误**，不是状态污染。原文的「采样证明 repo/project 版本稳定、变的是 task source 记录」一段随之作废。「报错把人引向错误原因」一事 Claude 已在 #432 记为跟进（P2 第 1 条）。

### P1-3（嫌疑，第二轮定性）· 写路径上 harness 映射或执行时序可判错

第二轮派工（工种冻结为 claude-code）以 `deadline expired` 收场；与 deadline 同秒建出的执行目录里是 **Codex 会话**（workspace `agency-codex`、cwd `codex-session-*`）。dispatch→执行目录的钉死证据（Agency 租户库）已随走查清理丢失。三样证据与时间线见「观察与过程失败」第一条；P1-1/P1-2 修复后的第二轮优先复现此场景再定 P1 或观察。
