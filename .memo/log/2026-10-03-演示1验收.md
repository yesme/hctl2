# 2026-10-03 · 演示 1「协作现场」验收实录

> 说明：`log/`，写完即冻结。Fable 在第 1 包 #307 合入后（main `a075a66`），用 main 构建的安装包与 `hctl2` / `hctl2-control`，在私有目录、默认端口上从零装了一套，照 [`07-demo-kickoff.md`](../design/p2-control-20260906/07-demo-kickoff.md) §三「演示 1」四步手工走了一遍。结论与所有者裁定在 `07` §三；本文只记做了什么、看到什么，给写演示手册的人照抄命令。

## 环境

- 构建：`cd src && ./buck2 build root//packaging/dependencies:package root//apps/cli:hctl2 root//apps/control:hctl2-control --config hctl2.xz_preset=fast`
- 安装：解开 `hctl2-0.0.0-macos-aarch64.tar.xz`，`HCTL2_INSTALL_ROOT` 指向其中的 `payload/`，`HCTL2_CONTROL_BIN` 指向构建出的 `hctl2_control`；`hctl2 --json --root <根目录> …`。根目录路径要短：Unix socket 路径超过约 100 字节会报 `path must be shorter than SUN_LEN`。
- 端口：Tuwunel 6167、Cinny 6168、Gitea 3001（包的缺省）。Cinny 要单独 `hctl2-services start cinny`（`HCTL2_STATE_ROOT=<根目录>/services`），`hctl2 start` 只拉 Tuwunel，Gitea 在首次用到时拉起。
- 人类账号：在 Tuwunel 用 `<根目录>/services/config/tuwunel-registration-token` 注册 `@yesme:hctl2.localhost`（Cinny 的注册页就是这个流程）。第一个注册的人成为 Tuwunel 服务器管理员，会多看到一间 Admin Room。

## 四步与看到的

### 1 · 用命令建 Project

1. 本地建一个有一次提交的小 git 仓库 `apollo`。
2. `hctl2 repo register --input register.json --key register-apollo`，再带 `--preview-token` 提交。输入：`{"name":"Apollo","origin":"local","platform_path":"apollo","local":{"machine":"control","path":"<绝对路径>"},"default_source":"gitea_issues"}`。首次用到 Gitea 时它被拉起，仓库 `hctl-<control 前 16 位>/apollo` 建出，登记 `pending`。
3. `hctl2 repo register --confirm <repo_id> --version 3 --platform-repo-id 1 --key confirm-apollo`，两步确认后 `active`。
4. `hctl2 project create --input project.json --key create-apollo`，两步确认。返回 `project_id`、`main_room_id`、`receipt.matrix_room_id`、`delivery: confirmed`。再提交同一 key 返回同一个 Project。

### 2 · 在 Cinny 里看到主 Room

1. `hctl2 project members --input members.json --key invite-yesme`，两步确认。输入：`{"project_id":…,"project_version":1,"rooms":[{"key":<room show 里的 binding.key>,"version":{"state":<binding.version>}}],"users":["@yesme:hctl2.localhost"],"invite":true}`。回执 `members: [{membership: invite}]`。
2. 人类账号这边 `/sync`：收到「Apollo」的邀请；接受后在主 Room 里发两条消息（人在 Cinny 里打字，这里用同一套 Matrix 接口代替）。
3. 没有用眼睛看 Cinny 的屏幕，核的是 Cinny 用的同一套 Matrix 客户端接口；环境留给所有者自己打开看。

### 3 · 开 Topic、带前情提要

1. `hctl2 room draft --input draft.json`，`selection` 选那两条消息的事件 ID。返回 `automatic_summary: "not_configured"`、`rule_reference: "hctl2.brief.verbatim.v1"`，`fragments` 里是逐字原文与来源指针——未配置模型时的第一档，和 v0.18.12 一致。
2. 人补写各节后 `hctl2 room create-topic --input topic.json --key topic-readme`，两步确认；`brief.sources` 照抄草稿的 `fragments[].source`，`roster_confirmed: true`。返回 `room_id`、`receipt.matrix_room_id`。
3. `hctl2 room hierarchy <project> <main>`：`children` 里有这间 Topic，`carrier_space_id` 是主 Room 的承载 Space。Topic 房间的 Matrix 状态里有 `m.space.parent` 指向它。
4. `hctl2 room show <project> <topic>`：`brief` 是材料引用（`material_id`、`byte_digest`）。Topic 房间的时间线里只有建房状态事件，**没有消息**；成员只有 `@hctl2_control`，**人不在里面**；人也不在承载 Space 里，所以 Cinny 里两间房是平铺的，看不到树。再跑一次 `project members` 把人邀进 Topic 后，Cinny 能看到它，仍是平铺。

### 4 · 平台上的 issue 认领成 Task

1. control 建的 Gitea 仓库是私有的，人没有账号。用包里的 `gitea --config <根目录>/services/config/gitea/app.ini --work-path <根目录>/services/data/gitea admin user create …` 建人类账号，再用 control 存在钥匙串里的管理员令牌（`security find-generic-password -s hctl2 -a gitea:<control_id>:admin -w`）调 Gitea API 把人加成协作者。**这两步 hctl2 没有命令。**
2. 人以自己的账号在 Gitea 开 issue #1。
3. `hctl2 task connect`（`candidate_id: gitea_issues`, `consent: true`）→ `task attach`（`approved_scope: "1"`）→ `task refresh` → `task board <project> <source>` 看到 issue #1 → `task claim`（`entity_id: "1"`）。每条都两步确认。
4. `hctl2 task show`：`lifecycle: open`，`entity.immutable_external_entity_id: "1"`，标题照抄 issue。

### 5 · 重启后都还在

1. `hctl2 room save-view-state` 存一条未发送草稿。存下 10 个查询的输出：`project show / overview / list`、`room show` 主 Room 与 Topic、`room hierarchy`、`room timeline` 主 Room、`room view-state`、`task show`、`repo show`。
2. `kill -KILL <control.pid>`；`hctl2 services status` 报 `transport error`；`hctl2-services stop` 把 Tuwunel、Gitea、Cinny 全停掉。
3. `hctl2 start`。约 1 秒后 `room view-state` 能答；Tuwunel 与 Gitea 都回来了（Cinny 要手动再起）。
4. 10 个查询重跑，去掉 `unsigned.age` 这类易变字段后逐字节一致。人类账号 `/sync` 看到的两间房和消息都在；Gitea 的 issue #1 在；重启后再跑一次 `task refresh`（要碰 Gitea）正常。

## 钥匙串

control 把 Gitea 管理员令牌存在 macOS 钥匙串（服务名 `hctl2`），每条碰 Gitea 的命令都读一次。新构建的 `hctl2_control` 对钥匙串是新程序，每次读都弹授权框，点「始终允许」后不再弹；没有屏幕的会话（Codex 本机跑 B1）弹不出来就直接失败，报 `User interaction is not allowed`。代码里有不碰钥匙串的私有文件后端（`SecretStore::user_file`），但没有开关接出来。

## 没做的

- 没用眼睛看 Cinny 的屏幕（见上）。
- 没验多房间部分失败、权限等级调整；#307 自己也标了未验。
- 没跑 Request 那条线（`request create / resolve`）；B1 的自动化测试覆盖了，演示 1 的四步里没有它。
