## 环境

- 构建：`cd src && ./buck2 build root//packaging/dependencies:package root//apps/cli:hctl2 root//apps/control:hctl2-control --config hctl2.zstd_preset=fast`。
- CLI 与 control 的路径取自构建输出里的精确路径（`…/apps/cli/__hctl2__/hctl2`、`…/apps/control/__hctl2-control__/hctl2_control`），没有用 `find … | head -n 1`。DeepSeek 在 #315 的复审里实测过：构建过发布包的机器上，那条 `find` 会先命中导出包里的旧副本。
- 安装：解开 `hctl2-0.0.0-macos-aarch64.tar.zst`，`HCTL2_INSTALL_ROOT` 指向其中的 `payload/`。根目录用短路径（`/tmp/hd1/work/root`）。
- 启动：`hctl2 --root <根目录> start --secret-backend user-file`。`status` 报 `policy.credential_storage: "user-file"`，全程没有碰系统钥匙串。
- 端口：Tuwunel 6167、Gitea 3001，开跑前确认没有监听。Cinny 没有起：下面核的是 Cinny 用的同一套 Matrix 客户端接口，没有用眼睛看屏幕。
- 人类账号：`@yesme:hctl2.localhost`，用注册令牌经 Matrix 接口注册。

## 做了什么

照 [`docs/demos/demo-1.md`](../../docs/demos/demo-1.md) 的 §二 到 §五.2 走：起服务、注册人类账号、登记仓库并确认、建 Project、把人邀进主 Room、人加入并发两条消息、机械起草、`room create-topic` 两步确认。

和手册只有一处不同：**建完 Topic 之后没有再跑 `project members` 把人邀进 Topic 房间**。`topic.json` 照手册原样，没有写 `invites` 字段。之后直接用人类账号的令牌去看。

## 看到什么

### 建 Topic 的预览与提交

- 预览返回 `effect_summary` 与 `preview_token`。`effect_summary.invite_defaults` 与 `effect_summary.invites` 都是 `["@yesme:hctl2.localhost"]`；`effect_summary.effects` 的三个操作是 `chat.create`、`chat.opening`、`chat.members`。
- 提交返回 `state: "confirmed"`、`delivery: "confirmed"`，另有：
  - `opening.delivery: "confirmed"`，`opening.receipt` 带 `event_id` 与 `content_digest`；
  - `invite_defaults` 与 `invites` 同预览；
  - `invite_results[0]`：`delivery: "confirmed"`，`receipt.members` 为 `[{"membership":"invite","user_id":"@yesme:hctl2.localhost"}]`。

### 缺口 1：开 Topic 的人自己不在 Topic 房间里 —— 已补上

提交之后，人类账号的 `/sync` 里 `rooms.invite` 立刻有 Topic 房间（名字「README 起草」）。不需要再跑 `project members`。人用 `/rooms/<房间>/join` 接受，返回 `room_id`。

### 缺口 3：Topic 房间里是空的 —— 已补上

人加入后读 Topic 房间的消息，`m.room.message` 恰好一条，发送者是 `@hctl2_control:hctl2.localhost`，`msgtype` 为 `m.text`，正文：

```
话题与目标
起草项目说明文档

已定事实与理由
- 已确定先做 README

来源
- 消息：房间绑定 main-…，事件 $…
- 消息：房间绑定 main-…，事件 $…
```

提要里为空的两节（分歧与问题、约束与材料）没有出现在正文里。`room show` 的 `room.brief.material_id` 仍在，顶层 `brief.context_and_goal` 是「起草项目说明文档」，控制面保存的材料没有变。

### 缺口 2：人不在承载 Space 里，看不到树 —— 已补上

- 同一次 `/sync` 的 `rooms.invite` 里还有一间类型为 `m.space`、名字「Apollo」的房间，它的 ID 就是 `room hierarchy` 返回的 `carrier_space_id`。
- 人加入这个 Space 之后，以人类账号调 `/_matrix/client/v1/rooms/<Space>/hierarchy`，返回三个节点：Space「Apollo」（两个子节点）、主 Room「Apollo」、Topic「README 起草」。主 Room 与 Topic 都在这棵树里。

### Topic 房间的时间线

人加入之后 `room timeline` 共 14 个事件：建房与状态事件 10 个（`m.room.create`、`m.room.power_levels`、`m.room.join_rules`、`m.room.history_visibility`、`m.room.guest_access`、`m.room.canonical_alias`、`m.room.name`、`m.space.parent`、`io.hctl2.creation`、`io.hctl2.topic_creation`），`m.room.member` 3 个（control 加入、人被邀请、人加入），`m.room.message` 1 个（开场消息）。人加入之前的数目这次没有单独取。
