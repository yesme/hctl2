# 2026-10-07 · 演示 2「只读派工」验收实录

> 说明：`log/`，写完即冻结。Fable 在第 5 包主链 #372 合入后（main `6ced659`，含 3d #362、小活 M #378），用 main 构建的安装包与 `hctl2` / `hctl2-control` / `agency`，在私有目录、默认端口上从零装了一套，照 [`07-demo-kickoff.md`](../design/p2-control-20260906/07-demo-kickoff.md) §三「演示 2」的一行走了一遍：从 Room 发起一次只读调用，命令行给出派工预览，确认后 harness 在 Herdr 里运行，结果回到 Room。结论与所有者裁定在 `07` §三；本文只记做了什么、看到什么。

## 结论先说

- **派工主链在真实 Claude Code 上走通了**：预览冻结了请求正文和 Room 的当前窗口（人的两条消息），确认后 16 秒内 `pending → running → completed`，回答引用了 Room 里的讨论，由 `@hctl2_control` 投回 Room；第二次派工复用同一个会话（同一个 Session ID、同一个进程），6 秒返回。
- **从安装包起不来 Agency 的 harness**：macOS 打包时对 Herdr 重新签名，装出来的二进制摘要和 `lock.json` 记的下载摘要不同，Agency 以 `HERDR_DIGEST_MISMATCH` 拒绝上架，工种目录为空。本次用锁定的原始下载件绕过去才走完后面的步骤。**这条要修，不修演示 2 不能从安装包演。**
- 「隔离的工作副本」这半句没有做到：harness 在 Agency 的私有执行目录里跑，没有仓库的工作副本，也没有任何工具（`--restricted --tools ""`）。只读调研这一类用不到，但演示表里这半句要改口或等第 6 包。

## 环境

- 构建：`cd src && ./buck2 build root//packaging/dependencies:package root//apps/cli:hctl2 root//apps/control:hctl2-control root//agency:agency --config hctl2.xz_preset=fast`（本机，`--local-only --no-remote-cache`）。
- 安装：解开 `hctl2-0.0.0-macos-aarch64.tar.zst`（`sha256` 核对 OK），`HCTL2_INSTALL_ROOT` 指向 `payload/`，`HCTL2_CONTROL_BIN` 指向构建出的 `hctl2_control`；`hctl2 --json --root <根目录>/state …`。
- 密钥后端：`hctl2 start --secret-backend user-file`，不碰钥匙串（演示 1 用钥匙串时每条命令弹授权框）。
- 端口：Tuwunel 6167、Cinny 6168（`hctl2-services start cinny` 单独起）、Gitea 3001（注册本地仓库时拉起）。
- Agency：`agency --root <根目录>/agency serve`，不带 `--script-config`，`HCTL2_AGENCY_IDLE_MS=600000`。`claude` 取 PATH 上的 Claude Code 2.1.291。
- 人类账号：用 `<根目录>/state/services/config/tuwunel-registration-token` 注册 `@yesme:hctl2.localhost`。

## 步骤与看到的

### 1 · 建 Project（照演示 1）

`repo register` 两步、`--confirm` 两步、`project create` 两步，返回 `project_id`、`main_room_id`、`delivery: confirmed`。首次用到 Gitea 时它被拉起。

### 2 · Agency 上架、配对、接受工种、建 Profile、选人

1. `agency serve` 起来后 `status` 报 `ready: true`，但 `serve.err` 里一行：`harness not cataloged: HERDR_DIGEST_MISMATCH: installed Herdr sha256 6a59633e… does not match lock.json`。装出来的 `payload/libexec/hctl2/herdr`（22,099,008 字节，ad-hoc 签名，标识 `herdr-5555…`）和 `lock.json` 的 `macos_arm64` 下载件（22,210,016 字节，linker-signed，`5173a3e0…`）不是同一份字节；差异来自 `src/packaging/dependencies/platforms/macos/package.sh` 第 45 行对每个 `libexec` 组件 `codesign --force --sign -`。Agency 的 `launch.rs::installed_herdr` 拿装出来的文件去比下载摘要，macOS 上永远不等。测试没发现，因为 `herdr_test` 等用 `HCTL2_LOCKED_HERDR` 直接指向原始下载件。
2. 绕过：另建一个安装根，只放原始下载件（摘要等于 `lock.json`），`HCTL2_INSTALL_ROOT` 指过去重启 Agency。目录里出现 `claude-code`（harness `herdr` protocol-22，revision `2.1.291 (Claude Code)`，model `none`）。
3. `agency pair --binding-id local` 是在目录为空时做的，它冻结了空目录；之后 `agency accept` 报 `PROFESSION_CHANGED: candidate is not in the accepted catalog`，`recovery_action: refresh_binding`——**但没有这样的命令**（`agency` 只有 `pair / bindings / catalog / accept`）。绕过：换个 `--binding-id local2` 再配对一次。
4. `profile create`（`mode: read_only`、`permissions: ["context.read"]`、`required_capabilities` 全 false、`max_context_bytes: 65536`）两步；`project select` 两步，`candidate_validation: accepted_catalog_and_project_policy`，`roster_version: 1`。

### 3 · 人进 Room、发问

`project members` 邀请、人接受；人发两条：「我们在给 Apollo2 的命令行选参数解析库：clap 还是 argh？」「重点只看两点：编译时间和二进制大小。不改代码，先给个比较和推荐。」

### 4 · 预览、确认、看结果回 Room

1. `invocation preview --input invocation.json --key invoke-1`：`request` 是中文一段（只读、不改文件、200 字内、末尾「推荐：<库名>」），`target: research`，`profile` 取上一步的 revision，`deadline_ms` 10 分钟。预览里 `effect_summary.assembly.bundle.document.entries` 两条、逐字节：请求正文；Room 的当前窗口（解出来正是人的两条消息）。`preview` 节有 binding / profession / profile / room / selection / checks（Project v1、Repo v4、Room v2）。
2. `invocation start … --preview-token <预览给的>`：返回 `invocation_id`、`owner`、`prepare_effect`。
3. `invocation show` 每 5 秒一次：`t+1s pending → t+6s running → t+16s completed`，`reason: "read-only answer admitted; not Task acceptance"`，`results[0].output` 是回答原文（开头「Room 里明确只看编译时间和二进制大小两点……」，末尾「推荐：argh」）。
4. `room timeline`：`@hctl2_control` 投回同一段回答；人的 Matrix 客户端 `/messages` 看到同一条。
5. Herdr 这边（私有服务，`/tmp/hctl2-herdr-<哈希>/herdr.sock`）：`agent.list` 一条——`agent: claude`、`agent_status: idle`、`agent_session: 24181811-…`、标题「Clap 与 argh 命令行库对比」、`cwd` 在 `/private/tmp/hctl2-exec-…/session-…`；`pane.read` 看到会话的屏幕：注入的正文（请求 + Room 窗口 JSON）、回答、「Worked for 6s · done 2:20 AM」。进程是 `claude --restricted --settings … --strict-mcp-config --tools "" --plugin-dir …`。
6. 第二次：人再发一句「如果以后要加 shell 补全，argh 还够用吗？」，`invoke-2` 预览、确认，`t+6s completed`，回答以约定的 `DEMO2_SECOND` 结尾、回到 Room；Herdr 里还是同一个 Session ID、同一个进程，输入框清空了（第一轮结束后输入框里曾留着 Claude Code 自己建议的下一句「实测一下两者的编译时间和二进制大小」，第二次派工把它换掉了）。

### 没有做、没有看的

- 没用眼睛看 Cinny 和 Herdr 的界面；核的是同一套接口（Matrix 客户端 API、Herdr socket API）。环境留着给所有者看：Cinny `http://127.0.0.1:6168/`，Herdr `HERDR_SOCKET_PATH=/tmp/hctl2-herdr-<哈希>/herdr.sock herdr`。
- 没走取消、截止、重试、重启恢复（主链的用例盖了；演示 2 那一行不要求）。
- 没从安装包的 `install.sh` 正式安装，照演示 1 的做法直接用 payload。
- Linux 没试。

## 观察（不挡演示，记给改的人）

- 「auto mode on」：pane 里 Claude Code 的权限模式显示为 auto，是从用户全局设置继承的；本次隔离靠的是 `--restricted --tools ""`，不靠权限模式。README 可以写一句。
- `invocation show` 的 `results[0]` 只有 `output` 和 `record`，没有 schema 和证据级别的字段；回答在 Room 里是 `@hctl2_control` 发的，没有标明是哪个 Invocation、哪个工种答的。人在 Cinny 里看不出这条是派工结果。
- 派工的回答是 Claude Code 凭知识答的（它自己也写了「经验量级，并非实测」）；演示时问题要选成不需要看仓库的。
