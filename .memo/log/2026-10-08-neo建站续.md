## 原话

1. 所有者：

   > 我让deepseek讨论了一下做官网的事，然后引出了一个有趣的话题：新时代(AI/neo)的官网该怎么做？
   > (.memo/design/hctl2-site/20261007/03-neo-build.md)
   > 你有什么想法？我们讨论一下。

   结论：Claude 席同意 03 初版的大方向（LLM 只逐单元写文字，产物冻结入库，构建保持机械），提两处改动：
   - 模型是作者，不是编译器；这套东西更像本地化流水线（gettext、lingo.dev、`cargo insta` 为先例）。来源变了是「过期待审」，过期判定走机械 → sysone → 人，文字在人接受时冻结。
   - 读者里有 agent，站点要有给 agent 的一面（`llms.txt` 与每页 `.md`）。

   另提三点：LLM 只参与创作、不参与构建，展现也可以在设计期生成候选；模型在哪跑不是边界，产出不经人接受不上站才是；过期清单可以当 hctl2 自己的 Task 队列练手。

2. 所有者：

   > 有道理。而且我尤其喜欢你关于agent读者的那段 - 它让『展示层』独立的意义更明确了。我们说的风格、衬线字体这些，本质上都是把内容给人看；而把内容给agent看，本来就不需要这些东西。那么这就更加支持我们把内容(不是页面，而是意群、逻辑组织关系)与展示分开。agent可以直接读.md。

   结论：给 agent 的那一面不用渲染，它就是内容层本身。三个推论：页面归展现层，取舍与顺序也算展现；一份文字两边通用，靠不写营销腔；内容层用裸读可通的 markdown，借 DITA 的 topic 与 map 拆法，不借它的工具链。

3. 所有者：

   > 比喻从「编译器」改成「译者加审校」，我认

   结论：模型 id 移出缓存键，只作出处；只有来源章节或 prompt 变化才失效，失效后是过期待审；lock 记每个意群的审定记录与四个状态（待译、待审、已定、过期）。更正上一轮一处说法：gettext 默认不把 `fuzzy` 条目编进产物，Crowdin 把「原文变化后译文与审定怎么处理」做成项目选项。过期文字上不上线是各项目自己的取舍，提请所有者拍板。

4. 所有者：

   > 继续上线，colophon 标过期
   > 直接改03. 因为我们是git，有history

   结论：过期意群继续上线，colophon 标过期；03 原地改写，初版留在 git 历史 `3ec6698`。

5. 所有者：「落 已定」
