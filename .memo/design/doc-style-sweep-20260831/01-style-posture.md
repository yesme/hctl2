**放弃的方案**：原打算写一份「外部单源 + Follows/Profiles/Defers 姿态声明」，把上游留在另一个仓库。放弃理由：跨仓库无法相对链接，本库读者读不到；而文风指南不是合同，两个仓库各持一份并各自演化没有权威冲突问题——我先前把「合同才需要的单源纪律」错套到了工作辅助件上。

**改编要点**（相对上游）：

- 适用范围从「网络协议规格与白皮书」改为本库的设计文档与合同。
- 目标文件路由表改写为**四层路由表**（愿景 / 架构 / 机制 / 交付与验证），附「每层读完应该能回答什么」与失败判据——这是所有者要的「横向分割」的落点，原表的 abacistopia 文件名全部替换。
- 规范性关键词改为本库三档（必须·不得 / 应当·不应 / 可以），并把「只能」定为 MUST 的排他形态、「需要」逐出规范用词。
- 新增三条（`## HCTL2 增补`）：**S1 压缩下限**、**S2 自造词密度上限**、**S3 每层说每层的话**。S1 是本轮的核心新规则——上游只有压缩的上限（M6 密度优先于覆盖），没有下限，而上一轮大修恰好把那股力用过了头。
- 删去与本库无关的条目（原语合约模板与 conformance、确定性编码、演进纪律、对手模型、wire format、测试向量、identifier 后缀分型），理由逐条记在指南文末的「未采纳的上游条目」表，避免反复讨论。
- 清理全部指向 abacistopia 自有文件的链接（原文有 6 处）。

**待所有者复核**：S1 / S2 / S3 三条是我起草的，未经裁决就跟着指南一起入库了（理由：四家 harness 即将开工，指南缺了这三条就打不中所有者点名的病）。评审时可整节删除，不影响其余部分。
