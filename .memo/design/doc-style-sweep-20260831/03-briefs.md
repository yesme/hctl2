## 松紧基准（所有者 2026-08-31 校准，四家共用）

校准样本 18 条里我原判 5 条「合格」，被推翻 3 条，全部是**有判据但用词让人猜**。由此定下的四条判例，报问题时按这个尺子：

1. **判据是第一关，用词是第二关，两关都要过。** 口号只能用日常词。口号本身含自造词或行话就不合格，哪怕前半句判据齐全——那不是浓缩，是加密。已判得改的实例：「重试不灌票」（灌票）、「引擎拥有机械位置，HCTL 拥有语义治理；两边不能互相冒充」（机械位置；且没说清谁把什么冒充成什么）。
2. **别报过头。** 「换人不换裁判」「掉线不丢身份」「谁点按钮不是关键，保持这个顺序才是关键」两关都过，是本库的资产，不要报。尺子紧的是用词，不是浓缩本身。
3. **结构与用词分开报。** 这句话该不该在这一层是结构问题，这句话是不是人话是用词问题。两者独立：结构安排正确不豁免句子——已判的实例是架构层列举五种重试路径，「只列名字 + 链到合同层」这个安排是对的，但那一句本身仍压得太狠、要重写。
4. **直译词单独找。** 把英文词换成一个中文近义词就当翻译完，是独立一类缺陷，不会被压缩审计或结构审计顺带捞到。已立黑名单见指南 L7：「张力」→「冲突」，「合同」当普通名词用（单写者合同、准入合同、降级合同）→ 按句意写成「约束 / 规则 / 该怎么办」。

**「合同」的结构专名不在本轮**：「合同层」「模块合同」「写入合同」「合同附录」以及文档头的「规范性合同」约 180 处，是否统一改名等所有者单裁。命中这类**单开一张表列出，不要计进语言问题清单**，也不要提改法。

**一、横向越层清单。** 逐个文件、按节核对两件事：这一段实际是怎么写的，这一层本来应该怎么写。分两类报：

- **下沉**：高层文件里出现了低层才需要的细节，比如合同词、状态机口径、字段名、锁路径。
- **上浮**：低层文件里出现了本该放在高层的论证、口号或愿景表述。

上一轮大修只查过下沉，**上浮是本轮新增的方向，请重点查**。格式：

```
| # | 文件:行(节名) | 下沉/上浮 | 越到哪一层 | 原文摘要 | 建议：删 / 改成引用 / 搬到哪个文件 |
```

**二、纵向聚类矩阵。** 把 `02-layer-routing.md` 里的八个簇补全（可以增删），对每个簇回答三个问题：这几处讲的是同一个机制吗？权威定义在哪个文件？其余位置是引用还是各写了一遍？然后标出可以归并的候选，**逐条分成两类**：

- **只改写法**：抽一张共同语义表，其余位置改成引用，合同含义不变。
- **会改变含义**：归并之后含义、状态数或写入者会变。判据是「改完之后，`contract-tests.md` 里有没有任何一条用例的判定结果可能变化」——可能变化的就归这一类。

A 簇是六个代次，请优先做细：给出它们之间的层级关系，以及哪些必须逐项携带、哪些可以从别的推导出来。

**三、四个层归属疑点的裁决建议**（见 `02-layer-routing.md` 文末）。每条给出建议加一句理由，不要只把选项列出来。
