## 本轮回答什么

上一轮全库大修（`../doc-overhaul-20260830/`，已收口 v0.15.1）解决的是**内容权威**问题：谁定义什么、去重、断链、禁令。本轮解决剩下的两件事，都是所有者点名的：

1. **讲人话。** 部分中文压过了头，结论留下、判据被删——所有者举的例子是「量级差三个数量级才值得动」被压成「量差三则动」。同时要清掉翻译腔和自造词堆砌。
2. **分层清晰。** 纵向按话题聚类，让同类机制能被认出来、能归并，安全机制尤其；横向按颗粒度分级（愿景、架构、机制、实现），每层目的不同，写法也不同。这么做的目的是替读者省力：读者不必深入细节时，就不该被细节占住注意力。

## 方法：不自己另写一份，把既有指南改编进库

文风规则不自己另写一份。所有者裁定直接把 `yesme/abacistopia` 的 `SPEC-WRITING-GUIDE.md` 复制进本库并按需改写，成果是根目录的 [`WRITING-GUIDE.md`](../../../WRITING-GUIDE.md)——**分工和评审都以它为准**。改编要点、放弃的旧方案和库内已知缺口见 [`01-style-posture.md`](./01-style-posture.md)。横向分层落成了四层路由表，已经进指南 §0.4；它的审计口径和纵向聚类的起点清单见 [`02-layer-routing.md`](./02-layer-routing.md)。

## 流程

1. 四家按本目录的任务书并行产出问题清单，只报不改。
2. Fable 汇总复核，把归并候选分成「只改写法」和「会改变含义」两类，整理成一份给所有者裁决的材料。
3. 所有者一次裁决：指南定稿、结构条目逐条、语言松紧的基准。
4. 落地分两个 PR，**先结构后语言**，避免改完文字又搬家返工。只改写法的那批每波推进一个补丁号，并在小修订台账加一行；**会改变含义的归并不在本轮落**，单独走设计变更路径：决策史记转折，配契约测试的失败用例。
