## 演示 3 的步骤骨架（第 9 包验收 1–7）

- **A. Gitea 链**（验收 1）：注册仓库（缺省绑本地平台）→ 建 Project 与带契约的 Task → Room 发写入型调用（预览含 ChangeSet、租约、冻结的发布策略）→ Claude Code 在隔离工作树改真实代码 → 封存、准入、自动发成评审请求 → 人预览合入（只能选接受目标前移）→ Integration Receipt → 人预览完成 → Task Completion Receipt。
- **B. GitHub 链**（验收 2）：同 A，`yesme/hctl2-canary` 受保护 `main`，harness 换 Codex。
- **C. 开关链**（验收 3）：开了「须人显式确认」的 Project，多一次发布预览，三次预览单独验收。
- **D. 重启三处**（验收 4）：发布第一段后、集成已提交未回读、完成已预览未提交，各杀一次 control、Agency、随包服务再起。
- **E. 凭据与加固**（验收 5）：harness 环境读控制面凭据根、钥匙串、`gh auth` 都失败。
- **F. 逃生口与安静**（验收 6）：三条逃生口各走一遍；正常成功时保持安静；`status` / `task show` 十秒回答。

投影与事实的固定核对点：`review show` / `integration show` / `task show` 的字段，平台上的分支头、评审请求数、合并提交，两种 Receipt 各一张。
