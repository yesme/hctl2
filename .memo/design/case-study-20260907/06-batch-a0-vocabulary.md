## 二、改法：五种改写情境，先问这句话在说什么

v1 把五类写成"五种不同的东西，一类一个替换词"，Codex 指出它们不互斥：甲乙丙是标的物，丁是句法，戊是对比关系。v2 改成五种改写情境，判别有顺序：

1. 这句话在说**谁负责准入、授权、判定、冻结、拥有、隔离、执行限制**，主语写**控制面**。例："账本接受这个版本，这是准入"改"控制面接受这个版本"；"账本给门"改"控制面管权限与判定"；"账本先固定 Task 身份并提交后端 outbox"改"控制面先固定"；"完成与评审都在账本里判"改"都由控制面判"；"身份由用户在账本里建"改"由用户经控制面建立"；"账本标 unknown"改"控制面将其可核验性记为 unknown"。判据（GLM 的总判据，Codex 补充）：不能按"保存、记、标"三个动词直接判给存储，"控制面根据核验结果记为 unknown"仍是判定，要看整句在说责任还是在说内容。
2. 这句话在说**什么事实被记录、什么事实参与判据、什么记录有权威**，写**治理记录**。例："只由账本谓词决定"改"只由治理记录的谓词决定"；"进度与账本不一致"改"与治理记录不一致"；"纪要不进权威账本"改"纪要不作为权威治理记录"（Codex：原句断言的是非权威，不是不许存放，"不进控制面存储"替规范说了它没说的话）；"批准施工图与开工是账本里的两件事实"改"是两条治理记录"；"账本自己的 Obligation 截止时间"改"控制面记录的 Obligation 截止时间"。
3. 这句话在说**实际存放、备份、打开、写入的对象**，写**控制面存储**；用户级的写"用户级控制面存储"。例："metadata 账本与写锁"改"控制面存储与写锁"；"账本备份用 SQLite Online Backup"改"控制面存储备份用"；"账本只保存引用与 digest"维持写存储，因为它在描述内容。量词"本"一律去掉或改"份"："存储只有一本库"改"只有一份：用户级控制面存储"（不趁机改单写者与用户级范围）。
4. 这句话在说**事务边界**，写**控制面事务**，不写"控制面存储事务"（Grok、Codex）：连接约束 12、77、118、158，Run 约束 82，Task 约束 95 全部统一；`connections.md:12` 的"同一本用户级 metadata 账本的一个事务"改"同一个用户级控制面事务"。
5. 这句话在**与 Git 或平台对举**：说权威在哪一边写"权威仍归控制面"或"权威在控制面存储"，说字节在哪一边写"Git 正文"，说平台那半写"平台记录"，"第二本账"改"第二个权威"。例："权威在账本，Git 里只有审计影子"改"权威在控制面存储，Git 里只有审计影子"；"control 账本独占身份、准入、摘要和 current pointer"改"身份、准入、摘要和 current pointer 的权威仍归控制面"（Codex：区分权威归属与字节在哪）；"Verdict/Receipt 的权威在用户级 metadata 账本产生并保存"改"由控制面产生并保存在用户级控制面存储"。

三条施工规则：同一行里几处"账本"按整行改一次，不按片段叠加，v1 附录的"威控制面存储"就是片段叠加出的残留（GLM、Codex）；清除替换后中文词组之间多余的空格，`participant.md:92`、`spec/participant.md:83、85`、`spec/run.md:64`、`spec/system.md:144、146、181` 七处要清（Codex 逐处核过），中文与英文、数字及行内代码之间仍按 `WRITING-GUIDE.md` §L4 保留半角空格；"账本"改成"控制面存储"后，与它对举的另一半不动。

一处有意的选择：`architecture.md:84`"保存是工具箱的事，算数是账本的事"改"算数是控制面的事"，算数本来就是控制面的判断（GLM 判含义保持并接受）。
