## 一、结论一句话

**不保留控制面拥有的 Repo Instance 这个独立对象，也不保留必经的"挂接"命令；保留精确的现场引用，以及本控制面围绕它作出的授权与确认。** 机器一侧管理实物；控制面不拥有克隆，仍对自己引用、授权和确认过的目标负责。这是 Codex 对 v1 的修正，我接受。

## 二、v1 哪里说过头了

v1 的立场是"取消对象，现场归 Agency，只是它的实现细节"。Codex 逐项裁决，我认下面四处：

- **"三件职责都以控制面是克隆的主人为前提"，推翻。** 认准目标、限定自己授出的写权、恢复未确认的动作，都不要求独占那份克隆。两个控制面可以各自持有指向同一份外部资源的引用；共享推翻的是独占归属，不是关系本身。
- **"主人只能是 Agency"，修正。** Agency 负责提供和管理获准使用的资源，但不因为服务了两个控制面就取得人已有克隆的所有权；一台机器与一个 Agency 也不是永久一一对应。管理责任与文件所有权分开。
- **"没有克隆就用自己的凭据克隆"，修正。** 我把第 15 条引反了：它明确说有凭据直接取得、没有则走既定中转，不加"每台机器必须登录平台"的前置。应写"Agency 按已授权、可达的路径准备材料"。
- **"现场只是 Agency 的实现细节"，修正。** 路径、目录布局、锁的实现可以私有；但指向哪份资源、允许改哪里、资源被替换后旧授权是否仍有效，是控制面与 Agency 双方的约束，不是一方的细节。平台目标之外，本地目标必须能被授权者准确指认。

另有两处我写少了，Codex 补上：控制面这边的 Repo 不是"只剩平台绑定与各 Project 的归属"，第五模块还负责本控制面的仓库引用、ChangeSet 的获准版本与写权、集成与发布的意图和凭证，不因删除物理现场对象而消失；"每次执行一张令牌"只是候选，认证一份报告证明不了旧进程已失去文件写权，活着的执行清单也覆盖不了集成已发生但确认丢失的情形。

## 三、保留什么，不保留什么

**不保留**：现行 Repo Instance 这个控制面独立对象，它的"活跃、已移除"生命周期，以及必经的"挂接、移除 Repo Instance"命令。不另造一个改名后的同类实体。

**保留**：现场引用，作为意图与记录里指认外部资源的信息，不是新对象。它必须能回答一个别的对象答不了的问题：**这条授权或这个结果，针对的是哪一份实际的 Git 资源；重启后我回读的还是不是它。** 逻辑 Repo 回答哪一个仓库，Agency 回答谁提供资源，执行编号回答哪次执行，ChangeSet Revision 回答哪份获准内容，这些都不自动回答那一问。

Codex 的反例说明为什么不能只靠目录名、同一 HEAD 或同一根提交：同一 Agency 里 A、B 是同一逻辑仓库的两份克隆，main 当前头相同；控制面授权合入 A，恢复时选到 B，源树校验和预期头比较都能通过，仍然写错了目标。所以意图沿用现有字段承载三样信息：目标属于哪个可解析范围、那个范围内哪份确切的 Git 资源、哪个 ref；从命令受理到回读恢复期间不能悄悄换成另一份资源；Agency 移机或路径重建后要核对仍是原目标。

## 四、三处核的结果

1. **没有平台的受限路径：维持，不随对象删除而删除。** 目标改写为"某个 Agency 可解析的精确现场上的 ref"成立，前提是现场引用带上面三样信息；同一对象库可以共享，但实际写入的工作树与 ref 要守获准范围与互斥条件，不同控制面的执行令牌不能代替共享工作树的写入互斥。两条原边界不动：不挂平台才有本地目标；平台不可用不改道为本地目标。
2. **恢复：推翻"用活着的执行清单替代原恢复规则"，改为分责后的完整对账。** 可以移走"控制面直接取得机器现场锁"这一步，不能移走它保证的条件。原恢复流程还要恢复持久意图、已收事件与待投递动作、租约，核对 Git 与平台，处理结果未知，再决定是否授予新写权。五种情形的判据（Codex 的表，C 批照抄进方案）：控制面重启而 Agency 与旧执行正常，先恢复本控制面自己的唯一写权，只让自己的过期动作失权，不重置 Agency 的全体执行；Agency 重启或暂时不可达，"没报告活着"不证明执行已停止，身份不能证明时才按规则判丢失，不能证明旧写者失权时不把同一可写资源交给新写者；执行已结束、结果待交、控制面由旧备份恢复，完成报告仍要能按原授权核验，结果与代码保留到接收方确认保全；集成已写入但响应丢失、或人的显式封存尚未准入，按持久意图回读精确目标，封存字节不是自动准入；Agency 换机器或同路径重建克隆，对照原意图的目标与交付项，换成另一份资源时不沿用原授权。恢复本控制面也不先抢占 Agency 全部克隆的排他权，互斥在执行具体写动作、重新授予具体资源写权时由资源管理方落实。
3. **所有者自己的本机克隆：维持直接编辑加显式采用，不加"先雇一个参与者"的前置。** 人直接改代码；要 HCTL 接受时，由工具回读、用户预览并提交封存或采用命令，控制面按原规则准入；现场引用在这次命令里确认，不要求先走一个挂接向导。依据是现文已允许生产者是 human command、不经 Invocation 或 Attempt，以及单元稿 §四丙 3 保留的控制面本机工具与人显式封存的直报来源。
