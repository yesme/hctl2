## 二、改法与推荐

### B1 Agency 是参与者的代理：一道门，进出都是

**已定边界**见 §五 D15：要人直接找 Agency；此后派工、输入、停止、观测、终端接管、执行结果与工具报告的回传全部经 Agency 转接，客户端不直接连参与者；Agency 有全部通路，没有任何治理权威。

**拟改义：** Agency 是控制面、前端与参与者之间唯一的通路。控制面向 Agency 要人，Agency 交付一次执行并对它负责；之后控制面的激活、输入、停止、票据签发对象都是 Agency 交付的这次执行，由 Agency 转到门后的进程、会话或主机；执行结果、证据与工具报告也经 Agency 转交回控制面，参与者机器不需要持有控制面的地址与凭据。前端观察或接管终端，经 Agency 转接，票据仍由控制面签发、由 Agency 校验。Agency 门后的进程、PTY、会话文件、主机布局是它的内部，控制面不维护完整布局，只保存精确关联、权限核验与所声明恢复能力所需的引用与证据。「全部通路」指参与者相关的全部交互——要人、派工、输入、停止、观测、终端连接、结果与证据回传；控制面之间没有直连，也不需要；前端到控制面、控制面到内容系统的连接不经 Agency。改「派工与观测直接发给执行体端点」那句时，「Agency 永不包含治理权威」留在同一句里：转接不是准入。

系统支持的客户端交互都经 Agency；机器主人在系统约定之外直接操作宿主上的原生界面，是外部事实，按冻结的输入策略记录来源能否逐次证明（现行 `native_interactive_allowed` 的写法），不作为代理模型的正式例外。

出门方向不再列待裁：所有者原话「商业组织只有一个出口」与 05 §二 B 行都覆盖了报告回传；「进门经 Agency、出门直连」与它相反，不作候选。代价写在 B5：报告能否核对来源不能再靠"谁直连"，改靠通道核对。

### B2 failover 阶梯与执行身份：无感是不重新派工，不是不区分新旧

**已定边界**见 §五 D15：failover 只在冻结的执行规格内——同一工种、同一权限、同一施工图版本——Agency 内部重启会话、改派备份、换主机都不改变控制面看到的席位，不要求人重新选人或追加授权；超出规格的一律报回；Agency 挂了由人指定别的 Agency；回来的旧执行体封存前机械核图与席位。

**拟改义：** Execution Runtime 保留为对象，含义改为「Agency 为本次派工交付并负责的一次执行的物理运行身份」；`runtime_generation` 仍标识物理运行身份。Agency 在冻结规格内自愈分两种：同一运行身份可证（进程被挂起后恢复、同进程同 PTY，按 Agency 声明的退出与停止回读能力证明）——不换代，控制面只记观测；接替（重启会话、改派备份、换主机）——Agency 自动交付新的运行身份并报告，控制面记录归属者到新运行身份的映射，不重新派工、不需要人，这就是所有者说的无感。接替涉及写入时，沿 Repo 与 Participant 已有的规则核旧写者停止或隔离的证据，并由 Agency 在报告里给出：证明旧写者已停止的，接替者可在同一 ChangeSet 取新租约；只证明它被限制在旧工作树与旧 ChangeSet 边界内的，原 ChangeSet 不重授、接替者改用新 ChangeSet；两者都证明不了的，不算已隔离，Agency 报无法履约，不冒充已接替。只有旧代次失权、没有资源隔离证据，不算已隔离；自动记录新映射不跳过这些分支。举证责任：Agency 提供进程、PTY 与工作树状态的证据，控制面按 Repo 与 Participant 的既有规则核验后才记为已停止或已隔离，不凭 Agency 的一句自述。席位连续不等于运行身份连续；报告始终能区分实际执行来源。

Agency 无法履约时按所报的技术故障处理：候选切换、Request、失败或取消，都沿冻结规则；控制面不替 Agency 猜。换 Agency 是有权的人显式提交的替代（现行「只有归属者提交显式替代命令后才能创建替代执行」不动），选另一个工种实例，沿 09-11 不存在换绑。

旧执行体回来：发起新的写入、封存或结果准入之前，`hctl2-tool` 在参与者一侧机械核对三样——本次执行规格摘要与施工图版本仍是自己被派的那份、席位或调用仍归自己、运行代次仍是当前——任一不符就在本地拒绝这次新的封存与报告，新字节不出机器（用例段的 check-in 前置钩子）。失权的旧执行不能以当前执行身份发起新的写入、封存或结果准入；它已保管的原结果与证据仍可按原引用交付，供控制面对账与审计，是否还能准入另按原授权、归属者状态与适用代次判——「不能准入」与「不能交付」分开，与 B3 的「已完成而待交的报告按原授权核验」一致。接替已换代，所以被接替的旧执行体带的是旧代次，能被机械区分；控制面准入侧原有的代次、规格、租约核对是第二道。「当前值」怎么取得（经 Agency）留实现层。

作者要选的地方（**推论**）：

- **甲：如上，接替自动换代、自动记录。** 控制面不重新派工、不找人；旧执行体可机械区分，旧写者按 C 批的三分支核隔离。代价是控制面的映射会随接替更新一次，Agency 要能报告接替与隔离证据。
- **乙：接替不换代，同席位同规格同代次。** 与所有者原话字面更近，但 E1 卡住、E2 接替、E1 又回来时，三样核对同时放过两者，两者若持同一写租约，事后拒收结果也隔离不了工作树写入。不推荐。

**推荐甲。**

### B3 端点非独占，按执行排他

**已定边界**见 §五 D3：配对不排他，同一 Agency 同时服务多个控制面；排他落在每一次执行上；Codex 的三个条件——同一进程续做下一次调用不续用上次的权限；进程已结束、结果尚待交付时，已完成的报告仍能核验；一个控制面重启、换绑或从旧备份恢复时，只隔离自己过期的动作权限，保留未确认的意图与结果，不使别人在同一 Agency 上的执行失效。删端点代次是本批要给出的替代证明，不是已裁。

### B14 证据通道互异：启动时核可满足，计票时核实际证据（#216 R2）

**已定边界**：#216 R2（D11）：证据通道是每条实际 Evidence 的属性，选入记录里没有实际证据，启动时判不了；R 批方案 §八 明写归 B；R 批已定的等待、截止、失败路径与去重规则不动。

**拟改义：** `spec/run.md` §Request、重试与 Gate 的席位多样性声明里，「证据通道互异」从启动拒绝改为两个时点：启动时只核声明及当时可证明的可满足性——席位所选 Worker Profile 的接入方式与工具能否产生所要求的通道——不把声明当成已取得的证据；计票时按实际用于判决的 Evidence 核对冻结的互异要求。硬条件不满足时不得签通过凭证，也不得因此按重复配置只算一票；未收齐与已确定不满足分别沿 R 批既有的等待、截止与失败路径处理。Worker Profile 互异、harness 互异、回避作者所用 Worker Profile 三项仍在启动时判，不受本项影响。

多条证据怎么比较（**推论**，待裁）：

- **甲：比较各席位「用于满足必需判据项」的证据通道集合，要求互异时两席集合不得相同；与判据无关的附加证据不计入，所以附一条无关转述制造不出差异。** 代价：可用通道种类限制可满足的席位安排，两席都只能拿到旁路时互异要求满足不了，须在启动时就报可满足性不足。
- **乙：要求两席集合不相交。** 更强，但两席各有一项必需判据只能用直报时永远满足不了不相交；要说明为什么大部分判据来自同一通道就不算互异。Codex 交叉审阅撤回了对乙的推荐。

**推荐甲。** 甲只证明所比较的通道组合不同，不证明来源主体独立或事实互不相关，那些更强的要求仍按既有 Gate 策略与能力处理。

取数口径（甲能机械执行的必要补充，不新增对象）：比较对象是冻结的互异要求所覆盖席位的有效裁决；证据集合从这些裁决明确引用、且符合本次证据要求的 Evidence 提取；按必需判据筛选时，判据与证据的对应按冻结 schema 中可核验的引用确定，不靠计票时猜报告文字是否相关，无对应的附加项不参与比较。尚无有效裁决不当作一个不同的空集合；提前结束仍按 R 批「剩余席位按冻结规则不能否定通过」判断；未取得的证据若可能使冻结的互异条件不成立，不能把未知当满足；本来可撤且不影响条件的席位照旧可撤，不新增一律收齐的规则。

例：Gate 策略要求判据「测试通过」的证据来自高证据类，并要求两席通道互异。席位 A 的裁决引用一条直报的测试退出码；席位 B 的裁决引用一条旁路的测试事件，另附一条直报的 Git 基线——Git 基线不对应任何必需判据，不计。集合 {直报} 与 {旁路} 不同，互异成立；若 B 也引用直报的测试退出码，两个集合都是 {直报}，互异不成立。判据与证据的对应来自 Verdict 里对 Evidence 的引用与策略声明，现行 Task 验收项的校验等级与 Gate 策略的证据等级要求就是那份冻结 schema，不另建。

CT 至少五条：`{直报}` 对 `{直报, 旁路}` 按甲通过；两份 `{直报, 旁路}` 不通过；第二个通道没有合法的判据对应时不得制造通过；缺来源标记不能补足；尚未取得有效裁决不算一份不同的空集合。

## 三、代价与批次切法

推荐一个 B 动手 PR，v0.18.2（**推论，待裁**）。B1、B3、B4、B10、B13 是同一件事（门在哪、谁认证、谁排他、派工怎么走）的五个落点，拆开会留下"派工步骤经 Agency、恢复表却按端点代次"的中间版本；B5、B9、B14 是证据这一条线的三面。文件数少于 C，一个 PR 能读完。提交怎么组织由作者定；W.1 的 PR 描述按 §六 落点表逐行对照，W.2 按表查漏（沿 C 批拍板 10 的做法）。

用户的持续成本：远程控制面要与 Agency 配对认证一次；未加固时不保证与同用户进程强隔离，具体凭据可见性按持有位置和授予方式说明，不放宽 B9 的凭据底线，要求防伪能力的项在能力未验证的部署里不通过；本地参考实现多承担接入与保管职责，形态的代价在交付层论证。换来的是一台机器只开一道门，参与者卡住不惊动控制面，Agency 挂了才找人。

## 四、借用现成机制与分层

本批不选新依赖。代理这一层沿 [Herdr 运行服务验证记录](../../../docs/research/runtime/agency-runtime-validation-20260829.md)的 API 与 TUI 边界：Herdr 继续持有进程、PTY 与会话，接入层只做门口的配对核对、票据校验与转发，不重写终端服务；转发 PTY 与观察流的做法与 SSH 跳板机同形，是实现选择。harness 的会话恢复入口沿 [harness 适配器调研](../../../docs/research/harness-adapters.md)，是 Agency 门后自愈的现成机制，不进约束。来源标记优先复用现有配对认证与执行引用，不新造证据签名协议；不够时再研究，先落研究文件。

分层：架构层只加总则一段与 Agency 条的改口；约束层写门、排他、三分、三档、R2 两个时点、两条不变量与"做不到的"；设计正文写为什么是代理、待命段；交付文档写本地参考实现的职责与形态候选、部署前置；四态转换表、令牌格式、转发方式是实现层，不进约束。
