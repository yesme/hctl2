本文说的 sysone（system one）指 Jev、CLM 一类判断器：输入一份小状态和几道有限选项的题，输出各选项的概率，不生成文字。它就是规范里 small-brain 的「判断」那一半。

## 一、起点

所有者让主笔调研 mu（Pi 的分叉，以 Jev 为主后端的判断内核，35 个决策点），并问：Room 阶段能不能也靠提问题来决定要不要开新 Topic Room、要不要形成 Task、要不要对已有 Task 做收敛？这正好是已留的 TODO：体验 T1 的「持续建议」、[任务书 06](./p2-control-20260906/06-small-brain-engine-research.md) 的 A、B、C 三件活，以及 #290（Grok，未合入，卡在样本不够）。

调研收进 #299：原始材料、对象文件，DeepSeek 与 Qwen 两份审查。所有者要求先记录、不急着定「要不要按 mu 走」，随后在聊天里逐条讨论，得出 §二。

## 二、所有者定的

0. **机械判断优先，然后 sysone，然后人。** 能机械判断的就不给 sysone：sysone 本质上也是概率判断，而且慢；人最贵。推论：
   - 每个判断点的规格先写机械部分。规则定得了的由规则定，sysone 只接规则定不了的灰区。
   - 人排在最后，所以人只看到前两层都定不了、又确实要人的事，这本身就是防「伪决策洪流」的机制。sysone 拿不准时，建议类判断点退回机械缺省（不弹），不自动升级给人。
   - sysone 的结论可以往下沉：判定记录里稳定重复的判断，改写成规则，从 sysone 降回机械层。mu 的先例：测试日志的真实收益（7 份长日志净省 51%）来自一条确定性规则，判断器在真实日志上没产出候选。
   - 关键决定不走这条阶梯。Task 完成、合入、授权归人，是因为权限在人；机械层和 sysone 只准备材料。
1. **判断点从两处来。**
   - **流程判断**：按 mu 的方法论，遍历用户流程，找出本来由人（智能）做决定的地方。数量少，出口直达人（建议卡）。初稿见 §三。
   - **警觉题**：人一边看讨论或 agent 输出、一边在想的问题：是不是又重复造轮子了？同一类代码是不是散落在各处？同构的几个问题，这里考虑到了，那里有没有漏？这些最耗人的注意力。数量多，随原则增长。初稿见 §四。
   - 两类排除：① 项目内部的领域决定，HCTL 不判（那是项目自己的 domain knowledge），但提供机制让项目把自己的原则登记成题；② 最关键的决定（如 Task 是否结束）必须人做，AI 给建议。
2. **原则就是题源。** 题挂在原则上，原则改了题升版本。HCTL 自带通用的工程卫生题；项目登记自己的原则，hctl2 是第一个这样用的项目。能用 lint 判的（禁用词、版本戳、链接）留在 lint。
3. **先召回，再判断。** 召回是机械层的事：代码搜索、符号索引、`docs/research` 索引、相关性门，把「可能是同一件事」的候选找齐；sysone 只在候选里答「同一件事 / 重叠 / 不同 / 说不清」。没进候选的，判断器永远选不回来。每道题的规格写清召回从哪来。
4. **题多不等于打扰多。** 两者之间是注意力预算。警觉题的结果大多不直接给人：回给 agent、给评审当材料、汇总，严重的才升级。到人面前的每一条都要讲人话，答得出「为什么现在告诉你」「你点一下会发生什么」。
5. **标注：先假设判断器对，有了正反例再逐步纠偏。**
   - 每次判断都记录，包括没弹出来的；最值钱的反例是「判断器说不用、人却手动做了」。
   - 标签挂在人的动作上（开没开 Topic、采没采纳候选卡、改没改提要），不挂在某道题的答案上，换题、换判断器后标签照用。忽略只算弱信号，明确驳回才是负例。
   - 判定记录存引用、不存正文：读了哪些事件 ID、哪版 Task 或治理记录。这样新题或新判断器能在历史上重放对比，也不复制正文；与「引用按事件 ID 冻结」同一规矩。mu 缺省只存状态摘要，换题后旧记录不能重放。
   - 三样分别迭代、各自升版本：题面（问得不好就换）、判断器（CLM、Laya 一类可训练）、策略阈值。
   - 只出建议的判断点可以直接生效，不必像 mu 那样全量 shadow 起步；会改状态的事永远不归判断器。
6. **判断器：先把机制做上，模型可以换。** Pi v0.99.0 的分类接口（与提供方无关的 choice / score / bool）就是这个形状。hctl2 自用的 Project 在策略上放行 Jev（所有者选 (b)，账号待申请）；其他 Project 按缺省，正文不出本机，这是策略面的事。账号到位前机制照跑：判断器缺位走 fallback（现行机械规则），记录照记。
7. **收敛是接口细节，主笔设计。** 新讨论碰到已有 Task 时，可能是重复、细化、冲突或可能完成。sysone 用一道选择题识别是哪一种，然后分四条路走（指向已有 Task、提出新的 Task Revision 等人采纳、标出冲突等有权的人选、准备完成检查材料等人确认），每条路的终点都是人。
8. **警觉题的结果只作观测。** 不是 Verdict，先不允许升级成 Gate 席位（所有者「同意，先不允许升级成 Gate 席位」）。

## 六、候选落点

- 愿景原则 6「机械动作必须由确定性规则执行」扩到判断，或新增一条原则；所有者落地时定。
- 规范：判断点的规格形状（机械部分、召回来源、题面版本、fallback、出口）与判定记录（存引用、可重放）。落在 Project 还是 Context 规范，主笔出方案。
- 契约测试：判断器缺位时行为等于机械缺省；会改状态的动作不接受判断器结果；警觉题不产生 Verdict；建议类出口受注意力预算约束。
