## 1 调研优先

可引的机制不是"我们调研了很多"，而是**调研的纪律**：每条研究钉定 commit、版本与许可证，发布后正文不改、只在文末追加复核记录；六种复用决策（采用二进制／采用 SDK／适配协议／移植有边界的组件／仅参考行为／暂缓）里明确**不得给整个产品一个"取代 HCTL"的总分**（`docs/research/README.md`:194-198）。33 家复核的头条数字见 [`governance-attrition-20260908.md`](../../../docs/research/governance-attrition-20260908.md) :5-13、:19、:31、:57：工作台 15 家与方法论 19 家，去重 33 家；有明确起止时间的自造治理功能二十多例没有一例活过半年；流程中段的三类判断门，19 家里没有一处由代码判定且输入不由施工模型写。

## 2 对话 ≠ 更优方案

可引的实证（全部在同一份调研里有出处与版本）：

- 等调用数下 MAD（多智能体辩论）对 CoT 的胜率没有一个配置超过 20%；同 token 下低于自一致性；唯一稳定有效的改动是**异构**（`multi-agent-effectiveness-20260908.md`:100）。
- Choi 等「Debate or Vote」：把辩论拆成"多数投票 + 看别人答案后更新"，去中心化辩论在理论上是鞅（平均不进不退），多数投票拿走通常归功于辩论的绝大部分增益（:151）。
- ChatEval 表 3：把多 agent 的角色提示改成同一份，准确率与单 agent 一样——**同一模型换名字不换视角等于没多一个人**（:159）。这条与 hctl2 "同一模型换个名字不能给自己投票"是同一个形状。
- 无外部反馈的内在自纠只会变差；自一致性才是等预算比较的默认基线（:145、:147）。

必须降级的三处（`multi-agent-effectiveness-20260908.md`:293、:297-301、:304）：没有"多模型评审同一份 diff 对比单模型"的同基准等 token 实证；没有评审法定票数的实验；"两轮上限"是从 Magentic-One 与 Huang 借的，不是评审场景实测。另：引用 Pappu 的 41.1% 要用修正口径——那是相对逐题理想上界，不是比最佳固定个体低 41.1%（[`collective-intelligence-research-20260918.md`](../../../docs/research/collective-intelligence-research-20260918.md) :210、:1068）。

站点上的写法：**idea 是合作的起点，讨论不是方案更优的证明；真正的增益来自异构与独立判断，不是多开几轮对话**。

## 3 机械 → sysone → 人

定义以 [`room-judgment-20261002.md`](../room-judgment-20261002.md) 为准，不另立一说：**机械判断优先，然后 sysone，然后人**；sysone 指 Jev、CLM 一类判断器（输入小状态与有限选项，输出概率，不生成文字），即规范里 small-brain 的「判断」那一半。关键决定不走这条阶梯——Task 完成、合入、授权归人，机械层与 sysone 只准备材料。

站点上落成一句话就够：**能用规则判的不问模型，模型只答有限选项的题，人只看到前两层都定不了的事**。配套的边界例句可以直接引 small-brain 调研的原话：「不让 Jev 写短句，它写不了」（`small-brain-engines-20260928.md`:19）；缺省是机械行为，模型没配就不开（同文 :17-19）。

与 spec 的关系要在站上说清，避免术语混用：`mechanical`／`gate`／`human` 是**校验等级**（谁来判），sysone 是**判断器类别**（用什么判）；两者只在流程图上并排出现，正文不混用。

## 4 注意力是稀缺资源

**仓库里没有外部出处**，`信息过载`、`带宽`、`稀缺` 在全库零命中；能引的都是 hctl2 自己的设计与度量：

- `vision.md`:96 的注意力分配原则：多个 Harness 默认在后台执行，前台只保留需要人商议、授权或接管的事项，正常成功保持安静；观察手段是一道阶梯（结构化执行流 → PTY 转录 → 终端接管）。
- 「待你处理」只投影确需人处理的记录，普通进度与可忽略建议不进数字（`docs/design/spec/project.md`:47、:76；`docs/user-experience/04-project-navigation.md`:53、:114）。
- `collective-intelligence-research-20260918.md`:870-876、:929：人的介入要分型而不只是计数；注意力减少必须与风险可见性成对约束，"更可靠且更省注意力"是联合主张，不能只减打断。

管理学与一战参谋部那层（所有者原话）目前是**本项目立场**，站点要么如实标成本项目立场，要么先落一份调研（候选：注意力经济学的经典文献、参谋部与总参谋部制度的史料），再上站。**不得**把立场写成研究结论。

## Participant 与 bot（对外用词）

裁决：**对象名与导航统一 Participant；bot 只做首现的一句桥接与对照物**。三条理由都在 [`participant.md`](../../../docs/design/participant.md)：① Participant 是七层身份（工种、参与者、人设、模型、Skill、执行配置、一次派工），文件明确警告不能压成一份大配置，而 bot 恰好把七层压成一层；② 两个卖点 bot 表达不出来——换进程不等于换人、同一模型换个名字不能给自己投票（`docs/design/run.md`:55 两个席位执行配置与材料相同只算一票）；③ **人不是 Participant**（人不干活、人拍板），所以 bot 也不能与"人"对举。

建议的写法：首现一句「Participant（参与者）：你项目里的数字同事——业界常叫 bot／agent，但它有身份、席位和履历，不是一次性调用」；标语可用对照句**「不是又一个 bot，是一张有纪律的名册」**。双轨词会与仓库术语表冲突，也会让页面回指的链条断开。
