## 一、起因

所有者 2026-10-05：

> 我们还是要stick to community version，这样才能让我们这个one-man-project最大程度借用到community的力量（帮我看下，我们还有哪个地方是自己做方案而没有用社区方案的，我需要一个完整评估 - 放一个专门的高优task，codex, deepseek, grok做）。

引出这句话的是第 3c 包（#335）。为了让「程序跑完没有」伪造不了，接手的一版把 harness 改成由 Agency 自己起进程、自己收输出，Herdr 只剩显示——在已经采用的社区组件旁边，把它已有的事重做了一遍。两席评审都没有拦，主笔还建议接受。所有者叫停，并要求全库查一遍：别处还有没有同样的事。

库里有一份 2026-09-02 的[部件矩阵](../../docs/research/component-matrix-20260902.md)，问的是同一个问题，结论是「建议换的两处都在构建与发行侧」。但它写在大部分代码之前，对着的是设计与选型，不是现在的 `src/`。这一次对着代码查。

## 二、查什么

查的是：**一件通用的事，社区已经有人做好了，我们却自己写了一份。** 分五类，报告里每条标一类：

| 类 | 是什么 | 例子（只为说明，不是结论） |
| --- | --- | --- |
| 1 | 在已经采用的社区组件旁边，重做了它已有的能力 | 用了 Herdr，又自己管进程、自己收输出 |
| 2 | 自己实现了一个通用部件，社区有成熟的库或二进制 | 进程监督、重试退避、规范化 JSON、分页、迁移 |
| 3 | 自己定了协议或格式，社区有标准或事实标准 | 自定的端口协议、清单格式、配置格式 |
| 4 | 用自建脚本或工具绕过了构建系统、平台的原生机制 | shell 脚本做 Buck2 能做的事，自己写 CI 逻辑 |
| 5 | 当初论证过要自建，但理由现在可能不成立了 | 上游后来加了这个能力；当时锁的版本太旧 |

**不算自建的**：这个项目本来要做的事——Project、Task、Run、Room 这些治理对象和它们的规则。但它们底下用到的通用部件（存储、幂等、签名、序列化、调度）算。

**借用的四级尺子**沿用部件矩阵里所有者立的那一把：跨平台二进制 > 拿 SDK 自己开发 > 直接复制代码 > 借鉴想法；四级之外才是自研。每条都要回答：它现在在哪一级，能不能往上挪一级。

## 四、每条怎么写

一条发现写成一小节，字段固定，方便三份合并：

- **位置**：文件或模块，规模（大约多少行、几个文件）。
- **自建了什么**：一句话。属于 §二 的哪一类。
- **它解决什么问题**：一句话。
- **社区方案**：名称、链接、版本、许可、最近是否还在维护；我们是否已经在用它或它的同门。
- **当初为什么自建**：引 PR、调研文件或决策史；找不到就写「没有找到记录」。
- **换过去要动什么**：涉及的文件、接口、数据迁移、测试；有什么风险。
- **建议**：换 ／ 留（写理由）／ 去上游提需求 ／ 等上游。现在在尺子的哪一级，换完到哪一级。
- **把握**：实测（跑过）／ 查证（读了上游源码或文档，附链接）／ 印象（凭记忆，没有核）。

规矩四条：

1. **只出报告，不改代码**，不改设计文档，不动锁文件。
2. **社区方案必须亲自打开核对**：链接、版本、许可、它到底有没有那个能力。没核过的标「印象」，不许写成查证。
3. **先看已有的调研**：`docs/research/` 里对应的文件和部件矩阵。已经论证过的不重新论证，只核「当时的理由现在还成立吗」（第 5 类）。
4. **该自建的也要列**：范围内确认应该自己写的，列一个短清单，每条一句理由。只报问题不报结论的清单没法用。

报告末尾两样：按「换过去的好处与代价」排出前五条；一段话说这一块整体借用到了什么程度。

### 结论

**通用的基础设施基本都是借的，自己写的集中在产品规则和胶水上。** 三块各自的清点：

- 构建与运维：Buck2、Reindeer、官方 btd、bazel-remote、Process Compose、syft、actionlint、shellcheck，都用官方制品，版本与摘要进锁文件。
- 控制面与命令行：规范化 JSON、文件锁、SQLite 备份与迁移、全文检索、RPC、命令行解析、Matrix、Git、GitHub、Gitea、文件监听，都落在二进制或 SDK 上。
- 执行面：RPC、数据库、密码算法、Git 操作、Landlock 都有社区基础；没有自己实现 Git、RPC 栈、摘要算法或文件锁。

**真正偏离「用社区方案」的只有一处，而且还没有合入**：#335 把 harness 改成由 Agency 自己管进程（Codex 的 C1）。所有者已经纠正（开工书 §二 第 18、19 条），第 3c 包按新验收返工。

**其余是三类小口子**：已经引入了某个库或二进制，却没有用深（C2、C3、C5、C6、C7）；一处通用部件自己写了，社区有现成的库（G1）；社区组件缺一样东西，我们在它旁边补了一段，可以去上游提需求（D2、D8、D9）。没有发现第二个「在已采用组件旁边重做一套」的大件。

### 规模：G1 与 C4

第 3 项问的「是 process_control 吧」：不是同一件。两样名字很像——**`process_control` 是一个 Rust 库**，用在 G1（控制面调外部命令时的时限）；**Process Compose 是一个独立的进程监督程序**，随包已经带着，托管服务在用，C4 问的是要不要把 Agency 的启停也交给它。2026-10-05 实测的规模：

| | G1：子进程时限换 `process_control` | C4：Agency 启停交给 Process Compose |
| --- | --- | --- |
| 我们现在的代码 | `repo/src/git.rs` 的 `run` 85 行（轮询、到点终止、用线程把输出截到 16 MiB）；`store/src/materials.rs` 的 `run` 30 行；另有 8 处直接 `.output()`，**完全没有时限**（材料库 4、`facts` 3、拉起 `agency` 1） | `agency` 入口的 start / status / stop 48 行；`herdr.rs` 里私有 Herdr 服务的启动 76 行、旧进程回收 23 行、`ps` 与发信号约 50 行、`Drop` 约 14 行；合计约 210 行 |
| 社区方案的规模 | 5.2.0 共 2114 行（去掉注释与空行约 1500），macOS 与 Linux 用得到的约 1550 行；依赖 `libc`（已有）和一个新的小依赖 `attr_alias`（608 行的过程宏） | Go 写的独立程序，源码约 1.3 MB；已经随包（1.122.0），换过去包不变大 |

| 风险 | 库最近一次发版是 2025-09-06（13 个月）；终止要做到不误杀被系统复用的进程号，这正是它的卖点；要在两个平台先测 | 未验证：两个 Agency 并存、父进程退出、旧进程回收；Codex 实测过从后台会话启动的进程读不到 Claude Code 的登录，监督器怎么起会影响这一点 |

### 设计层对照（第 5 项的结果）

报告：[Claude · 设计层的协议与对象](../review/20261005-community-first/claude-design-layer.md)。对照了 ACP v1、A2A v1、MCP 2026-07-28，以及 Claude Code、Codex 的 agent 定义、Agent Skills、AGENTS.md。

- **三样都留**：Agency 端口、Context Bundle、Worker Profile 承载的是治理语义（多租户配对、冻结与摘要、票据、输入租约、结果保管到确认、游标缺口），三份社区协议都没有。
- **交给 harness 的那一侧可以借**：上下文交付可用 MCP 与 ACP 共用的内容块（`resource`、`resource_link`）；Worker Profile 落地时可渲染成 Claude Code 的 subagent 文件、Codex 的 agent TOML；名册将来可用 ACP Registry 的条目。现行的 PTY 路线下前一样没有入口，后两样在第二家 harness 接入时做。
- **和第 3c 包相关**：ACP 有结构化的一轮结束信号（`stopReason`），但它要求客户端把 agent 当子进程、走标准输入输出，和「Herdr 实际持有 harness 与会话」是两条路线；Claude Code 与 Codex 都只能经 Zed、JetBrains 维护的适配器说 ACP；Herdr 已把含「ACP registry adoption」的请求关为不做。所以 3c 的「这一轮答完了」建议用 Herdr 社区版的 agent 状态加 harness 钩子，不引入 ACP。
- **一处前后不一致**：`docs/research/README.md` 把 ACP 写成「L1 的 Harness 接入标准」，与 `harness-adapters.md` 的决定和现行实现不符，下一次动研究索引时改成「结构化接入路线的标准」。

这一节不需要所有者另裁：「三样都留」与现状一致；3c 的取法属于作者在验收第 2 条里自己定、写进调研记录的事，报告只是给作者的参考；其余几条都标了「将来做」。
