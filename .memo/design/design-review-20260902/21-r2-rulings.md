- 所有者条件：Process Compose 须跨 mac-intel、mac-arm、linux-x86、win-x86 且有单文件二进制。研究已证：Go 单二进制、官方发行 linux_amd64 / darwin_amd64 / darwin_arm64（已钉 DotSlash）；Windows 资产以 `gh release view` 核对（见聊天）。
- 落地（第三轮，非文档批次）：限时验证 → process-compose.yaml 接管五个服务 → 按服务拆配置模板 → 删通用监督器 shell；control 第二阶段经其 REST / Unix 套接字驱动。用户包增加约 15–16 MB 一个二进制。先补 `docs/research/` 对象文件的发行侧用法段。

### I-13 · harness 钩子作白名单实现 → 方向同意，但先调研（所有者：钩子的调研要进 research）

- 事实：Herdr 无 PreToolUse 类钩子也做不了（在 harness 进程外、PTY 层）；钩子是 harness 自己的机制。链路：Herdr 拉起会话 → 本地 Agency 参考实现在拉起前注入钩子配置 → 钩子调 hctl-tool 按声明白名单判。
- 待办（第三轮调研批次，动代码前）：`docs/research/harness-hooks-<日期>.md`，一 harness 一行：有无钩子、事件名、配置位置（用户级 / 项目级 / 环境变量）、能否硬拒绝、决策格式、能否按会话配置而不污染 worktree、钉版本；覆盖 Claude Code、Codex、Gemini CLI、OpenCode、Cursor CLI、Kimi Code、Qwen Code、Copilot CLI 等；另列 ACP 协议的 `session/request_permission` 作结构化接入模式下的等价物。
- 选法不是「选一个钩子」而是「一份声明式白名单 + 一个检查入口（hctl-tool）+ 每个 harness 一个薄适配」；判据：能在执行前硬拒、按会话配置不动仓库、拿到工具名与参数、有文档且稳定、在我们用的接入模式下可用；不满足者标不支持。
- 与 Herdr 的兼容：原理上无关（Herdr 只按我们给的命令、cwd、环境变量拉起），需验证三点：环境变量与配置目录能透传、钩子回调能找到 hctl-tool、钩子的 stderr 输出不干扰 Herdr 的 agent 状态判定。
