## M · 方法论

### 八条边的快好省（核验后）

| 边 | 交付物 | 谁判 | 快 | 省 | 好 | 结论 |
| --- | --- | --- | --- | --- | --- | --- |
| Project → Task（两次过边） | 身份 + 后端 outbox；契约版本 + 来源引用 | 人（创建、采纳两个命令） | 有契约一次；无契约卡两次（先采纳） | 不：来源冻结为引用 | 承诺可核验、有版本 | 维持 |
| Project / Task → Run | 施工清单 | 人（批准图 + 启动） | 两次动作，别家也两次；一次性施工图上多一次 | 不 | 图与开工分开，讨论不阻塞施工 | 维持；「一次预览同时提交」B 档 |
| Project → Participant | 执行规格 | 人（调用预览） | 一次动作 | 不：三档投喂 | 身份链冻结 | 维持 |
| Run → Participant | 执行规格 | 代码 | 零 | 不：接力只经结晶 | 席位与尝试身份稳定 | 维持 |
| Participant → Project / Run | 结果提案 + 版本 / 证据 | 代码校验，Run 另有评审席位 | 零 | 不 | 自述不能变事实 | 维持 |
| 人 / Run 归约器 → Participant（合入） | 合入命令 + 版本引用 | 代码（回读签凭证） | 无 Run 路径合入与完成是两次动作，比 Gas Town 多一次，买的是「合入 ≠ 验收」 | 不 | 模型说合了不算 | 维持 |
| 人 / Run 归约器 → Task（完成） | 完成命令 + 验收证据 | 代码（独立验收），人或归约器发起 | 有契约一次；无契约卡两次 | 不 | 完成不能自述 | 维持 |
| Task / Run / Participant → Project | 事件；Memo | 无需判；Memo 由人发布 | 投影零；Memo 沉淀一次人的动作 | 不 | 一个 Project 看全局 | 维持 |
| Request（新增行） | 问题 + 阻塞范围 + 输入 schema | 人回答，代码校验 | 一个人的来回，不可省 | 卡片须带阻塞对象精确引用与「为什么问」，回答者不必开终端或重读聊天（待写进约束） | 不猜答案，过期按 fail/cancel | 维持；M-39 |

总结：八条边里施工两道门待裁；另有三处多出的来回（无契约卡先采纳、无 Run 路径合入与完成分两次、Memo 由人发布）是有意的取舍，各自能说出买到了什么；没有一处是白多的。
