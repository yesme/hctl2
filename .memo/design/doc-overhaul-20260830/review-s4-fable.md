## 2. 三条阅读路径逐站走一遍

**新读者**(README → vision → 设计地图 → architecture → 四模块 → participant → context → delivery 范围/阶段):每站承诺的内容在位;README 的「为什么需要它」一段不复述 vision、只给四个精确锚点;设计地图在四模块表之后交代「先看愿景再回本页」的顺序;architecture 的 4×3 矩阵与模块交接表把新读者送进模块正文;四模块末节「模块交接」互链成环;participant/context 定位行明确「横切不是第五模块」;终点 delivery「第一阶段范围」的 P2/P3 双列表恰好回答读完设计后的第一个问题(现在做到哪了)。全程无断站、无循环依赖。

**实现者**(spec/README → system → connections → 模块合同 → contract-tests → delivery 阶段/切片/自举 → research):总则先给词汇法与三条法,system/connections 给共享机制与交接,四件模块合同的「对象 → 写入合同 → 专节 → 外部对齐」结构一致;contract-tests 按族对应模块,delivery 的两条纵向切片与 B0–B6 阶梯给出验收顺序;research 条目索引给依赖证据。走通。唯一注意点:README 实现者一句里链了 delivery 五个锚点,句子偏长但每个锚点都有效。

**provider adapter 开发者**(architecture 场景/锁定 → system 三节 → 模块合同 → contract-tests → delivery 判据/P0 → research):替换边界表 → 受控端口 → 动作分类 → 对应模块合同的外部对齐表,链条完整;P0 五项按「HCTL 实际调用面」陈列,CT-CONNECTION 族覆盖换绑/迁移/客户端无等级。走通。
