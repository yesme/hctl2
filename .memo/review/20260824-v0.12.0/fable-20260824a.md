## 总评

v0.12.0 把上一代基线的全部大问题解掉了：记忆归属（用户级控制面 + 各场景 content 归各自系统 + 结晶进 Git，且"暂时失联"与"永久丢失"分开立约）、Conductor→Dagu（附九候选源码级对比）、CLI 先行（P2 承载 B0–B5，Workbench 退到 P3）、命名清洗（Agent 模块正名、词形收敛）。两份新调研的质量属于设计仓库里的最高一档。

本轮意见的性质随之改变：**不再是"架构有矛盾"，而是"几个押注要说清楚、一笔总账没人立"。**

## 做得好的（均经核实）

- **完成判定权横评**：11 个方法论工具逐仓库查源码，证明没有一家把"完成"做成绕不过的系统边界（每家都留了模型自报通道）——这是本项目诞生以来最硬的一份"为什么该存在"的实证。审计纪律罕见：钉 commit、宣传语不作数、连对方官网已下线的营销文案都考古并注明引用边界。
- **提交直方图判产品重心**：投入口径压过宣传口径（如 Codeg 名义看板、实际七成投入在终端），只有看提交路径才能做出的判断。
- **三面架构 + 4×3 归属矩阵**：把 Workflow/Terminal 已被验证的规则（content 归系统、治理归账本）推广到 Chat/Kanban，一刀解开缠了三个版本的存储归属与"平台能否当事实源"两个结。
- **选型是实测出来的**：Dagu/Zellij/tmux/shpool/Electron 的 RSS、包体、动态库逐项测量；九个 workflow 候选按源码而非 README 复审。
- **反面教材栏**：自由文本当验收证据、提示词当权限边界、LLM 验 LLM、声明权限但执行路径不读——全是给自己立的界碑。

## 发现

### 生死级

**F1 · 横评表证明了"没人做到"，但没问"为什么没人做"——人关单的摩擦必须指标化。**
11 家全留模型自报侧门，大概率不是 11 家都马虎，而是让人关单太烦、用户绕开、产品先死。HCTL2 的正门是"人随时可从看板关单"，真正的赌注很窄：赌"证据替人验好、人只按一下"的摩擦低到用户不绕开。这必须成为被测量的产品指标（关一个单人要做几个动作、等几秒），写进 `CT-PRODUCT`，而不是停留为立场。agent-os 自宫信号的另一面即此：活下来的是 harness 之外的资产，但用户嫌重的工具活不到证明资产价值那天。

**F2 · 五台服务器的整机总账没人立。**
footprint 表逐项诚实（Dagu 92MiB RSS + Vikunja 57 + 十 tmux 37 + Tuwunel 未知且 macOS 需 Linux 容器/VM + control + agentd + Electron 壳空载 78MiB），但从未加总立预算。这类整合套件的第一死法是"装不动/太重"。建议交付文档立两条整机硬指标：从零安装到干成第一件事的时间上限、全家桶空载总 RSS 上限；P0 各探针对总账验收，不是各验各的。

### 中

**F3 · 全场最佳同向实证恰是自己未采纳的机制，需一句"为什么不"。**
survey 把 vibe-kanban"看板列由 Git/PR 事实机械归约（全部合并→Done）"评为生产系统里最完整的同向实证，但借鉴清单只搬其日志格式与适配器代码。HCTL2 的完成只有两条路（人、task-bound Run 正常完成的机械归约），不存在"合入凭证 + CI 齐备后按预冻结规则自动完成"的第三条。拒绝可能是对的（人在环），但设计文档应写明取舍，否则后续读者（或模型）会替设计"补上"这个功能。

**F4 · 砍 swarm 的判词会回旋到三选二头上，需正面论证。**
"多模型互投仍是自述"说得对，但挑剔读者会问：三票两票不也是三个模型的意见？区别是实质的（票绑定精确版本与证据、作者回避、票只过 Gate 不关单、规则由人冻结）——但这个区别现在没写在任何文档。run 设计正文或愿景应有一段"冻结投票 ≠ swarm consensus"。

**F5 · survey 成了第二套准入。**
搬 vibe-kanban executors、搬 Gas Town tmux 封装、采 AGENTS.md 注入面等实质是实现决策，却住在 memo 且自称"与 implementation-evidence 准入相互独立"。按自家文档纪律：已定的升格为正式 evidence 条目，未定的标候选。

**F6 · 借 schema 清单约十种，未排主次。**
EARS、delta 规格、依赖边词表、tasks.json、BMAD 冻结段、must_haves 三层核验等各自有理，但 Task Revision 若全兼容会成杂烩。建议钦定骨架（EARS 与"确定性归约需要可逐条判真的原子命题"最登对；delta 规格承载"相对现状变更"），其余降为导入/导出兼容。

**F7 · Tuwunel 在 macOS 需容器/VM，与 local-first 默认形态相刺。**
P0 已列阻断项，但需明确 B 计划：验证不过退到哪里（备选是否有原生 mac 路径；"B1 前 chat server 可不装"算不算合法降级），勿让唯一"中—高"运维项卡整条 B 阶梯。

**F8 · executors 搬运会快速折旧。**
来源项目已 sunset，六个 harness 每周在变（P0 矩阵钉的六个版本号即证据）。搬"形状"（会话 ID 语义、日志归一测试样本）保值，搬代码等于接一台需持续供养的跑步机。建议该条从"移植组件"降半格为"移植测试样本 + 参考实现"。

### 低

**F9 · 最硬的证据没进愿景（一句话改动，收益最大）。**
"审计 11 家、零家把完成判定权做成系统边界"是愿景"为什么需要 HCTL2"梦寐以求的实证背书，现在躺在 memo 里。愿景引用它。

**F10 · agent-os 信号值得写成排期决策规则。**
被 harness 逐步吞掉风险最高的恰是 Run/Workflow 那套最重的机器（各家都在做编排与子代理），最保值的是账本、身份、完成判定权、跨 harness 中立。现行施工序（B2 先自举、Dagu 至 B4 才必需）已暗合，建议说破："时间不够时，先保什么、可以晚什么。"

**F11 · "十秒答六问"仍无测量方法。**
第一阶段是 CLI，测量对象反而变简单：`status` 一条命令的输出算不算答完六问，可直接写进 `CT-PRODUCT`。

## 所有者指示（本轮拍板，待落地）

**O1 · 评审方法论化：从 BYOA 到专业化评审 Participant。**
现状：设计评审完全靠 LLM 自发性，没有方法论；"场景走查"一类补丁只是微小的查漏补缺，不是解法。真正的解法是在确定 Participant 阶段引入**外部的专业化模型 Participant**（实际形态：模型 + 专用方法论 Skill），而不是 bring-your-own-agent。落地：设计文档显式提及此事，由 Participant 专章/文档承载——已落为 `.memo/design/participant-design-20260819.md` §8（评审方法论化），升格为规范正文时一并 cover。

**O2 · Context 独立成章。**
遍览各 ADE 后的共同结论：Context 是必需品，须在设计文档单独分章（`.memo/design/context-design-20260819.md` 升格），不再散落。

两项与 F5 同向：`.memo` 里已成熟的专题（participant、context、methodology-landscape 的借鉴决定）按各自纪律升格进正式文档，memo 不再长期兼任第二权威。
