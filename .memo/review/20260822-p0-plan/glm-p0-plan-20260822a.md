## 一、P0 边界校准（先于一切动作）

1. **已拍板、不选型**：Tuwunel（chat server）、Vikunja（task server）、Zellij（runtime backend，tmux 为降级方向）、conductor-oss（workflow engine）。P0 回答"关键假设能否落地"，任何探针不得重开"选谁"的问题；只有验证失败才触发既定的重开路径。
2. **产出只有三样**：钉死版本（release/commit + digest + license + build features）、实现证据（回写 implementation-evidence）、产品化约束（启动依赖、数据目录、备份手续、体积与常驻内存实测）。探针脚本、临时数据、拼装环境一律可丢弃，不进产品生命周期。
3. **不是全局 barrier**：按合同，chat/task 探针在 B1 首次消费前、runtime 在 B2 前、Conductor 在 B4 前完成即可。四项彼此独立且都便宜，**全部并行启动**，只按风险排复核优先级（见第五节）。
4. **建议增补第五项：OS 强制执行探针**（超出 delivery 现文，需所有者拍板）。受治理 Harness 的 OS 沙箱、凭据网关代用、Git/凭据隔离，是当前合同最尖的 go/no-go 押注：gap 审计已称其为"P0/B2 阻断性工程验证"，CT-AGENT 有整组越界负例，但 delivery 的 P0 清单没有它。建议显式立项，最晚 B2 前完成；这是唯一可能反噬合同层（system.md 安全边界、agent.md 沙箱条款）的探针。

## 二、仓库形态

```text
probes/p0/<name>/
  manifest.md        # 钉死的 release/commit + sha256 + license + build features
  bootstrap.sh       # 可丢弃环境搭建；全新目录可重跑、可整体删除
  assertions/        # 逐条断言脚本 + 原始输出留存
  findings.md        # 合同假设逐项裁决 + 产品化约束
```

统一纪律：断言必须映射它担保的合同假设（列出处），不写"跑通了"式的游记；每条断言留原始输出；`bootstrap.sh` 从干净状态可重复执行；失败输出不得被脚本吞掉。

## 三、各探针的完成定义（DoD）

### 1. OS 强制执行（新增，复核优先级最高）

- macOS seatbelt（`sandbox-exec` profile）与 Linux bubblewrap/namespace 两腿。
- 正例：harness 进程在沙箱内正常读写获准 worktree、经网关代用凭据完成一次 git 操作。
- 负例即 CT-AGENT 探针版：读 `control.sqlite`/SSH agent/OS secret store/未授权 provider 配置/其他 ChangeSet worktree、越权网络目的地、直接写 target ref——全部必须被 OS 层拒绝（不是被 CLI 拒绝）。
- 附加取证：`sandbox-exec` 在 macOS 的弃用状态与替代路径；无头环境下 profile 的生效验证方式。
- DoD：两平台各一份"能强制什么 / 强制不了什么"清单；若任一平台强制不了，输出降级选项（候选标 unsupported 之外的第二剧本）供所有者重开沙箱合同。

### 2. Zellij（B2 关键路径）

- attach/detach、输入、resize、会话重启、残留进程回收，macOS/Linux 两腿。
- headless 启动期 TUI 能力查询应答（无人 attach 期间 DA1/DA2 类查询须有应答，否则 harness TUI 降级）。
- kitty keyboard protocol 下 Codex/Claude Code/OpenCode 三 harness 按键实测（修饰键、Esc 序列）。
- `zellij-no-web` 瘦身构建可用性与体积差；打包体积与常驻内存实测。
- DoD：上述断言逐条 pass/fail + 实测数字；若 fail 且不可绕，按既定降级方向对 tmux 跑同一套断言。

### 3. Tuwunel（B1 前置）

- 事务 ID 幂等：同 `txnId` 异 payload 重试的实际行为（合同前提，spec/project.md「Room 与消息」）。
- 单 homeserver 线性顺序：并发写入的顺序一致性与时钟无关性。
- 账号/房间管理 API、AppService 程序化注册（不靠房间内发命令）。
- `/sync` 断点重同步与 gappy sync 后的消息完整性。
- RocksDB 状态目录冷备/恢复（停机复制即可，P0 不要求热备）。
- **macOS 腿注意**：官方无 darwin 包——从 pinned 源码构建本身就是探针产出（打包策略押注我方 CI 交叉编译，此处先取证可行性与构建依赖）。
- DoD：合同两条前提（幂等、线性顺序）有原始输出背书；固定 release/commit/build features。

### 4. Vikunja（B1 前置）

- **排序并发令牌**（最关键）：看板排序写入是否存在可条件写入的令牌（ETag/版本前置）；没有则按 spec/task.md「排序与位置永远归 content 后端」的降级条款记录，不得伪造。
- 相对移动 vs 绝对移动语义；跨 project/泳道移动后卡片身份与 webhooks 的行为。
- webhook 投递可靠性 + 轮询兜底（合同不依赖公网 webhook）。
- SQLite 运行中备份与恢复。
- DoD：排序令牌结论明确（有/无/部分）；身份稳定性断言 pass；固定版本。

### 5. Conductor（B4 前置，风险最低）

- postgres-only 容器形态启动（免 Elasticsearch）；Lima/Colima VM 跑 Linux 腿。
- external task poll/complete 往返；worker 崩溃后 redelivery 行为（对应合同「Engine retry 创建新 Obligation」的机械前提）。
- timer/wait 节点；带状态升级路径（旧版本 → 新版本）。
- pg_dump 备份/恢复；镜像体积 + JVM/PG 常驻内存实测。
- DoD：最小持久化组合与打包重量有数字；失败即按合同重开 Engine 选型决定。

| 角色 | harness | 理由与边界 |

## 五、时序与人审门

1. **第 0 步（约半天）**：Fable 搭 `probes/p0/` 骨架与 findings 模板；Grok 出五份测试矩阵；**所有者审矩阵后再放行脚本**——矩阵错了脚本全废。
2. 五探针并行。复核优先级：**OS 强制 ≈ Zellij（B2 关键路径）＞ Tuwunel/Vikunja（B1）＞ Conductor（B4）**。
3. **过一门审一门，不过批**：每个探针完成后由所有者逐项裁决 pass/fail，Fable 即刻回写证据；失败立即触发既定重开路径（Tuwunel→Continuwuity 备选、Zellij→tmux 降级、Vikunja→git-bug 对照、Conductor→重开 Engine 决定），不留到收尾批处理。
4. OS 强制探针若两平台都强制不了：**停下，先重开沙箱合同设计**（影响 system.md/agent.md 多处），不要带着空洞继续铺 P1。
5. 全部收口后：Gemini 干净环境复核一轮；Fable 汇总 findings，更新 delivery P0 节与 implementation-evidence。

预计墙钟 3–5 个工作日（并行展开）；复核与回写另计半天。

## 六、本计划自身的边界

- 不重定义 P/B 双表语义，不改动合同层；第五项 OS 强制探针的立项是对 delivery 的增补建议，采纳与否由所有者裁定。
- 分工表是能力画像建议，不预设调度权威；所有者可任意重组。
- 探针结果若与合同假设冲突，一律走"重开对应选型决定 + decision-history 记录"，不在探针仓库就地改合同。
