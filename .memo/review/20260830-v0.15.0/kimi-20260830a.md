## 一、结论先行

主干判断：**当前设计文档是正确的，且健康度在变好。** 可以按计划进入 P2 施工，挡路的只有一个小拍板和两处文档残留，不是结构问题。

依据不是"读起来合理"，而是演进形状：v0.12.3 评审（codex）的结论是"可以开始 coding"，No-go 项全是"不该写的复杂度"；v0.13→v0.15 的七轮修订几乎全是删过度设计和诚实降级（撤沙箱入场券、撤在场证明、代次移出 Dagu、客户端无等级），没有一次新对象爆炸。审计纪律（两轮封顶、转向立项、逐条裁决）在真实起效。核心不变量——三类数据、四模块事实归属、单写者账本、证据高于进度、Task 终结只有两个来源——经过五轮评审没有反复。

瑕疵集中在两类本项目自己已诊断过的病：转向传播残留、过强断言未清理。

## 二、瑕疵一：转向传播残留（v0.12 审计定性过的病，再现）

`docs/design/delivery.md` 内部自相矛盾：

1. P0 第 3 条说 Tuwunel 的 macOS 包是"HCTL2 在自己 GitHub Release 托管的预编译制品，源码构建不进日常依赖图"；但「打包策略」一节仍写"Tuwunel 因上游没有 Darwin 二进制而**从锁定源码原生构建**"。`3b0d89c` 已切换到消费托管制品，这句话没跟上。
2. 同节的"macOS 最低基线为 15"出处是 decision-history §19——**那是 tmux 官方二进制的约束**。tmux 在 v0.14.1（§29）已整体退场，这个地板失去论证。要么由 Tuwunel/Herdr 的 Darwin 制品重新论证，要么降下来。

## 三、瑕疵二：已裁决"先不改"的过强断言仍挂着 MUST

`.memo/notes/doc-cleanup-backlog-20260825.md` 的 13 条（存储拓扑写死、所有动作必须 Preview、Context 必须毫秒级零模型、活动 Run 禁改契约等）至今仍在合同原文里。codex 评审的处置建议是"进入相应切片时再做最小合同清理"——建议本身对，但前提是每个切片开工前真清。风险是 P2 的实现者把过强条款当成要建的系统。

B0–B2 路径会撞上的只有三条：存储拓扑（B0 第一天建目录）、Preview 强制（CLI 日常使用）、Context 零模型硬门（B2 纵向切片要萃取聊天史）。其余 10 条留给对应切片，不需要再开一轮大审计。

## 四、瑕疵三（待拍板，不是错误）：agentd PRD 归类未完成

`.memo/design/hctl2-agentd-prd-20260826.md` 仍在 `.memo` 待拍板表。agentd 退场后其条款要按"内置 Agency / 控制面网关 / 现场保管"三类重新归位；Herdr 接了 Agency 之后，剩下的恰好就是 **control 自己的边界**。这是 P2 开工前唯一真正挡路的设计决定，建议展开成可拍板的对照表处理。

## 五、架构风险（非文档瑕疵）：Herdr 单点与缺失的上游触发条件

v0.14.1 放弃自建终端服务、把 Terminal 场景押在 Herdr 上，方向是对的（避免再造一个产品）；设计对 Herdr v0.8.2 已知限制（无输入租约、无统一写入门、事件环无 sequence/gap、停止回读不足）的诚实降级也处理得好。但文档只写了"需要运行服务支持的优先修改 Herdr 上游"，没有写**上游不接受时怎么办**的触发条件。若这些能力长期缺位，"受管单写者"一档保证永久空缺。建议补一条触发条件（什么情况下重开 Agency 选型或接受该档位永久缺失），记入 decision-history。

## 六、下一步

按 delivery 的 P/B 表对账：P0 探针基本完成（tmux 接缝、Herdr 验证、Tuwunel 托管制品均已入库），P1 大部分就位（`hctl2-tool`、Buck2 发行链、Herdr 打包）。下一步是 **P2 · 接钥匙，从 B0 开始**。建议顺序：

1. 拍板 agentd PRD 三类归类（决定 control 第一刀：Herdr 适配代码、终端票据网关、现场保管哪些进 control、哪些进 tool）；
2. 修 delivery.md 两处残留（小修订台账一行的事，但会误导打包实现）；
3. 只清理 B0–B2 撞得上的三条过强断言，其余留给对应切片；
4. B0 开工：control 骨架——SQLite 账本 + 单写者锁、command envelope/幂等、outbox/事件流、`hctl2 init/start/status/doctor`。B0 不依赖任何 content 系统产品化，可立即动；验收标准现成（B0 晋级行 + `CT-SYSTEM` 失败用例族）。构建按约束走 Buck2 原生目标。

B1（Tuwunel/Vikunja 首次消费产品化）与 B2（无 Run 自举 = 纵向切片 A）排在其后；Run pause 语义、Project 归档是否禁言 Matrix 两个 go-with-local-decision 项到 B4 和归档切片前再拍，不挡现在。

## 七、本轮刻意没有做的事

- 没有因 delivery.md 两处残留而重开打包策略讨论——它们是传播遗漏，不是选型问题；
- 没有把 13 条过强断言逐条给出裁决建议——所有者已裁决"记下来，先不改"，本轮只指出切片开工前的清理时机；
- 没有重评四类执行面选型（Tuwunel/Vikunja/Dagu/Herdr）——v0.13–v0.15 的改判均有源码级证据支撑，本轮未发现需要再翻案的新事实。
