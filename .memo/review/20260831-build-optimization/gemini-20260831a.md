## 三、 第一问：关于“目的”是否有必要？

**裁决：非常必要，且属于工程基础设施层的高价值刚需。**

### 展开论述：

1. **化解多 Harness 并发协作的吞吐瓶颈**
   - HCTL2 采用 6 个不同 Agent（Codex、Claude、Grok、Kimi、GLM、AGY）高频协作模式。
   - 在优化前，任一 Agent 提交一行文字修改或编辑 PR 描述，都会无差别触发 Linux x86_64、macOS x86_64、macOS arm64 三平台的全量 Buck 编译、Cargo 检查及完整 Release 打包（单次 3～4 分钟，且严重挤占 macOS runner 资源）。
   - 优化将非代码 PR 的响应时间缩短至 20～30 秒，直接解决了 CI 队列拥堵与反馈延迟。

2. **化解严格分支保护（Strict Gate）与重复计算的死锁**
   - GitHub 的 Strict Branch Protection 要求合入前必须同步最新 `main`。在多 Agent 连续合并时，每合入一个 PR，其他排队 PR 均需“Update branch”。
   - 若每次更新都重跑三平台全量编译，多 PR 排队将陷入严重的反常阻塞；第四批优化（PR #123）在不降低门禁权威的前提下复用祖先成功证据并仅验证增量，打通了合并吞吐瓶颈。

3. **守住验证强度与可信度底线**
   - 目的不是通过宽泛的 `paths-ignore` 绕过检查（那会导致 Required Check 在 GitHub 侧变成 `Pending` 悬空，或漏掉隐式破坏性依赖变更）。
   - 优化的原则是“**只收敛执行范围，不降低验证强度；选择器异常无条件全量回退**”，目标极其明确且克制。

## 四、 第二问：关于“手段”是否合适？有没有完全原生化？

**裁决：手段高度合适，严格贯彻了“原生/业界标准优先”，没有自造私有轮子。**

### 展开论述：

1. **变更侦测：使用 Meta 官方 `btd`，未自写图遍历解析器**
   - **业界标准**：未编写私有的 `git diff + grep` 或脆弱的 Python 脚本猜测变更影响，而是引入 Meta 为 Buck2 配套开源的 [Buck2 Change Detector (`btd`)](https://github.com/facebookincubator/buck2-change-detector)，并严格按纪律在 `docs/research/build-tools/buck2-change-detector.md` 完成了源码审计与二进制锁定。
   - **原生图能力**：充分利用 Buck2 原生声明式规则（`tests=[...]`、Label、`test --build-default-info`），将构建依赖与测试关系完全建模在 Buck 图内部，而非散落在外部脚本。

2. **远程缓存：对接通用 REAPI 标准，未自建专有缓存机制**
   - 远程缓存直接对接业界通用的 **REAPI（Remote Execution API）** 标准，利用 Buck2 原生的 `.buckconfig` 进行声明式挂载（测试消费官方 `bazel-remote`）。
   - 严格遵循 mTLS 与安全凭据边界，未自造任何基于 tarball 或私有 API 的缓存旁路。

3. **文档分类：复用 Git 原生 `.gitattributes`，未自创路径 DSL**
   - 文档 Profile 分类（design / spec / delivery / research / memo）直接声明在 Git 原生 `.gitattributes` 中，通过 `git check-attr` 统一查询。
   - 使得本地命令行、Git pre-push hook 与 GitHub Actions 使用完全一致的单一事实源。

4. **架构解耦：CI 逻辑与 GitHub-hosted 解耦**
   - 将目标选择与验证提升为通用的 `src/build/ci/affected-targets` 与 `src/build/ci/verify-affected`。
   - 使得本地开发机、Git pre-push hook 与第三方 CI 均能脱离 GitHub Actions 跑出完全一致的判定结果。

5. **防御性设计（Fail-closed 安全回退）**
   - 所有批次均严格实现“失败关闭”：一旦 `btd` 解析失败、图导出异常、GitHub API 查询失败或检测到 rebase 改写历史，一律**无条件回退到全量第一方目标测试**，绝不漏测。

## 五、 综合评价

Codex 交付的 4 批构建系统优化在目标上精准定位了并发协作瓶颈，在手段上严守了原生化与业界最佳实践。该优化不仅大幅提升了 CI 反馈效率，也为多 Agent 长期并行开发提供了稳固可靠的构建与验证基石。
