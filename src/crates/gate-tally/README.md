# Gate 计票（第 5a 包）

P2.5 第 5a 包：评审关卡的计票，只做纯算法。依据是 [`spec/run.md` §计票与结束](../../../docs/design/spec/run.md#计票与结束)，以及 §Request、重试与 Gate 里关于去重键、否决权与多样性的几段。它不读写存储，不依赖别的 crate，也没有三方依赖。席位、候选与事实从哪条记录取，由第 5b 包在接入时决定；本包只规定输入长什么样、怎么算。

## 接口

`tally(&Gate) -> Result<Tally, Invalid>`：输入是法定票数和这一轮关卡的全部席位，每个席位带着冻结数据与已记录的事实；输出是结论和按键分好的组。同一组事实无论按什么顺序排进 `Gate::seats`，结果都一样。

席位上的字段：

| 字段 | 含义 |
| --- | --- |
| `veto` | 关卡策略给这一席声明了否决权 |
| `candidates` | 这一席还能用来产出裁决的 Worker Profile 摘要：正在跑的尝试用的那个，加上获准候选里还没试过、没失败的 |
| `material` | 这一席交付内容摘要所依据的冻结引用（ReviewSubjectRef、席位必需 Skill 的引用、根 Manifest）的摘要；两席不同即证明交付内容不同 |
| `delivered` | Bundle 交付后的实际交付内容摘要 |
| `attempt` | 最近一次尝试：未派发、在跑、已交提案、失败（`allowed` 表示故障类型在冻结策略允许切换之列） |
| `pending` | 已冻结、尚未准入的提案，带它产出时的键；不计票，也不当作没有 |
| `vote` | 有效裁决：已过结果准入的裁决与键；`evidence_channel` 只为凭证记录，不进键 |
| `end` | 由既有准入与撤权规则判定的结束：取消、替代、到截止 |
| `budget_left`、`time_left` | 预算、剩余截止还允许再开一次尝试 |

五个词对应的方法：

| 约束里的词 | 方法 |
| --- | --- |
| 有效裁决 | `Seat::vote` |
| 仍可产出 | `Seat::producing`；其中「还能再开尝试」是 `Seat::can_open_attempt`，候选切换也用它判 |
| 已结束 | `Seat::ended` |
| 仍可能加入 | `Seat::may_join` |
| 已定 | `Group::decided` |

结论 `Outcome` 有五种：

- `Pass`：签汇总 Verdict/Receipt，撤销 `revoke` 里的席位。已交提案待准入的席位不撤；被撤席位之后交回的提案只留历史，不形成组、不改已签汇总。
- `Vetoed`：否决席的有效裁决不是 `accepted`，走返工路径。
- `VetoUnresolved`：否决席结束了却没有有效裁决，按候选耗尽处理：建 Request 或标类型化技术失败，不签通过。
- `QuorumUnreachable`：上界少于法定票数，返回 `quorum-unreachable`，沿失败边推进。
- `Pending`：暂未收齐，继续等；等待由各席位的结束保证有界。

五步重算的落法：第一步「结果准入」在调用之前完成，准入过的裁决才记成 `vote`。第二步按键分组，`Group::decided` 用「没有席位仍可能加入」判。第三步先看否决。第四步签通过要满足三条：已定的通过组够数；没有仍可产出的否决席；剩余席位不能否定通过。第五步算上界：当前全部有效裁决（含未定组里的）是固定输入，每个仍可产出的席位取对通过最有利的落点。

`Diversity::check` 是席位多样性的检查，只有两项可声明：Worker Profile 互异、回避作者所用的 Worker Profile。启动时用选定记录的 Profile 查，候选切换后用实际 Profile 查，有违反就拒绝启动或拒绝切换。证据通道与 harness 不在其中。

## 约束没写死、本包自己定的读法

这几处请评审与第 5b 包留意：

1. **最不利的顺序。** `rejected` 最不利，其次是落在契约的 `changes_requested`，再次是落在实现的，最后是 `accepted`。约束只写「取最不利」，没给两种 `changes_requested` 与 `rejected` 之间的先后。契约内分歧会停下返工、交给人，所以排在实现内分歧之前。
2. **「冻结引用能否证明不同」用 `material` 判。** 两席的冻结引用摘要不同，就证明交付内容不同；相同则证明不了，算可能相同。
3. **上界里，未交付的席位总能落到一个自己独有的键上**：它的交付内容还没定，没有什么能证明它与别人相同。这和「仍可能加入」里「证明不了不同即算可能相同」方向相反，两者各取对自己那一步保守的一边：上界不提前判失败，已定不提前签通过。
4. **已冻结待准入的提案**，键按它产出时记下的算（既用于「仍可能加入」，也用于上界）；它的裁决内容在准入前不用，上界里按 `accepted` 计。
5. **CT-RUN 第 29 条第一句的两种顺序。** `accepted` 先到时，组要等另一席准入或结束才定；`changes_requested` 先到时，按第 31 条的上界规则，这一轮当场就判不可达，因为那个组已经过不了。两种顺序的结论相同；但「标需要关注」（`Group::split`）只在两票都准入后才出现。

## 用例

`tests/ct_run.rs` 把 CT-RUN 第 29、30 条逐句写成用例，另有第 31 条运行期的一半、第 17 条判定的一半、第 32 条计票的一半。`tests/properties.rs` 是性质用例：随机生成各席位的事实序列，按八种到达顺序逐条记录、逐条重算，签了通过就照撤销名单撤席。检查四件事：

- 是否通过不随顺序变；
- 不通过时各顺序的最终结果完全相同；
- 签了通过就不再变，确定不可达之后也不会变成通过；
- 每个席位都结束后不会还停在暂未收齐。

随机数用固定种子的 splitmix64，失败时报出种子就能复现。
