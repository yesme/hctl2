## E-L1-HAPPY · Happy

### 它是什么(产品形态与投入口径)

Happy 是把本机编码代理 CLI(Claude Code、Codex 等)会话远程化到手机/网页的开源工具,自称卖点是端到端加密(E2E,服务器不可读内容)的多设备同步。形态是三角:本机 `happy` CLI 兼守护进程(daemon,常驻后台进程)、中继服务器(官方云或自托管,`HAPPY_SERVER_URL` 可指向自建实例)、Expo/React Native 移动与 Web 客户端,全部装在一个 monorepo 里(2026-01-27 由 happy-cli/happy-server 三仓合一,旧仓 2026-02-14 归档)。投入口径要留意:主仓 90 天 226 commits 仍在维护,但团队重心已转向两个新仓——`happy-agent`(自研通用 Harness「rig」,基于 Pi,2026-07 起 90 天 2044 commits)和 `happy-desktop`(Slack 形态桌面端,889 commits);主仓 CLI 已内置可选启动 happy-agent 机器级守护的钩子(默认关闭,[happyTerminalBoot.ts#L39-L53](https://github.com/slopus/happy/blob/b824cd0a4681d41af631a8e422a813873e4455b0/packages/happy-cli/src/daemon/happyTerminalBoot.ts#L39-L53))。另有 `murmur` 仓在做 MLS(RFC 9420 消息层安全,TreeKEM 群组棘轮)前向保密信道,是其下一代加密方向。

### 设计亮点(远程操控与会话同步视角,含代码证据链接)

**E2E 加密核实为真,服务器只见密文。** 算法是 NaCl(tweetnacl/libsodium)加 AES-256-GCM 双制式:老制式用账户主密钥直接做 secretbox(XSalsa20-Poly1305);新制式每会话生成随机 32 字节数据密钥走 AES-256-GCM,数据密钥用密封盒(sealed box,一次性密钥对加密给账户 X25519 公钥)存到服务器([api.ts#L37-L52](https://github.com/slopus/happy/blob/b824cd0a4681d41af631a8e422a813873e4455b0/packages/happy-cli/src/api/api.ts#L37-L52)、[encryption.ts#L62-L79](https://github.com/slopus/happy/blob/b824cd0a4681d41af631a8e422a813873e4455b0/packages/happy-cli/src/api/encryption.ts#L62-L79)、[#L154-L174](https://github.com/slopus/happy/blob/b824cd0a4681d41af631a8e422a813873e4455b0/packages/happy-cli/src/api/encryption.ts#L154-L174))。客户端从主密钥用 HMAC-SHA512 密钥树派生各用途子钥([deriveKey.ts](https://github.com/slopus/happy/blob/b824cd0a4681d41af631a8e422a813873e4455b0/packages/happy-app/sources/encryption/deriveKey.ts)、[encryption.ts#L17-L20](https://github.com/slopus/happy/blob/b824cd0a4681d41af631a8e422a813873e4455b0/packages/happy-app/sources/sync/encryption/encryption.ts#L17-L20))。服务器数据模型里消息统一是 `{t:'encrypted', c:密文}` 信封([messages.ts#L6-L9](https://github.com/slopus/happy/blob/b824cd0a4681d41af631a8e422a813873e4455b0/packages/happy-wire/src/messages.ts#L6-L9)),Session/Machine 的 metadata 与 agentState 也全是密文字段([schema.prisma#L95-L115](https://github.com/slopus/happy/blob/b824cd0a4681d41af631a8e422a813873e4455b0/packages/happy-server/prisma/schema.prisma#L95-L115))。仍明文的元数据:账户公钥、session tag、seq、时间戳、push token、RPC 方法名、用量 tokens/费用([usageHandler.ts#L63-L67](https://github.com/slopus/happy/blob/b824cd0a4681d41af631a8e422a813873e4455b0/packages/happy-server/sources/app/api/socket/usageHandler.ts#L63-L67)),以及推送通知的标题正文(由 CLI 明文提交,[pushRoutes.ts#L95](https://github.com/slopus/happy/blob/b824cd0a4681d41af631a8e422a813873e4455b0/packages/happy-server/sources/app/api/routes/pushRoutes.ts#L95))。

**配对即授钥。** 设备配对不经服务器信任:CLI 生成一次性 X25519 密钥对,把公钥编进 `happy://terminal?<公钥>` 二维码([auth.ts#L102-L103](https://github.com/slopus/happy/blob/b824cd0a4681d41af631a8e422a813873e4455b0/packages/happy-cli/src/ui/auth.ts#L102-L103));手机扫码后把账户主密钥(新制式为账户公钥)加密给该一次性公钥,经服务器盲转([useConnectTerminal.ts#L31-L38](https://github.com/slopus/happy/blob/b824cd0a4681d41af631a8e422a813873e4455b0/packages/happy-app/sources/hooks/useConnectTerminal.ts#L31-L38))。密钥即全部权限,没有分级授权。

**观察通路是结构化事件投影,不是终端字节。** CLI 把代理输出规整成 text/tool-call-start/tool-call-end/usage/turn 等结构化事件加密上行([sessionProtocol.ts#L22-L57](https://github.com/slopus/happy/blob/b824cd0a4681d41af631a8e422a813873e4455b0/packages/happy-wire/src/sessionProtocol.ts#L22-L57))。本地/远程是双模式:`local` 模式把 Claude Code 直接接管终端跑,`remote` 模式改用 Claude Agent SDK 无头驱动,`controlledByUser` 状态位标记谁持有输入([types.ts#L401-L413](https://github.com/slopus/happy/blob/b824cd0a4681d41af631a8e422a813873e4455b0/packages/happy-cli/src/api/types.ts#L401-L413))——单写者语义靠模式切换实现,不是租约。

**同步与恢复:服务器序号是排序权威,内容仍是密文。** 每会话一个服务器分配的单调 seq,客户端维护接收游标按 `after_seq` 拉取,发送走带 `localId` 幂等去重的离线出箱(outbox),且自己 POST 的回执不推进接收游标以免跳过对端消息——注释里明写这是踩过的坑([apiSession.ts#L229-L240](https://github.com/slopus/happy/blob/b824cd0a4681d41af631a8e422a813873e4455b0/packages/happy-cli/src/api/apiSession.ts#L229-L240)、[#L658-L689](https://github.com/slopus/happy/blob/b824cd0a4681d41af631a8e422a813873e4455b0/packages/happy-cli/src/api/apiSession.ts#L658-L689))。metadata/agentState 更新用版本号 CAS(比较并交换),冲突时服务器回抛当前版本让客户端重放([sessionUpdateHandler.ts#L34-L48](https://github.com/slopus/happy/blob/b824cd0a4681d41af631a8e422a813873e4455b0/packages/happy-server/sources/app/api/socket/sessionUpdateHandler.ts#L34-L48))。没有版本向量;daemon 可用 `HAPPY_RECONNECT_*` 环境变量组(会话 id、密钥、seq、版本号)让新进程以同一会话身份续接([sessionEnvironment.ts#L6-L19](https://github.com/slopus/happy/blob/b824cd0a4681d41af631a8e422a813873e4455b0/packages/happy-cli/src/daemon/sessionEnvironment.ts#L6-L19))。

**输入与审批路由:RPC 中继房间 + 密文载荷。** 远程控制走 socket.io:daemon 按「用户:方法」加入 `rpc:U:M` 房间,服务器只按房间名转发、带 30 秒超时与 15 秒重连宽限([rpcHandler.ts#L7-L14](https://github.com/slopus/happy/blob/b824cd0a4681d41af631a8e422a813873e4455b0/packages/happy-server/sources/app/api/socket/rpcHandler.ts#L7-L14)),RPC 参数与应答均端到端加密([RpcHandlerManager.ts#L73-L94](https://github.com/slopus/happy/blob/b824cd0a4681d41af631a8e422a813873e4455b0/packages/happy-cli/src/api/rpc/RpcHandlerManager.ts#L73-L94))。工具权限审批(permission prompt)由 SDK 的 canUseTool 回调挂起,请求写进加密 agentState(断线不丢、多端可见),手机以 `permission` RPC 应答 approved/approved_for_session/denied/abort([BasePermissionHandler.ts#L17-L21、L76-L90](https://github.com/slopus/happy/blob/b824cd0a4681d41af631a8e422a813873e4455b0/packages/happy-cli/src/utils/BasePermissionHandler.ts#L17-L21))。远程启动是手机对 daemon 发 `spawn-happy-session`(目录、代理类型、权限模式、resume/fork 点),另有基于复制截断 Claude 本地 JSONL 的 fork/回退 RPC 族([apiMachine.ts#L150-L273](https://github.com/slopus/happy/blob/b824cd0a4681d41af631a8e422a813873e4455b0/packages/happy-cli/src/api/apiMachine.ts#L150-L273))。推送(Expo)只在完成/审批/提问三类事件时发,且有 UI 活跃即抑制的焦点追踪([pushDispatch.ts#L1-L23](https://github.com/slopus/happy/blob/b824cd0a4681d41af631a8e422a813873e4455b0/packages/happy-server/sources/app/push/pushDispatch.ts#L1-L23))。

**Harness 适配面:** Claude Code(Agent SDK 深度集成)、Codex(app-server 协议客户端)、Gemini CLI 与 OpenCode(走 ACP,即 Agent Client Protocol 代理客户端协议,还支持 `happy acp -- <任意命令>` 通用挂接,[acpAgentConfig.ts#L6-L9](https://github.com/slopus/happy/blob/b824cd0a4681d41af631a8e422a813873e4455b0/packages/happy-cli/src/agent/acp/acpAgentConfig.ts#L6-L9))、Antigravity、OpenClaw。tmux 现状:daemon 生成会话时仅当 spawn 请求的环境变量档案显式给出 `TMUX_SESSION_NAME` 且本机装有 tmux 才把 CLI 放进 tmux 窗口,否则就是普通后台子进程([run.ts#L398-L414](https://github.com/slopus/happy/blob/b824cd0a4681d41af631a8e422a813873e4455b0/packages/happy-cli/src/daemon/run.ts#L398-L414));remote 模式无头驱动 SDK,全程不需要 PTY(伪终端)。

### 采用与边界(建议复用决策 + 不采用边界 + 对既有观察清单行的确认/修正)

- 建议复用决策:**仅参考行为**。Happy 不拥有任务语义,密钥即全权、无治理权威、无输入租约,不能作 HCTL2 事实源;但它是「结构化事件投影 + 审批远程路由 + 密文中继」的完整活体参照,与 Terminal 场景的 L1 观测定位吻合。
- 最值得参考的行为:① 配对即授钥的 QR 流程(对照控制面签发短期票据:Happy 证明中继可以全程盲转,但也示范了「无租约、无代次」的边界——密钥泄露即全线失守);② 单调 seq + localId 幂等 + 收发游标分离 + 版本号 CAS 的同步语义(与输入租约的 TTL/代次/CAS 同族,注释里的游标踩坑记录有直接工程价值);③ 审批请求落加密状态、应答走按方法建房的 RPC 中继(审批路由的断线不丢与多端可见)。
- 不采用边界:不引其 Session/Machine/agentState 等名称与数据结构为 HCTL 公开结构;不采用其服务器为依赖(排序权威在中继服务器,与 HCTL2 控制面唯一权威冲突);murmur 未定许可前不引用其代码。
- 对既有结论:观察清单行「守护进程、端到端加密同步、远程启动、多设备;MIT;第二阶段观察」全部确认,E2E 从 README 落实到代码。2026-08-29 复审的钉定 commit 仍是 HEAD,「Node CLI/daemon 与远程同步」「远程控制与 Harness adapter」确认;「本地进程路径优先借 tmux」需修正为:tmux 仅在用户环境档案显式配置时使用,默认远程生成是无 PTY 的后台子进程;「底层仍需要 tmux/PTY host」不成立——远程观察不经终端字节,PTY 只服务于人在本地终端接管的场景(其机器级 PTY/守护的未来在 happy-agent 的 happy-terminal,主仓预留了默认关闭的启动钩子)。
