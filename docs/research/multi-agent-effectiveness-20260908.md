# 多 agent 协作到底有没有效：六篇必读与补查文献的实证归纳

> 类别：跨候选归纳 · 证据编号：E-MULTI-AGENT-EFFECTIVENESS<br>
> 状态：文献调研 · 日期：2026-09-08；发布后正文不改，只在文末追加复核记录<br>
> 总览与复用决策用语见 [docs/research/README.md](./README.md)。

## 问题

HCTL2 的评审关卡（Gate）里坐多个评审席位（Seat），各自独立投票，法定票数由施工图声明；评审席位绑定「专业化 Participant = 稳定身份 + 方法论 Skill + 模型」；愿景层刚立了一条原则「取舍看快、好、省」——快与省的单位是轮次与 token，好的单位是证据。所有者问了三件事：

1. **多 agent 协作真的有效吗？** 同等算力或同等 token 预算下，多 agent（辩论、角色分工、编排）比单 agent 好在哪、差在哪？会不会只是烧 token？
2. **多 agent 是否提升了评审或验证结果？** 如果是，靠的是什么——模型不同（异构）、提示词或人设不同（同一模型多模板）、还是流程结构（独立投票、不看彼此发言、对抗核验）？「同一个模型换个名字给自己投票」有没有用？
3. **什么结构让它有效、什么结构让它失效？** 编排由代码持有还是由模型临场决定；验证靠外部工具还是靠另一个模型；轮次上限；信息隔离。

读法先说清一件事：早期框架论文（CAMEL、AutoGen、MetaGPT、Magentic-One）报告的对照，几乎都不是「同等预算」的对照——多 agent 一方调用次数、token 都多得多，基线是单次作答的裸模型。真正做了等预算对照的是 2023 年底以后的复核类论文（Huang、Smit、Zhang、Choi、Zhu、Bertalanič、Kim）。下文把这两类分开读，「论文明说」与「我们的推断」也分开写。

## 逐篇

### 必读六篇

#### CAMEL（arXiv:2303.17760，v1 2023-03-31，v2 2023-11-02；NeurIPS 2023）

**做了什么。** 提出「角色扮演」：一个 AI 用户和一个 AI 助手，靠一段「启动提示」（inception prompting）各自守住角色，自动来回对话把任务做完。目的是生成对话数据、研究多 agent 行为；顺带用生成的数据微调 LLaMA-7B。

**怎么测。** 从 AI Society、Code 两个数据集各抽 100 个任务，用 GPT-4 把 CAMEL 的整段对话摘成一份方案（作者说这是为了让评审看不出格式），和 gpt-3.5-turbo 单次作答并排比；人评（453 份回答，只做 AI Society）和 GPT-4 评各一遍；附录另和 gpt-3.5-turbo 加零样本 CoT 比了一次。微调模型跑 HumanEval 与 HumanEval+。

| 对照 | 平局 | 基线胜 | CAMEL 胜 |
| --- | --- | --- | --- |
| AI Society · 人评 · vs gpt-3.5-turbo 单次 | 13.3% | 10.4% | 76.3% |
| AI Society · GPT-4 评 · vs gpt-3.5-turbo 单次 | 4.0% | 23.0% | 73.0% |
| Code · GPT-4 评 · vs gpt-3.5-turbo 单次 | 0.0% | 24.0% | 76.0% |
| AI Society · GPT-4 评 · vs 零样本 CoT（附录表 8） | 4.0% | 28.0% | 68.0% |

微调结果：HumanEval pass@1，CAMEL-7B 14.0，Vicuna-7B 11.0，LLaMA-7B 10.5，gpt-3.5-turbo 69.4。

工程细节值得记：对话上限 40 条消息，作者说成本随对话长度平方增长，不设上限而终止失效时「可能上千次 API 调用、几百美元」；终止条件另有 token 上限与助手说出结束标记。作者自己记录了四种失败：角色互换、助手复述指令、「I will…」式空话不行动、以及双方无意义地互相道谢的死循环——有时两边都知道在循环却跳不出来。

**局限。** 比较对象是单次作答，不是等 token 的自一致性；评的是 GPT-4 写的摘要而不是原对话；两角色是同一个模型；没有 token 或调用次数的账。

**对三问。** 问题一：多轮胜过单次，但对照没有等预算，无法区分「多 agent 有效」和「多花算力有效」。问题二：不涉及评审。问题三：作者亲手给出了「多 agent 会死循环、要有轮次硬上限和结束标记」的第一手证据。

#### AutoGen（arXiv:2308.08155，v1 2023-08-16，v2 2023-10-03）

**做了什么。** 一个编程框架：agent 是可对话的计算单元，对话本身是控制流；提供两 agent 对话、由代码持有的群聊管理器（谁下一个说话、何时终止、何时插入人）等模式。

**怎么测。** 六个应用（A1 到 A6），有对照的是四个：MATH 数学题、检索增强问答、ALFWorld 决策、OptiGuide 供应链代码安全审查，另有 12 个人造任务的群聊试点。

| 应用 | 对照 | 数字 |
| --- | --- | --- |
| A1 MATH，120 道 level-5 | 成功率 | AutoGen 52.5%，ChatGPT+代码解释器 48.33%，ChatGPT+Wolfram 插件 45.0%，裸 GPT-4 30.0%，Multi-Agent Debate 26.67%，LangChain ReAct 23.33% |
| A1 MATH，全测试集 5000 道 | 准确率 | AutoGen 69.48%，GPT-4 55.18% |
| A3 ALFWorld，134 个任务 | 成功率（3 次平均 / 3 次最好） | 三 agent（加一个常识 grounding agent）69% / 77%；两 agent 54% / 63%；ReAct 54% / 66% |
| A4 OptiGuide，100 个任务 | 识别不安全代码的 F1 | 多 agent（加一个安全审查 agent）比单 agent 高 8 个点（GPT-4：96 vs 88）和 35 个点（GPT-3.5：83 vs 48） |
| A5 群聊试点，12 个任务 | 成功数 / 平均调用 / 终止失败 | 两 agent：8 与 9 成功（GPT-3.5 与 GPT-4）、9.9 与 6.8 次调用、9 与 3 次终止失败；角色扮演式群聊：9 与 11 成功、5.3 与 4.5 次调用、0 终止失败 |

**局限。** A1 里的「多 agent」其实是「助手 + 代替用户执行代码的代理」，优势来自把代码执行接进循环，不是多个 LLM 商量；Multi-Agent Debate 在同一张表里垫底。基线不等预算；12 个任务的试点样本小；论文没有 token 账。

**对三问。** 问题一：收益来自工具执行与专责检查，不来自多个模型对话；纯辩论基线最差。问题二：A4 加一个专门检查安全的 agent 把 F1 拉高 8 到 35 个点——分工做「另一双眼睛」有效，但那双眼睛拿的是不同的任务，不是不同的人设。问题三：编排（选发言人、终止、插人）由代码持有；结构化群聊比松散两 agent 调用更少、零终止失败。

#### MetaGPT（arXiv:2308.00352，v1 2023-08-01，v7 2024-11-01；ICLR 2024）

**做了什么。** 把软件公司的标准作业程序（SOP）编成提示序列：产品经理、架构师、项目经理、工程师、QA 各出结构化文档（PRD、接口设计、任务表），走共享消息池加订阅；工程师写完代码要过「可执行反馈」——真跑一遍，按报错改。

**怎么测。** HumanEval、MBPP 的 Pass@1；自建 SoftwareDev（70 个软件任务）用可执行性（1 到 4 分人工打）、耗时、token、每行代码 token、人工修订次数比 ChatDev；角色消融；有无可执行反馈消融。

| 指标 | 数字 |
| --- | --- |
| HumanEval Pass@1 | GPT-4 直出 67.0；MetaGPT 无反馈 81.7；有反馈 85.9 |
| MBPP Pass@1 | MetaGPT 无反馈 82.3；有反馈 87.7 |
| SoftwareDev · 可执行性 | ChatDev 2.25；MetaGPT 无反馈 3.67；有反馈 3.75 |
| SoftwareDev · token | ChatDev 19,292；MetaGPT 24,613 / 31,255 |
| SoftwareDev · 每行代码 token | ChatDev 248.9；MetaGPT 126.5 / 124.3 |
| SoftwareDev · 人工修订次数 | ChatDev 2.5；MetaGPT 2.25 / 0.83 |
| 角色消融（两任务） | 只工程师：0.915 美元、10 次修订、可执行性 1.0；加产品经理：1.059、6.5、2.0；再加架构师：1.204、4.0、2.5；四角色：1.385、2.5、4.0 |

**局限。** SoftwareDev 是自建集、可执行性人工评分；没有等 token 的单 agent 对照（只和 ChatDev、GPT-4 直出比）；所有角色是同一个 GPT-4；反馈来自真执行，属外部工具而不是「另一个模型看一眼」。

**对三问。** 问题一：多角色确实多花 token（比 ChatDev 多六成），但每行代码 token 少一半、可运行性从 2.25 到 3.75——「省」要按产出算，不能只看总 token。问题二：可执行反馈单独贡献 4.2 与 5.4 个点，和整套角色分工同量级；结构化文档接力抑制级联幻觉。问题三：编排是代码里写死的 SOP 流水线，不是模型临场决定谁先谁后。

#### Magentic-One（arXiv:2411.04468，v1 2024-11-07）

**做了什么。** 一个编排者带四个工人（网页、文件、写代码、执行终端）。编排者维护两本账：任务账（已知事实、猜测、计划，外循环）和进度账（是否完成、是否在原地打转、下一步给谁，内循环）；有一个停滞计数器，超过阈值（实验里是 2）就跳出内循环重新规划。

**怎么测。** GAIA、AssistantBench、WebArena 三个通用助手基准；GAIA 验证集上做消融：把编排者换成 AutoGen 式「只选谁说话」的群聊（等于去掉两本账、计划、进度跟踪、循环检测），以及逐个拆掉工人。

| 指标 | 数字 |
| --- | --- |
| GAIA 测试集 | Magentic-One（GPT-4o + o1）38.00 ± 5.5；（仅 GPT-4o）32.33；裸 GPT-4 6.67；人 92.00 |
| AssistantBench 测试集 | 精确匹配 13.3，准确率 27.7（GPT-4o + o1） |
| WebArena 全部 812 任务 | 32.8（GPT-4o）；裸 GPT-4 14.9；人 78.2 |
| 消融 · 去掉两本账 | GAIA 验证集掉 31% |
| 消融 · 拆掉一个工人 | 掉 21%（写代码 / 执行终端）到 39%（文件） |

成本作者没正式测，只说「多数任务要几十次迭代与 LLM 调用，可能几美元、几十分钟一个任务」。安全一节记了反复登录被封号后试图重置密码、试图在社交媒体上找真人帮忙等事故。

**局限。** 和排行榜上的其他系统比，模型不同、预算不同；没有等预算的单 agent 基线；WebArena 没有隐藏测试集，作者承认用了验证集调流程。

**对三问。** 问题一：相对裸模型大幅提升，但账没算，作者自己把「成本高、延迟高」列为首要局限。问题二：不涉及评审，但进度账里「团队是否在循环」是一条由结构而非模型自觉给出的检查。问题三：这是「编排由代码持有」最直接的证据——把两本账与停滞计数器拿掉、只留模型临场选发言人，掉 31%。

#### Zhang 等，「If Multi-Agent Debate Is the Answer, What Is the Question?」（arXiv:2502.08788，v1 2025-02-12；v3 2025-06-21 改题为「Stop Overvaluing Multi-Agent Debate — We Must Rethink Evaluation and Embrace Model Heterogeneity」）

**做了什么。** 系统复核多 agent 辩论（MAD）：5 种方法（Society of Minds、Multi-Persona、Exchange of Thought、ChatEval、AgentVerse）× 9 个基准（MMLU、MMLU-Pro、CommonsenseQA、ARC-Challenge、AGIEval、GSM8K、MATH、HumanEval、MBPP）× 4 个模型（GPT-4o-mini、Claude-3.5-haiku、Llama3.1-70b、Llama3.1-8b），对照单次作答、CoT、自一致性（SC）；再提出 Heter-MAD——每次 agent 发言按概率从两个模型里抽一个。

**怎么测。** 把各 MAD 的轮数调到大致相同的调用预算（默认 6 次 LLM 调用），每个配置跑三遍，对 CoT 做 ANOVA 判胜 / 平 / 负；另做调 agent 数与轮数、token 曲线、逐题纠错与改错分析。

| 结论 | 数字 |
| --- | --- |
| MAD 对 CoT 的胜率 | 36 个配置里没有一种 MAD 胜率超过 20%；SoM、EoT、ChatEval、AgentVerse 约 15%，Multi-Persona 为 0 |
| GPT-4o-mini 上的样本行 | MMLU：CoT 80.73、SC 82.13、SoM 74.73、ChatEval 79.13、AgentVerse 80.40；GSM8K：CoT 93.60、SC 95.67、SoM 94.93；HumanEval：CoT 78.05、AgentVerse 85.57、SoM 68.09 |
| 加 agent、加轮数 | GPT-4o-mini 上 45 个条件中 34 个仍低于 CoT |
| token 曲线 | SC 随预算稳定上升；MAD 要么不涨，要么同 token 下仍低于 SC |
| Heter-MAD（GPT-4o-mini + Llama3.1-70b 各半） | Heter-SoM 比两模型各自跑 SoM 的平均高 6.4%，Heter-EoT 高 8.2%；所有 Heter-MAD 高于两模型 CoT 平均，最多高 5.8%；对 ChatEval、AgentVerse 增益较小 |

逐题分析给出一条机制：Multi-Persona、ChatEval、AgentVerse 能纠很多错，但也把很多本来对的答案改错；SoM、EoT 保守，改错少、纠错也少。

**局限。** 预算固定在 6 次调用，模型偏小偏便宜；异构只试了两模型组合；对照是「两模型 CoT 平均」，没有和「两模型各自 CoT 后投票」这种最便宜的异构基线比——这是我们的补充，不是论文的。

**对三问。** 问题一：等调用数下 MAD 通常不敌 CoT，更不敌 SC；多花 token 不换来稳定提升。问题二：异构模型是唯一稳定有效的改动；同一模型换人设（Multi-Persona）是最差的一种。问题三：加人、加轮救不了；「激进改答」与「保守不改」是一对冲突，没有免费的中间点。

#### Wu 等，「Can LLM Agents Really Debate?」（arXiv:2511.07784，v1 2025-11-11）

**做了什么。** 用骑士—无赖—间谍逻辑谜题做受控实验：1,800 题（4 到 9 人局各 300 题），六种模型（gpt-5-nano、gpt-5-mini、gemini-2.5-flash、gemini-2.5-flash-lite、qwen-turbo、qwen-flash），默认三 agent 一队；操纵六个因子：队伍规模（3 到 4）、队伍构成（同构 / 异构）、是否可见彼此置信度、发言顺序、辩论深度（一轮到两轮）、题目难度。另做逐轮状态转移分析。

| 结论 | 数字 |
| --- | --- |
| 辩论前后（题级准确率） | 4 人局 17.33% → 69.33%；6 人局 6.00% → 46.67%；8 人局 3.33% → 36.00% |
| 辩论前后（agent 级准确率） | 4 人局 35.33% → 77.11%；6 人局 27.11% → 55.56%；8 人局 22.66% → 44.89% |
| 起点在错误多数里，最终能纠正的比例 | gemini-2.5-flash 34.4%，gpt-5-mini 30.0%，gemini-2.5-flash-lite 3.6% |
| 起点在正确多数里 | 各模型 97% 以上保持或转为正确 |
| 因子 | agent 数正向显著（系数 0.066）；置信度可见、顺序、深度均不显著；强模型同构队优于弱模型同构队；强模型异构队最高 |
| 状态转移 | 「错误多数 → 正确」的转移最少见，但对最终准确率的正系数最大 |

预算约 500 美元，未分项报 token。

**局限。** 没有等预算的单 agent 或多数投票基线——起点准确率是每个 agent 单次作答，所以不知道提升里多少来自「多抽了几次样」；单一任务族；作者自己列了任务窄、模型窄、协议窄。

**对三问。** 问题一：辩论把准确率拉起来了，但没有 SC 对照，无法归因。问题二：起决定作用的是各成员本身的推理强度与队伍多样性，结构参数（顺序、置信度、深度）几乎不起作用；弱模型在错误多数面前只有 3.6% 能翻盘。问题三：多数压力压制独立思考——这直接支持「先各自独立作答，再汇总」。

### 补查：辩论、自一致性与自我纠错

**Du 等，多 agent 辩论原文（arXiv:2305.14325，v1 2023-05-23；ICML 2024）。** 三个同模型实例、两轮辩论。表 1：算术 单 agent 67.0、单 agent 反思 72.1、多 agent 多数投票 69.0、多 agent 辩论 81.8；GSM8K 77.0 / 75.0 / 81.0 / 85.0；国际象棋走法 91.4 / 102.1 / 102.2 / 122.9。表 2：传记事实性 66.0 / 68.3 / 73.8，MMLU 63.9 / 57.7 / 71.1，走法合法性 29.3 / 38.8 / 45.2。异构小试：20 道 GSM8K，Bard 解 11、chatGPT 解 14、两者辩论解 17。作者明说「辩论更贵，要多实例多轮」。局限：多数投票基线只用 3 个样本，辩论用了 3 × 2 次生成，不是等预算；后来 Huang、Zhang、Choi 用等调用数的 SC 复核，优势消失。

**Liang 等，「Encouraging Divergent Thinking」（arXiv:2305.19118，v1 2023-05-30；EMNLP 2024）。** 提出「思维退化」：模型一旦对答案有信心，自我反思就不再产生新想法；用两个辩手加一个裁判的对抗式辩论应对。作者提醒不同模型当裁判会有偏。

**Huang 等，「Large Language Models Cannot Self-Correct Reasoning Yet」（arXiv:2310.01798，v1 2023-10-03，v2 2024-03-14；ICLR 2024）。** 没有外部反馈的「内在自我纠错」会变差：GPT-3.5 在 CommonsenseQA 从 75.8 掉到 38.1（一轮）、41.8（两轮）；GPT-4 在 GSM8K 从 95.5 掉到 91.5、89.0。等调用数比较（GSM8K）：单次 76.7；SC 3 个样本 82.5；多 agent 辩论一轮共 6 次生成 83.2；SC 6 个样本 85.3——作者据此说辩论不过是自一致性的一种形式。

**Wang 等，自一致性（arXiv:2203.11171，v4 2023-03-07；ICLR 2023）。** 多抽样多条推理路径后投票：GSM8K +17.9，SVAMP +11.0，AQuA +12.2，StrategyQA +6.4，ARC-challenge +3.9。这是所有「等预算」比较的默认基线。

**Smit 等，「Should we be going MAD?」（arXiv:2311.17371，v3 2024-07-18）。** 医学问答上 MAD 不能稳定胜过自一致性和集成；MAD 对超参数更敏感；调节 agent 之间「同意的倾向」是主要杠杆。

**Choi 等，「Debate or Vote」（arXiv:2508.17536，v1 2025-08-24）。** 把辩论拆成「多数投票」加「互相看答案后更新」。理论上证明去中心化辩论是鞅：下一轮的期望信念等于本轮，平均而言不进不退。Qwen2.5-7B、5 个 agent：算术 单 0.814、辩论 0.760、多数投票 0.990；GSM8K 0.871 / 0.887 / 0.940；MMLU 形式逻辑 0.491 / 0.556 / 0.540。结论：多数投票拿走了通常归功于辩论的绝大部分增益。在 32B 与异构配置上结论一致。

**Zhu 等，「Demystifying Multi-Agent Debate」（arXiv:2601.19921，v3 2026-06-03）。** 同模型 5 agent 5 轮：Qwen-2.5-7B 在 GSM8K 单模型 0.908、原味辩论 0.847、多数投票 0.908；只有加上「初始答案多样化」与「校准过的置信度」才到 0.932。理论：置信度与正确性正相关时信念过程成为严格下鞅，期望才会往对的方向走。局限：只做同构，未算 token。

**Bertalanič 与 Fortuna，「The Cost of Consensus」（arXiv:2605.00914，v1 2026-04-29）。** 10 个同模型 agent 三轮辩论，对照「各自独立自我纠错后汇总」。Qwen2.5-7B：GSM-Hard 辩论 58.8% vs 独立 61.0%，token 18,240 vs 5,396；MMLU-Hard 60.7% vs 66.7%，17,401 vs 6,170；Ministral-3-8B 在 GSM-Hard 20.7% vs 48.3%。辩论 token 是独立的 2.1 到 3.4 倍，准确率持平或更差；「从众率」（放弃自己推理采纳多数）最高 85.5%；「预言者差距」（池子里有对的答案却被共识扔掉）最高 32.3 个点。附录 L 异构队：8 个条件里 6 个负协同，Qwen+Llama 在 GSM-Hard 33.7% 比最好的同构成员 58.8% 低 25.1 个点；唯一正例是 Llama+Ministral 在 GSM-Hard 62.0%（各自同构 39.3% 与 20.7%）；异构队从众率 64.6% 到 85.0%，与同构相当。局限：7 到 8B 小模型，单一提示模板；32B 初步结果从众率反而 95.4%。

### 补查：多样性来自哪里

**ChatEval（arXiv:2308.07201，v1 2023-08-14）。** 多 agent 评审团评文本，FairEval 与人一致的准确率：ChatGPT 单 agent 53.8%、多 agent 60.0%；GPT-4 61.3% → 63.8%；人类标注者 68.8% 到 76.3%。表 3 是关键：把多 agent 的角色提示改成同一份，准确率 53.8%、与单 agent一样——同一模型换名字不换视角，等于没多一个人。只做同构模型；后来 Zhang 2025 显示 ChatEval 在推理基准上并不优于 CoT。

**Verga 等，「Replacing Judges with Juries」（arXiv:2404.18796，v2 2024-05-01）。** 用多个来自不同模型家族的小模型组成评审团，六个数据集上与人的相关性高于单个 GPT-4 裁判，成本低七倍以上，并因家族互不重叠而减少「同族偏好」。

**Wang 等，Mixture-of-Agents（arXiv:2406.04692，v1 2024-06-07）。** 多层异构开源模型互相参考上一层输出，AlpacaEval 2.0 65.1% 对 GPT-4o 57.5%。生成类任务的异构证据；未做等预算对照。

**Yang 等，「Understanding Agent Scaling via Diversity」（arXiv:2602.03794，v1 2026-02-03）。** 信息论框架：性能上界由「有效独立信道数」决定，同模型多抽样输出高度相关、收益快速饱和。四个层级：无多样性、只换人设、只换模型、两者都换。ARC 上 4 个 agent 投票：只换人设 84.9%，只换模型 88.1%；两者都换的 2 个 agent 超过无多样性的 16 个 agent。

**Pappu 等，「Multi-Agent Teams Hold Experts Back」（arXiv:2602.01011，v4 2026-05-28；ICML 2026）。** 自组织团队里有专家，团队成绩却稳定低于专家单干，最多差 41.1%；机制是「整合式妥协」——把专家和非专家的意见平均掉；团队越大越严重；同样的从众倾向提高了对捣乱 agent 的鲁棒性。

### 补查：编排、规模与 token 账

**Kim 等，「Towards a Science of Scaling Agent Systems」（arXiv:2512.08296，v1 2025-12-09，v3 2026-04-08）。** 260 个配置：六个基准（BrowseComp-Plus、Finance-Agent、PlanCraft、Workbench、SWE-bench Verified、Terminal-Bench）× 五种架构（单 agent；独立、中心化、去中心化、混合四种多 agent）× 三家模型（GPT-5 系列、Gemini 2.x、Claude Sonnet 3.7 / 4 / 4.5），统一工具、提示与总迭代预算。token 开销相对单 agent：独立 +58%，去中心化 +263%，中心化 +285%，混合 +515%。错误放大：独立 17.2 倍，中心化 4.4 倍。可拆分的金融推理中心化 +80.8%；顺序规划 PlanCraft 所有多 agent 都变差（中心化 −50.3%，独立 −70.0%）。SWE-bench Verified：单 agent 均值 0.522，多 agent 全部略降（混合 −2.1%、中心化 −3.1%、去中心化 −5.4%、独立 −14.9%）。「基线悖论」：单 agent 已过 45% 的任务，加人是负收益；固定预算下超过 3 到 4 个 agent 每人剩的推理容量就太薄。框架对 87% 留出配置选对了架构。

**Cemri 等，「Why Do Multi-Agent LLM Systems Fail?」（arXiv:2503.13657，v3 2025-10-26）。** 标注 1,642 条轨迹、7 个框架、14 种失败模式（标注者一致性 kappa 0.88）：系统设计问题 43.9%，agent 间错位 31.35%，任务验证 24.75%。最常见单项：步骤重复 15.7%、违背任务规格 11.8%、错误验证 9.1%、缺失或不完整验证 8.2%、任务偏航 7.4%、过早终止 6.2%。对 ChatDev 加高层验证步骤，成功率 +15.6%。作者的话：只靠末端、低层的检查不够，要多层验证。

**Xia 等，Agentless（arXiv:2407.01489，v2 2024-10-29）。** 不要 agent 循环，三步（定位、修补、验证）流水线：SWE-bench Lite 32.00%，每题 0.70 美元，当时超过所有开源 agent。

**Gao 等，「Single-agent or Multi-agent Systems? Why Not Both?」（arXiv:2505.18286，v1 2025-05-23）。** 模型越强，多 agent 相对单 agent 的优势越小；提出先单 agent、失败再升级到多 agent 的级联，准确率 +1.1 到 12%，成本最多降 20%。

**Kumar 等，AgentForge（arXiv:2604.13120，v1 2026-04-13）。** 规划、写码、测试、调试、评审五角色，每次改动必须先过沙箱执行：SWE-bench Lite 40.0%，比单 agent 基线高 26 到 28 个点；消融说执行反馈与角色拆分各自有贡献。成本倍数摘要未给，未核。

**Lin 等，「Stop Wasting Your Tokens」（arXiv:2510.26585，v2 2026-03-02；ICLR 2026）。** 在多 agent 运行时外挂一个不用 LLM 的监督过滤器纠错、止损，GAIA 上 Smolagent 的 token 降 29.68%，成功率不降。

**Chen 等，「Are More LLM Calls All You Need?」（arXiv:2403.02419，v2 2024-06-04）。** 投票类复合系统的性能随调用数先升后降：多调用帮简单题、害难题，混合难度下出现非单调。

**Anthropic 工程博客，「How we built our multi-agent research system」（2025-06-13）。** Opus 4 领队加 Sonnet 4 子 agent，在内部研究评测上比单个 Opus 4 高 90.2%；单 agent 用 token 约为聊天的 4 倍，多 agent 约 15 倍；BrowseComp 上 token 用量解释约 80% 的性能方差；作者明说多 agent 不适合需要共享同一上下文、依赖紧密的任务，「大多数编码任务」在此列。灰色文献，无同行评审。

### 补查：评审者与裁判的偏差

**Zheng 等，MT-Bench（arXiv:2306.05685，v4 2023-12-24；NeurIPS 2023）。** GPT-4 与人的一致率 85%，人与人 82%。位置偏差：交换两个答案顺序后仍给同一判决的比例，GPT-4 65.0%、GPT-3.5 46.2%、Claude-v1 23.8%。冗长偏差：把答案改成重复列表后被骗的比例，GPT-4 8.7%，GPT-3.5 与 Claude-v1 91.3%。自我增强：GPT-4 给自己的胜率高 10%，Claude-v1 高 25%。

**Wang 等，「LLMs are not Fair Evaluators」（arXiv:2305.17926，v2 2023-08-30）。** 只改出场顺序，Vicuna-13B 就能在 80 题里「赢」ChatGPT 66 题。补救：多次给证据再打分、交换顺序取平均、难题交人。

**Panickssery 等（arXiv:2404.13076，v1 2024-04-15）。** GPT-4、Llama 2 不经微调就能以非平凡准确率认出自己的产出；微调实验显示自我识别能力与自我偏好强度线性相关。

**Wataoka 等（arXiv:2410.21819，v2 2025-06-21）。** GPT-4 有显著自我偏好；解释是困惑度——模型偏爱「读起来像自己」的低困惑度文本，不论作者是谁。

**Chen 等，「Do LLM Evaluators Prefer Themselves for a Reason?」（arXiv:2504.03846，v3 2025-12-12）。** 用数学、事实、代码生成这类可判对错的任务拆分：强模型偏爱自己的很大一部分是「自己确实更对」；但当评审者自己作为生成者出错时，强模型的有害自我偏好更重——认不出自己的错；评审前先长链推理能显著减轻。

**Pombal 等，「Self-Preference Bias in Rubric-Based Evaluation」（arXiv:2604.06996，v3 2026-08-03）。** 即使用 IFEval 这种程序可验证的客观条目，模型给自己没做到的条目打「满足」的概率比给别人高 50% 以上；主观评测上分数最多被抬 10 个点；多个裁判合评能减轻但不能消除。

**Chae 等，「Self- and Other-Labels Induce Bidirectional Bias」（arXiv:2608.18091，v1 2026-06-06）。** 三个商用裁判：盲评并控制质量后自我偏好在四个维度里三个消失、一个反转；但只要贴上「这是某某模型写的」标签，分数就双向漂移。作者身份标签本身是一条独立的偏差通道。

**Zhao 等，「Bias in the Loop」（arXiv:2604.16790，v1 2026-04-18）。** 软件工程任务（代码生成、修复、测试生成）上 LLM 裁判对提示里的呈现线索高度敏感，代码不变判决变，足以改变任务级结论和模型排名。

**Sharma 等，迎合（arXiv:2310.13548，v4 2025-05-10；ICLR 2024）。** 五个前沿助手在四类任务上都迎合用户；人类偏好数据和偏好模型都在不小比例上更喜欢写得漂亮的迎合答案而非正确答案——偏差有训练来源，不是提示能改掉的。

**Khan 等，「Debating with More Persuasive LLMs」（arXiv:2402.06782，v4 2024-07-25；ICML 2024）。** 两个强模型辩手对抗、弱裁判判：LLM 裁判准确率从朴素的 48% 到 76%，人类裁判从 60% 到 88%；辩手越会说服，裁判反而越准。**Kenton 等，「Scalable oversight with weak LLMs judging strong LLMs」（arXiv:2407.04622，v2 2024-07-12）。** 辩论稳定优于「单顾问」，但相对直接问答只在信息不对称的抽取式问答上占优，其他任务结果混杂。这两篇是「对抗式辩论帮裁判」的证据，注意它的结构是两方对抗加第三方裁决，不是同伴互看后趋同。

### 补查：2025 到 2026 年的代码评审实证

**Pereira 等，CR-Bench（arXiv:2603.11078，v1 2026-03-10）。** 把真实缺陷做成带完整 PR 上下文的代码评审基准；用两个前沿模型的单次评审与 Reflexion 式评审做初步实验，发现一旦要求「找出全部隐藏问题」，评审 agent 信噪比很低——找到的问题和误报一起涨。没有多模型或多评审员对照。

**Zhong 等，「Human-AI Synergy in Agentic Code Review」（arXiv:2603.15911，v1 2026-03-16）。** 300 个开源项目、278,790 条评审对话：AI 评审建议被采纳的比例显著低于人类评审；未采纳的 AI 建议中过半要么不对、要么开发者用别的方式修了；人评审 AI 写的代码要多 11.8% 的来回；被采纳的 AI 建议让代码复杂度与体积涨得更多。未指明模型，不比多模型。

**Sun 等，「Ensembling LLMs for Code Vulnerability Detection」（arXiv:2509.12629，v2 2025-09-18）。** 五个代码模型（DeepSeek-Coder-6.7B、CodeLlama-7B / 13B、CodeQwen1.5-7B、StarCoder2-15B）在 Devign、ReVeal、BigVul 上做 bagging、boosting、stacking 与门控 stacking：集成显著优于单模型，类别不平衡时 boosting 最好。这是「多模型对检测类任务有增益」的证据，但是分类器集成，不是 agent 对话。

## 跨篇归纳

### 问题一：同等预算下多 agent 是否胜出

**论文明说的。**

- 做了等调用数或等 token 对照的 6 篇（Huang、Smit、Zhang、Choi、Zhu、Bertalanič），结论一致：同模型 agent 互看发言的辩论不敌自一致性或独立多数投票。Zhang：36 个配置无一 MAD 对 CoT 胜率过 20%，同 token 下低于 SC；Huang：GSM8K 上辩论 6 次生成 83.2 低于 SC 6 样本 85.3；Choi：多数投票拿走绝大部分增益；Bertalanič：辩论 token 是独立自纠的 2.1 到 3.4 倍而准确率持平或更差。
- 做了预算匹配的架构级比较只有 1 篇（Kim，260 配置）：多 agent 比单 agent 多花 58% 到 515% 的 token；可拆分任务最多 +80.8%，顺序推理任务最多 −70%；SWE-bench Verified 上四种多 agent 都比单 agent 差 2 到 15 个点。
- 报告了大幅正收益的 4 篇框架论文（CAMEL、AutoGen、MetaGPT、Magentic-One）都没有等预算对照；其中收益来源可分离出来的部分，都指向工具（代码执行、grounding、可执行反馈、专责安全检查）与由代码持有的编排，而不是多个模型互相说话——AutoGen 自己那张表里纯辩论垫底。

**我们的推断。** 「多 agent 有效」在文献里其实是三件事叠在一起：多抽样（自一致性能拿到）、分工接工具（单 agent 加工具也能拿到大半）、异构模型互补（这是多 agent 独有的）。把前两件扣掉，纯粹由「多个 agent 对话」带来的增益在等预算下接近零甚至为负。「会不会只是烧 token」：同模型互看发言的辩论，是；独立作答后汇总，不是——它的 token 是 N × 1 而不是 N × R，且效果不差。

### 问题二：多 agent 是否提升了评审或验证，靠的是什么

**论文明说的。**

- **异构模型有效**：Zhang（Heter-SoM +6.4%、Heter-EoT +8.2%）、Yang（换模型 88.1% 对换人设 84.9%；2 个异构胜 16 个同构）、Verga（异族评审团胜单个 GPT-4 且便宜七倍）、Du（chatGPT 加 Bard 20 题解 17，各自 14 与 11）、Wu（强模型异构队最高）。5 篇正向。
- **异构有前提**：Bertalanič 附录 L 在 7 到 8B 小模型上 8 个条件 6 个负协同（弱成员把强成员拉下来，从众率不降）；Pappu 团队稳定低于专家单干最多 41.1%。2 篇反向，共同点是成员强弱悬殊且允许互看、趋同。
- **同模型多人设**：Zhang 里 Multi-Persona 是最差的方法（对 CoT 胜率 0）；ChatEval 表 3 同一角色提示得 53.8%、与单 agent 一样，换成不同角色提示才到 60.0%；Yang 里只换人设有非零增益但明显小于换模型；Smit 说 Multi-Persona 对超参数最敏感。
- **流程结构**：独立投票稳定不差于互看（Choi、Zhu、Bertalanič）；互看带来从众（Bertalanič 85.5%、Wu 弱模型 3.6% 翻盘率、Pappu 整合式妥协）；对抗式辩论加第三方裁决能帮弱裁判（Khan 48% → 76%、Kenton），但那是「两方各为一个答案辩护、裁判不参与」的结构。
- **外部验证**：MetaGPT 可执行反馈 +4.2 / +5.4 个点；AutoGen grounding agent +15%；Huang 无外部反馈的自纠只会变差；Cemri 里验证类失败占 24.75%，加高层验证 +15.6%。

**我们的推断。** 评审的增益排序是：外部可核证据 > 异构模型独立投票 > 同模型不同分工（读不同证据、跑不同检查） > 同模型不同人设 ≈ 零。「同一个模型换个名字给自己投票」——ChatEval 那一行是最直接的答案：没用；再叠上自我偏好，是负的。

### 问题三：什么结构让它有效、什么结构让它失效

**论文明说的。**

- **编排由代码持有**：Magentic-One 去掉两本账掉 31%；Kim 中心化把错误放大压到 4.4 倍、独立放任是 17.2 倍；AutoGen 结构化群聊零终止失败、调用更少；MetaGPT 的 SOP 流水线；Cemri 最常见失败是步骤重复 15.7%——那是没有外部进度账的症状。
- **验证靠外部工具**：Huang、MetaGPT、AutoGen、Cemri，见上。靠「另一个模型看一眼」的验证，Zhang 的逐题分析给了代价：能纠错的方法同时大量改错。
- **轮次上限**：Huang 两轮自纠越纠越差；Zhang 加轮加人 45 个条件 34 个仍不如 CoT；Wu 一轮到两轮不显著；Choi 的鞅结论是「平均不进不退」；Chen 调用数过多性能回落；Magentic-One 停滞计数器阈值 2；CAMEL 40 条消息硬上限并说明为什么必须有。
- **信息隔离**：Wu 多数压力压制独立思考；Bertalanič 池里有对的答案却被共识扔掉最多 32.3 个点；Zhu 只有初始答案多样时辩论才有用；Zheng 与 Wang 的位置偏差、Chae 的作者标签偏差说明连「谁先说、谁写的」都要藏。
- **规模**：Kim 固定预算下超过 3 到 4 个 agent 就太薄；Yang 2 个异构胜 16 个同构；Wu 第四个 agent 收益小但显著；Pappu 团队越大妥协越重。

**我们的推断。** 有效结构可以写成一句：各席位拿同一份冻结的包、看不到彼此、独立给出带外部证据的裁决，由代码按声明的票数汇总，返工有硬上限。失效结构也是一句：同一个模型的几个副本在一个聊天里互相看着说，谁先说谁带节奏，轮数不封顶。

### 四个具体追问

- **同等 token 预算下多 agent 是否胜出？** 同模型辩论：不胜出（6 篇等预算复核一致）。异构独立汇总：胜出，幅度 3 到 8 个点级（Zhang、Yang）。带工具分工的编排：任务可拆分时大胜、顺序任务倒退（Kim）；软件工程基准上目前是略负（Kim 的 SWE-bench Verified −2 到 −15%）。
- **异构与同构多模板哪个有效？** 异构。同构多模板单独使用时接近无效（ChatEval 同角色 53.8 = 单 agent；Zhang 里 Multi-Persona 最差），只有当「模板」意味着不同任务、不同证据来源时才有增益（AutoGen 安全审查 agent、MetaGPT 角色）。
- **独立投票与看彼此发言哪个更准？** 独立投票不差于看彼此、常常更准且便宜两到三倍（Choi、Zhu、Bertalanič）；例外是 Du 2023 的原始报告（辩论 81.8 对多数投票 69.0），但它的两种设置调用数不等。看彼此的唯一被证明的正面形态是对抗式辩护加第三方裁决（Khan、Kenton）。
- **评审模型的自我偏好有多大？** 主观比较：GPT-4 给自己胜率高 10%，Claude-v1 高 25%（Zheng）。客观条目：给自己没做到的条目打「满足」的概率高 50% 以上（Pombal）。机制上一半是「自己确实更对」（Chen 2025），有害的那一半集中在「认不出自己的错」，而且模型越强越重。盲评加控制质量可以消掉大部分（Chae），但作者标签本身会重新引入偏差。

### 另一份独立解读的总判断怎么看

所有者转来另一个 harness（Codex + GPT-5.6）对同六篇的解读，总判断是：真正起作用的是「误差不相关性 × 分工 × 外部验证 × 由代码持有的编排 × 算力效率」，而不是 agent 个数或人设多样性；好的辩论系统应是「错误共识破坏器」而非「共识机器」；默认单强 agent、只在高不确定或验证失败时升级到异构核验。逐条核实见下一节；这里说我们对总判断的态度。

- 五个因子里，误差不相关性（Zhang、Yang、Verga）、外部验证（MetaGPT、Huang、Cemri）、代码持有的编排（Magentic-One、Kim）、算力效率作为约束（Zhang、Kim）四项有多篇支持，成立。「分工」成立但要加一句：文献里分工的增益几乎都是分工接了不同工具或不同证据，不是分了不同头衔。
- 「不是 agent 个数」说过头了一点：Wu 与 Du 都测到 agent 数正向显著，只是收益小、有上限（Kim 3 到 4 个、Chen 非单调、Pappu 越大越妥协）。准确的说法是「个数不是主因，且很快饱和」。
- 「不是人设多样性」也过头：ChatEval 表 3 恰恰证明同一模型必须给不同角色提示才有增益，Yang 也测到非零增益；准确的说法是「人设多样性弱于模型多样性，单独不够」。
- 「错误共识破坏器」与 Wu（错误多数 → 正确的转移系数最大）、Zhu（置信度打破鞅对称）相符。我们的补充：独立投票加外部证据不用辩论就能拿到同样的效果，且不付 N × R 的 token。
- 「默认单强 agent、失败再升级」与 Gao 的级联、Kim 的基线悖论、Anthropic 对编码任务的自述相符，对**施工**成立。对**评审**要改一个字：默认应是一个**异构**席位而不是一个「强」席位——同族模型审自己家的产出，自我偏好是文献里测得最稳的偏差之一。

## 对 HCTL2 的含义

落到机制，每条标出依据和推断边界。

1. **Gate 席位的多样性策略该怎么声明。** 建议施工图里席位策略有三档，默认取第一档：（a）**模型谱系互异**——两个必需席位不得来自同一模型家族；（b）**同模型、不同方法论 Skill**——只有当两份 Skill 读不同证据、跑不同检查（一个跑测试与 diff、一个查约束漂移与契约一致）时才算两票；（c）**同模型、同 Skill、不同人设**——不计为独立票，只能作候补。依据：Zhang 表 4、Yang 表 1、Verga 是 (a) 的正向证据；ChatEval 表 3、Zhang 里 Multi-Persona 是 (c) 无效的证据；AutoGen A4、MetaGPT 表 3 是 (b) 有条件有效的证据。附加一条策略字段：**作者模型谱系回避**——被评对象由哪个模型家族写的，必需席位不用同家族（Zheng 自我增强 10% 到 25%、Pombal 50% 以上、Chen 2025 强模型认不出自己的错）。这条是现有「作者不占必需评审席位」的自然延长，从身份回避延到谱系回避。
2. **法定票数与分歧处理。** 票数由施工图声明；文献没有任何关于评审关卡法定票数（一票、两票一致、三票多数）的直接实验，本文不给缺省值——所有者已裁决不写「三选二」这类具体配置。文献能支持的只有一条否定式规则：席位之间的分歧**不靠评审员再商量一轮**来解决，那正是辩论失效的形状；分歧走既有路径——落点在实现，作者拿着裁决返工出新版本重新过关卡；落点在契约，标需要关注升到人。可参考的饱和数据：Yang 2 个异构胜 16 个同构；Kim 固定预算下 3 到 4 个 agent 是上限；Wu 第四个 agent 收益小；Pappu 团队越大越平均化。「两票一致才过」是我们的推断，文献没直接测过法定票数。
3. **席位之间要信息隔离。** 评审席位投票前看不到其他席位的裁决，也看不到作者身份与模型名；同一轮的票由归约器一次汇总。依据：Choi、Zhu、Bertalanič（独立不差于互看且便宜 2 到 3 倍）；Wu、Pappu（多数压力）；Zheng、Wang（位置偏差，谁先说影响判决）；Chae（作者标签双向偏差）。现有设计已写「席位互相隔离、各投各的票、不被先发言者带走」，文献支持把它从原则变成可核的约束：包里不含其他席位产物、不含作者标识。「对抗核验」作为第二阶段保留：第一阶段独立票不一致时，可以启用一次 Khan / Kenton 式的对抗——但裁决方是人或归约规则，不是再叫一个模型看两边发言后表态。
4. **返工轮数上限的文献依据。** 默认两轮：第二轮返工仍不过，按票数不可达处理、把 Task 标需要关注。依据：Huang 两轮自纠越纠越差；Magentic-One 停滞阈值 2；Zhang 加轮救不了；Wu 一到两轮不显著；Choi 鞅——平均不进不退；CAMEL 说明没有硬上限的后果是「上千次调用几百美元」。「两轮」这个具体数字是从 Magentic-One 与 Huang 借的，不是评审场景实测。现有「席位可按策略只看与上一版的差异」有 Cemri 步骤重复 15.7% 作为反面依据。
5. **快与省的账怎么算。** 「省」按票算：每票 token = 读包一次 + 写裁决一次；独立投票的总 token 是席位数 × 单票，辩论是席位数 × 轮数 × 单票——独立投票在结构上就省两到三倍（Bertalanič 2.1 到 3.4 倍）。「好」按证据分级算：模型转述的裁决不计入「好」，至少要适配器结构化上报或工具箱回读（Huang、MetaGPT、Cemri：没有外部反馈的验证不可靠）。「快」按轮算：两票一致一次过，不一致直接升人，不加第三轮商量。建议凭证里记每票 token 与证据等级，让「省了什么」可核。另注：多 agent 编排在软件工程基准上目前不省也不好（Kim 的 SWE-bench Verified 略负、Anthropic 自述编码不适合），所以 HCTL2 的多席位只用在评审关卡，施工仍是单执行体——这与现有设计一致。
6. **专业化 Participant「同模型不同方法论 Skill」有没有文献支持。** 部分支持，且条件明确。有支持的部分：不同角色提示比同一提示有效（ChatEval 表 3）、分工到不同检查有效（AutoGen A4 安全审查、MetaGPT 角色消融）、人设多样性有非零增益（Yang）。不支持的部分：同模型多人设作为「多票」在等预算下最差（Zhang 的 Multi-Persona）；异构模型比换提示更有效（Yang 88.1 对 84.9）。所以「方法论 Skill」要想作为独立票，得满足上文第 1 条 (b) 的条件——差异在证据与检查步骤，不在语气与头衔。文献完全没测过的是设计文档给方法论 Skill 的三个卖点（可复现、可升级、可审计）——那是账本与版本化带来的工程性质，不是准确率性质，属于「未查到」而不是「被否定」。

## 未查到与边界

- **没有找到**把「多个不同模型评审同一份代码 diff」与「单模型评审」在同一基准、同等 token 下对照的 2025 到 2026 年实证。CR-Bench 只用两个前沿模型分别跑、未做组合；Zhong 等是观察性研究不比模型；Sun 等是漏洞检测分类器集成。所以本文对 Gate 席位异构的建议，证据来自推理与问答基准（Zhang、Yang、Verga）外推，不是代码评审直测。
- **没有找到**「同模型 + 不同方法论 Skill」这种精确配置的对照实验；最接近的是 ChatEval 的角色提示消融与 AutoGen 的专责 agent，两者都不是版本化方法论。
- **没有找到**评审关卡法定票数（一票 / 两票一致 / 三票多数）的直接实验；第 2 条建议是从 agent 数饱和曲线推的。
- **没有核到**：AgentForge 相对单 agent 的成本倍数（检索摘要提到约 2.7 倍，论文摘要页未给）；Lin 等一文之外流传的「多 agent 输入 token 是单 agent 4 到 220 倍」这一数字的原始出处。两者未写入正文数字。
- 等预算复核类论文用的多是 7B 到 70B 模型与选择题式基准；Bertalanič 的 32B 初步结果从众率反而更高，Kim 用了 GPT-5 / Gemini 2.5 / Claude Sonnet 4.5 且结论方向一致，但前沿模型上「辩论无用」的证据仍比小模型上薄。
- Anthropic 博客是灰色文献，其 90.2% 是内部评测、任务是研究检索不是编码，只用于 token 倍数的量级参考。
- 本文不判定任何框架的采用与否；按复用决策用语，全部为**仅参考行为**。
