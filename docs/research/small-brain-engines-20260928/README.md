这份目录配 [`../small-brain-engines-20260928.md`](../small-brain-engines-20260928.md)。这里只有已经公开的消息流和待填的判断点。模型还没有跑，所以没有原始输出。

## 消息流

`streams/*.jsonl` 每行一条消息：`id`、`speaker`、`time`、`body`。PR 讨论里 GitHub 登录名多数是 `yesme`，说话方按评论标题里的席位记（Fable、Grok、Codex、GLM、Muse、K3、作者、所有者）。两条 `.memo/log/` 按原文的说话人切开。

来源只有本仓库已公开的内容：`.memo/log/` 两篇，以及 PR #246、#257、#259、#262、#271、#276、#277、#278、#279、#282、#284、#285、#287、#288 的正文和议题评论。任务书点名的五条 PR 都在里面。没有用未入库的聊天。

## 判断点

| 文件 | 数量 | 问什么 |
| --- | --- | --- |
| `points/a.jsonl` | 100 | 到 `after_message` 为止，该不该提示开新 Topic |
| `points/b.jsonl` | 20 | 点名之前、对方上次开口之后的每条消息，和这次点名相关吗 |
| `points/c.jsonl` | 6 | 开新话题之前的每条消息，归进五节中的哪一节，或不选 |

A 的上下文至少两条消息。100 个点是从 16 条消息流里轮流取的，避免一条 PR 占满。B 的公开讨论几乎不用 `@login` 点人（扫过这些评论，参与者 @ 只有个别，`@loader_path` 这种链接器记号不算）。所以 B 记的是评论前几行点到另一席位名字、并且该席位在同一条流里已经说过话的位置，`address_kind` 为「点名」。缺口大多只有一到四条，因为这些评审是紧挨着回的。C 的六次开题各自写了为什么算转到新话题。

## 标注

Fable 已在 `fbce0ee` 填完 `labels/`。没有空项。这套题有三个硬限制，不能拿去算准确率：A 只有 2 条该提示；B 的 33 条消息全部相关；C 的六次开题里四次是评审阶段切换，不是真换话题。说明见对照文件「标注结果，以及这套题为什么不能开跑」。

当初的填法是：改 `labels/`，不要改 `points/` 和 `streams/`。

- A：`label` 填 `true` 或 `false`。`true` 表示这里该提示。`note` 可空。
- B：`label_by_message` 的每个 id 填 `relevant` 或 `irrelevant`。
- C：每个 id 填 `缘起与目标`、`已定事实与决定的理由`、`分歧与待答问题`、`所需约束与材料`、`来源清单` 或 `不选`。一条消息只选一节。

这套标注不拿去跑模型。若以后换了能打分的样本，原始输出再放进 `outputs/`，并在对照文件写命令、版本和硬件。测量脚本不入库。
