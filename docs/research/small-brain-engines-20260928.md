# Room 里三件轻量活：用什么引擎

> 状态：调研 · 2026-09-28。样本已整理，标注未到，模型准确率未跑<br>
> 类别：④ Context 管理 · 证据编号：E-SMALL-BRAIN<br>
> 上级：任务书 `.memo/design/p2-control-20260906/06-small-brain-engine-research.md`。设计位置是 `spec/project.md` §根 Context Manifest 与 §Room 与消息，以及体验文档里的持续建议。本文不改那些规矩

三件活都是控制面自己做的，不交给 Room 里的参与者。small-brain 指用户配给控制面的一个专用小模型。没配的时候走机械规则。本文回答各用什么，以及现在还不能打开什么。

样本、待填标注和语料说明在 [同名目录](./small-brain-engines-20260928/README.md)。单案在 [models/](./models/README.md)。

## 三件活各建议什么

准确率都还没测。所以建议不是「机械规则已经够好」，而是「还没有任何引擎被我们在这套中文样本上打过分，缺省保持设计里已经写好的机械行为」。标注到齐并跑完之前，不打开模型。

| 活 | 缺省 | 用户以后可以打开的 | 不做什么 |
| --- | --- | --- | --- |
| A 持续建议：屏幕下方提示「可以开个新 Topic」 | 不提示。只有人手动开题。按体验文档，这不算持续建议已经做成 | 先用机械预滤（转折用语、长时间离开当前标题、连续多条不再回应当前问题），再问一道是非。题可以交给 Jev 的 Noul，或本地千问。人忽略之后，同一段讨论三十分钟内不再问 | 不用嵌入相似度决定开不开题。不每条消息都问。不让模型写那条提示的正文 |
| B @ 时的缺口：上次开口以来，哪些消息和这次点名有关 | 只看提及、认领、Request 关联和游标。近期全文，更早的只留标题和事件指针 | 对缺口里每条消息问是非。相关的留原文，不相关的换成一行指针，指针由组装器按原消息写。问法可以是 Jev，或本地模型上的是非题，或 bge-m3 的相似度。短总结只在留下的原文上做，并且只有配了生成模型才做 | 不把不相关的消息从记录里删掉。不搬英文工具压缩项目的 0.2 或 0.7 阈值。不把模型输出当成来源 |

五节是：缘起与目标、已定事实与决定的理由、分歧与待答问题、所需约束与材料、来源清单。

### 按标价估算的费用上限

不是实测。用来约束「打开之后一天问多少次」，避免误报把账单打高，也避免每条消息都打一次。

一次是非题若 state 约 2000 token、题目约 100 token，按 0.042 美元 / 百万 token，大约 0.00009 美元。一个房间一天 50 次是大约 0.004 美元。建议上限取每房间每天 50 次或 0.02 美元，先到为准。人关掉提示之后，同一段讨论三十分钟内不再问。B 把一个缺口的所有是非题放进同一次请求（官方支持一道 state 多道题），按 30 条、每条 200 token 估算，一次大约 0.0003 美元。这些数只说明量级，样本上的真实 token 数未测。

A 的触发不要用定时轮询。用事件：新消息到达，并且机械预滤认为「可能换题了」。预滤没响就不调用模型。

误报会打扰人。在准确率出来之前，即使以后打开，也要同时满足：预滤响了、模型概率过阈值、冷却时间过了。阈值本身等标注后的误报曲线再定，现在不写死 0.8 之类的数。

## 对约束的建议

只建议，不改约束。

1. 模型判定要记模型引用和摘要。托管的 Jev 没有可公开的权重摘要。建议写成：响应里的版本号（例如 `jev-1.13.0`）记入引用；摘要字段写「托管服务，无权重摘要」。禁止把 `jev-latest` 记成版本。本地模型继续记仓库提交和文件摘要。
2. 正文是否允许发给托管判断服务，是一个策略点。缺省：不允许。未打开这个策略时，A/B/C 即使用户配了「小模型」，也只能走本机引擎或机械规则。不在引擎实现里再做一套过滤。

## Jev 的压缩做法能不能用于 B

能用的是「相关留原文，不相关不改写」。LiteLLM 把低分工具结果换成一行固定英文；jev-compactor 把整条消息拿掉。Room 应采用前者的可见性、后者的「留下的字节不变」：不相关的消息换成一行指针，相关的消息原样进入缺口。提问用是非：「完成这次点名，还需要这条消息吗？」不要用他们针对工具输出的英文句子直接搬过来。

他们报告的坑，我们还没在自己的样本上碰到，但设计上要预先躲开：概率重复调用会漂（jev-compactor 写过同题相差 0.14，阈值附近会翻）；中文没有他们的基准；大段无关正文会拉低判断，所以 state 应是缺口本身，不是整个房间；模型不可用时必须留下原文并标明这次没判断，不能假装已经挑过。

## 机械规则基线

还没有和模型比过分。基线定义如下，标注时模型也要面对同一套题，方便以后相减。

- A：出现明确转折（「另外」「话说回来」「这个先放一放」「单开一个」）且后面至少还有一条消息，才提示。其余不提示。
- B：留下含有被点名者名字、回复那条点名、或与之同一 Request 的消息。其余视为不相关。
- C：含有「因为」「已定」「拍板」的归入已定；含有问号或「待」「未决」的归入分歧；含有链接或 PR 号的归入来源；其余不选。这是故意笨的规则，用来当地板，不是产品提案。
