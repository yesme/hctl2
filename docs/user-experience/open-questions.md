已明确的体验不再重复设成问题：入口叫 project；当前对应 repo；点击进入 project room；rooms 初始为空并吸收 scoped room；kanbans 支持多个 source；runs 独立列出；三者松散关联。这些均见 [04](./04-project-navigation.md#本轮原话)。

## Q1：旧设计的两层对象怎样对齐一个 project 入口

**问题与影响：** 现行 [Project 定义](../design/spec/project.md#对象)与 [Repo 定义](../design/spec/repo.md#对象)是两层，允许同 repo 下多个旧 Project，另有 Repo Room。新体验不需要用户管理这两层；但旧 Project 还承担选人策略、预算、授权和归档等职责，不能只替换名称就丢掉这些职责。

- **一种做法：** 产品与领域一起收敛，以当前 project 承接工作范围，repo 只说明当前代码来源，topic room 承接讨论；明确旧职责的去向。好处是词与对象不再错位；代价是要成批修改规范和验证映射。
- **另一种做法：** 先用一个入口组合旧 Repo + Project，保留内部两层。短期改动较少；代价是继续解释隐藏的一对多、两类主 room 和设置归属，容易把混用带回实现。

**整理者建议：** 优先研究第一种，不把隐藏旧容器当长期答案。具体保留哪些模块和存储对象，不在本次体验文档中擅自决定；也不预先指定版本号或迁移框架。

**待裁边界：** 是一起收敛领域，还是允许一个明确期限/范围的旧模型过渡。阻塞正式架构改写，不阻塞体验口径；当前不做数据迁移或代码改动。

## Q2：本地 detach 会改哪份目录

**已明确：** 有 remote 的本地 repo 仍有两个入口——推荐接原 remote，也可用 Gitea 另起独立工作。不是讨论要不要保留第二个选项。

**未明确：** “本地 detach”是直接改用户输入目录的 remote，还是另建副本并让副本指向 Gitea？前者直接满足原地切换，可能影响共用配置的 worktree；后者保留输入目录，但多一份副本，且不能宣称原目录已经 detach。

**整理者建议：** 默认独立副本，原地切换作为显式选择；后果在操作前讲清。待所有者确认，不把推荐当已获准的物理操作。影响[新建流程 P1](./02-user-journey.md#p1选择代码来源)和 Repo 注册路径；阻塞这项写操作的最终产品语义，不阻塞入口归拢。

## Q3：删除 task 的后果

**已明确：** 两种 room 都能通过聊天建立和删除 task。不能只实现取消后就把整个删除需求划掉。

**未明确：** 对已有 run 或历史结果的 task，“删除”是否只是从活跃工作中移开并取消，是否同时删 source 卡片，以及是否要物理删除历史？这些后果不同；现行规范保留历史，源卡删除也不自动等于 HCTL 工作已停止。

**整理者建议：** 草稿可直接删；已有工作默认取消并保留历史；删 source 卡片另标动作和后果；活动 run 的停止单独说明。代价是动作文案不能只剩一个含糊的“删除”，收益是不会误删事实或误报停止。

这仍是建议，未代用户批准。影响 [T2](./02-user-journey.md#t2在两种-room-里操作-task) 与现行 Task 约束里的生命周期；阻塞删除行为的规范和实现，不阻塞聊天入口与其他 task 操作。

## C1：cloud 用例的 room 位置

这是原文还原核对，不是新增架构选择。原始 use case 中 `cloud_jstui_01`、`cloud_jssdk_01` 每个 repo 只出现一次，无法仅从名字确定它是主 room 的工作范围，还是额外的一间 topic room。

[01](./01-multi-unit.md#修正后的-project-与-room-对照)暂以 project room 承接它们的名册。若所有者原意是 topic room，只需改这两个场景位置；机器、人员、ctl 连接都不变。此项阻塞“原文已全部无歧义”的结论，不阻塞多单元能力讨论。

## 接手时的完成边界

- 已落盘：四份体验正文、第一手出处、术语对应、历史入口指路、以上待裁项。
- 未实施：规范收敛、产品实现、真实行为验收。文档检查通过也不等于这些能力已完成。
- 下一步：所有者处理 Q1–Q3，核对 C1；然后按对齐清单提出一批具体规范改法。本轮不再等待口头答复，也不把旧 memo 的作者推荐当作批准。
- Git 交付：本目录及所有指路变更经同一 PR 合到 main；另一台机器更新 main 后，以本清单继续，无需复制本机临时目录或恢复这段对话。
