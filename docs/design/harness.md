# Harness 与 Terminal

> 本文是 Harness 模块的设计正文：它为什么存在、拥有什么、按什么规则运转。精确对象、状态机与写入合同见[合同附录](./spec/harness.md)；模块交接见[连接合同](./spec/connections.md)，共享机制见[系统边界](./spec/system.md)。

## 为什么存在

进程、PTY（伪终端）、worktree（Git 工作树）和终端连接都是可替换的物理资源：它们可以丢失、重建和接管，但不能反过来定义 Project、Task 或 Run 的事实。Harness 模块的职责，是把上层的一次授权变成可观察、可隔离、可恢复的物理执行，并诚实上报发生了什么——执行结束了不等于上层成功了。

正常路径上用户不需要进入终端：状态、diff、证据和 Request（请求卡）应该先把事情说清楚（默认无界面，headless by default）。观察手段是一道阶梯——结构化执行流是默认视图，PTY 转录是二级诊断，终端接管是最后一级。如果日常了解进度要靠开终端，说明上层投影失职。

## 模块拥有什么

Harness 模块把上层的一次授权——Project 的单次调用或 Run 的一次派发——变成真实跑起来的进程。它拥有：可复用的执行者配置（哪个 Harness、什么模型、什么权限）；每台主机上的 Harness 目录（装了什么、实际能干什么）；获准的写入边界 ChangeSet（变更集）及其不可变快照；物理运行时与终端通道；以及提交给上层校验的结果提案与证据。它不决定 Project 目标、Task 完成、Run 的评审结果，也不创建下一条协作边。

## 关键规则

- worktree 是变更集的可替换载体，可以丢弃重建，不永久属于任何 Project、Task、Room 或参与者。
- 一个变更集同一时刻只有一个写入者；换人、接管或取消，都要先让旧写入者失权。
- 恢复时证明不了旧写入者已经安静退场，就把旧现场原样隔离、换一个新工作树重来；来历不明的修改绝不悄悄混进新的产出。
- 清理任何资源之前，必须确认没有唯一副本会随之消失；宁可留下现场和恢复指引，也不删孤本。
- Agent 说“我已经合并了”不可信。集成走持久意图、执行、回读、唯一凭证四步，由 core 校验 Git 事实。
- 观测（进程、屏幕、心跳、钩子）无论多可信都只是观测；它可以触发关注，不能自动变成领域结果。
- 执行体只拿到本次执行需要的窄能力。它可以建议完成、建议下一位协作者，但在执行环境里调用任务终结或群发命令，会因为来源是执行体而被直接拒绝。
- Project、Task、Room、Run、Participant（参与者）、Seat 都没有“自己的终端”；终端只属于一次具体执行。
- 一次执行被恢复或接管后进入新代次；旧代次的连接、输入和结果一律失效，只留审计。
- 客户端退出不停止执行；断流恢复时证明不了是同一个进程，就不能自称精确接管。

## Terminal 场景

Terminal 是 Harness 的观察、诊断和接管场景；它可以渲染结构化执行流或真实 PTY，不要求每次执行都有 shell。

| 能力 | 含义 |
| --- | --- |
| exact attach | 连接仍存活的精确 PTY/进程 |
| native handoff | 交接同一个外部 Harness 会话 |
| structured inspect | 查看实时结构化事件与原始记录 |
| semantic resume | 以外部会话 ID 恢复上下文，可能创建新进程 |
| replay | 只读历史 |

Execution Chat 是绑定一次精确执行的结构化观察与控制视图：它不是 Room，没有独立的会话身份；里面的输入和事件也不会自动进入 Room，只有显式的 Share to Room 动作经 Project 准入后才能发布。观察、输入、执行控制和安全输入是分开授权的四种权限，接管会原子撤销旧输入者。

| 角色 | 可以做什么 | 不能做什么 |
| --- | --- | --- |
| 场景客户端：Workbench Terminal | xterm、Execution Chat/结构化检查、精确 attach、能力说明 | 用 UI 状态推进 Task/Run，或把执行投影当作 Room |
| 场景客户端：CLI / WezTerm | 使用短期连接票据观察或接管精确目标 | 提交任意 argv/cwd/pane ID 绕过 agentd |
| 受控端口：HarnessAdapter | ACP、原生服务端、SDK、PTY 或钩子能力 | 把厂商 Session 当成 HCTL 身份 |
| 受控端口：RuntimeBackend | 持有进程/PTY/容器/mux 资源 | 决定领域权限、评审或完成 |

## 原生会话导入

原生会话导入（native session import）是可选能力：由用户显式发起导入，保留外部会话 ID 与路径来源，只把用户挑选的摘要或引用带入 Context，解析器使用固定版本的样本测试。它不把外部历史复制成 Room 事实，也不是第一阶段的交付前提。

## 模块交接

以下只列所有权方向；派发、结果准入与恢复由[连接合同](./spec/connections.md)统一定义。

- Project 与 Run 各传入一份冻结的执行规格（ExecutionSpec）；Harness 不重新解释上层范围。
- Harness 只返回结果提案、变更集快照、测试/SCM 证据和运行时观测。
- control/core 校验后才可形成 Run 的 Verdict/Receipt 或 Task 的验收证据。
- Skill 提供指导和上下文，不获得命令、评审或写入权。
