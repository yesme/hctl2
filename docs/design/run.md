# Run 与 Workflow（施工图）

> 状态：规范性（架构层） · 草案 v0.17.1<br>
> 日期：2026-09-02

> 本文是 Run 模块的设计正文：它为什么存在、拥有什么、按什么规则运转。精确对象、状态机与写入约束见[约束附录](./spec/run.md)；模块交接见[连接约束](./spec/connections.md)，共享机制见[系统边界](./spec/system.md)。

## 为什么存在

行业并不缺工作流引擎：DAG、代理委派、重试、定时器和历史恢复都已被反复实现。真正缺失的，是一套面向项目语义、绑定精确版本与证据的治理层——它回答“这个节点对应哪份交付义务、谁有资格尝试、结果是否有效、凭什么可以算完成”。这件事不能委托给聊天室、看板、Harness、终端或任何通用引擎；它是 Run 模块的原生价值。

两种权威一句话可以分清：

> 引擎说：“这个外部节点 READY / IN_PROGRESS / COMPLETED 了。”<br>
> HCTL2 说：“它对应哪份交付义务（Obligation），谁可以尝试（Seat 与候选），对结果的裁决（Verdict）是什么，是否可以完成（准入校验）。”

引擎只报告执行进度，HCTL 只裁决语义结果；进度报告不能替代语义判决，语义判决也不改写引擎事实。

## 模块拥有什么

Run 模块保存“哪份自动施工已获授权、引擎报告的进度如何映射为语义结果”。Workflow 是它的操作场景，不是独立的领域模块。它拥有：

- **施工图及其批准**：与引擎无关的不可变控制图，即施工图版本（Workflow Revision），先批准、后开工；
- **一次授权执行**：Run 是对冻结施工图、任务契约版本、代码基线、候选、权限和预算的整体授权；
- **交付义务**：Obligation（交付义务）是一个外部节点必须产出的逻辑结果。引擎重试时，control 根据再次进入等待态的进度报告创建新义务；旧义务及其票失效，因此重试不会增加票数；
- **席位与尝试**：Seat（席位）是义务里稳定的逻辑裁判位，换候选人不改变席位——换人不换裁判、不多一票；Attempt（尝试）是某个候选的一次具体执行，物理现场崩溃或重连不改变尝试身份——掉线不丢身份；
- **评审关卡**：Gate（评审关卡）按冻结规则决定结果凭什么通过；
- **裁决与凭证**：Verdict（裁决）是对精确版本的语义结论，Receipt（凭证）是校验后的正式证明。

在三类数据里，Workflow 场景的结晶是凭证链——“干成了的证明”。施工图（“干什么的计划”）从 Project Room 的塑形讨论中长出，作为结晶归 Room 场景；它的批准与版本对象仍由 Run 模块定义——结晶归属以事实为准绳，不随对象所有权走。判决的权威在控制面账本，结晶副本进 Git（私有仓库默认全文，公开仓库可降为仅摘要）。

跑图的是现成的工作流引擎，HCTL 只拥有语义。为什么用现成引擎而不自建持久状态机，见[工作流引擎选型](../research/workflow-engines.md)里「SCXML / XState 自建」一行与[来时路 §18](./references/decision-history.md#18-workflow-engine-从-conductor-改为-daguv0121)。

## 一次评审合入走一遍

八个治理词分三类：四个对象、一个节点类型、三个票据。用一张两步的施工图——第一步修登录页，第二步评审后合入——按出场顺序过一遍：

- **Obligation（交付义务）**是施工图上一步「要交出什么」：交出修复代码；交出评审意见。不管谁来做，这一步的义务固定。它是对象：有自己的活跃、达成、失败、被替代，引擎等的就是它。
- **Seat（席位）**是义务里的一把椅子：作者席；评审席位，可多个。坐的人可以换，椅子不变。它是对象：票和权限都按席位算，换人不换席。
- **Attempt（尝试）**是某个具体的 Participant（参与者）坐上椅子干的那一次。执行体崩了，同一把椅子开新一次尝试。它是对象：崩了从这里重来，是恢复边界。
- **ChangeSet（变更集）**是一次获准的写入范围加它的 Git 快照：允许改哪里，改完是哪个提交。它是对象：写入权限的边界；对象归 [Repo（仓库）模块](./repo.md)，Run 只引用它的精确快照作评审对象。
- **Gate（评审关卡）**是一种特殊的步：席位不干活，投票；法定票数够了才过。它是节点类型，不是对象，没有自己的生命周期。
- 三个票据是步骤产物，只被引用不被改写。**Verdict（裁决）**是席位判的，**Receipt（凭证）**是控制面判的，两个都是判定结果。**Evidence（证据）**是被判定的事实记录——一份测试输出、一个 CI 状态、工具箱回读到的提交号、一个 diff 的指针——它本身不下结论。凭证的结构是「结论、依据的规则、指向哪几条证据」：完成凭证说验收项一绑证据甲、验收项二绑证据乙；裁决也指向证据，评审员说「要改」时得引测试输出。证据有来路：工具箱直接读到的、适配器结构化上报的、模型转述的，三级可信度不同，验收可以要求某项证据不低于某级。

## 关键规则

Run 采用愿景中的[两种控制制度](./vision.md#两种控制制度)：批准与开工分开，开工后 control 才在冻结边界内自动推进。用户命令和执行体的结果先经校验并持久化，涉及运行时的动作再按撤权与 outbox（发件箱）顺序送往引擎；谁点按钮不是关键，保持这个顺序才是关键。

- 开工时冻结一份施工清单（Manifest）：项目与任务契约版本、施工图、代码基线、席位与候选、能力权限、评审与预算规则一次冻结。
- 运行中只有清单声明的放置参数可变；范围、验收、候选或权限变化通过结束或替代旧 Run 生效。
- “重试”有五种身份不同的路径——传输重投、候选切换、引擎重试、语义返工、替代执行。把候选切换当成引擎重试会多建义务并复制票数；把语义返工当成普通重试会沿用旧验收；把替代执行当成重投会让已撤权执行复活。完整分类见[约束附录](./spec/run.md#request重试与-gate)。
- 评审必须独立，独立性有三个来源：被评对象的作者不占必需评审席位；席位是经认证的 Participant 身份，不是随便一个进程；票是账本里附证据、可核的记录。别家买独立性的办法有三种：锁定一个评审者；换一家厂商的模型再看一遍；多人发言、最后统一成一个意见。我们直接提供多票评审——席位互相隔离、各投各的票、不被先发言者带走，法定票数由施工图声明，一票也行。「换厂商」可以是施工图里一条可声明的席位策略，账本记着每个 Participant 来自哪个 Agency，机器能查，但它不等于独立。备用尝试不增加票数；被评对象换版本后旧票作废，重新过关卡。
- 评审说「要改」分两种：活儿没干好，返工；契约本身有问题，归约器不自动返工也不换人，只把 Task 标需要关注、建议人采纳新契约版本。返工有轮数上限，到了按票数不可达处理，不原地转圈；席位可按策略只看与上一版的差异。
- 一步开始前可以等一个外部机械事实——CI 绿、PR 合并、某个文件出现。它是这一步的准入条件，由工具箱读回，不是一个有人执行的步骤，也不占席位。
- 工作流引擎自带管理界面的直接改写会先改变机械执行，因此只回读为分歧并安全暂停；精确顺序与准入见[Run 约束](./spec/run.md#写入约束)。
- 尝试的逻辑身份由 Run 拥有，物理进程由 Participant 模块观测；两边不维护两套状态。
- Run 正常完成且绑定契约时，由归约器提交同一个 Task 完成命令并交由 Task 独立验收；权威来源定义见[Task 约束](./spec/task.md#写入约束)。
- 裁决与凭证绑定精确的评审对象版本。
- 同一 Run 里节点之间靠结晶接力：评审席位拿被评版本，返工席位拿裁决正文，备用尝试拿同一份上下文并附旧变更集快照的指针。引擎报告的进度、步骤日志和终端记录都不是来源；没提交的对继任者不存在。完整规则见[横切正文](./context.md)。

## Workflow 场景

Workflow 场景提供施工清单预览、只读图、节点/席位/尝试的渐进展开、Request、证据、暂停/取消和恢复状态。

| 角色 | 可以做什么 |
| --- | --- |
| 场景客户端：Workbench Run 图 | 查询、预览并通过公共命令服务提交 Run 命令 |
| 场景客户端：CLI | show/preview/start/pause/cancel；写操作先预览确认 |
| 受控端口：workflow engine | 保存令牌、机械任务、定时器、重试和历史 |

Workbench 关闭不停止 Run。Workbench 就位前由 `hctl2` CLI 调用公共命令服务，就位后仍调用同一服务。工作流引擎控制台保留为供应端管理与诊断界面；其直接动作按[Run 约束](./spec/run.md#写入约束)回读为机械事实与分歧。

## 模块交接

以下只列所有权方向；字段、事务与故障语义由[连接约束](./spec/connections.md)统一定义。

- Project 通过启动命令交付冻结的 Project 与施工图引用；可选的任务契约版本由 Task 提供，Run 独占施工清单与执行生命周期。
- Run 向 [Participant](./participant.md) 模块交付派发时冻结的执行规格（Execution Spec）；Participant 模块只返回结果提案、证据和物理观测，变更集快照由 [Repo](./repo.md) 模块在 Run 准入提案的同一事务里准入。
- Run 的评审席位引用 Repo 模块的变更集快照；评审关卡通过后的合入意图由有权的人或冻结的归约器提交给 Repo 模块执行、回读并写凭证。
- Run 向 Task 返回精确的 Run、裁决与凭证引用；正常完成且绑定契约的 Run 可由归约器提交同一个 Task 完成命令。Run 向 Project 提交 Request 并投影低噪声里程碑。
