# Participant 与数字参与者

> 状态：规范性（横切设计正文）· 草案 v0.13.4<br>
> 日期：2026-08-25<br>
> 定位：本文回答"谁在参与、按什么方法工作、结果归于谁"。它是横切设计正文，不是第五个模块：Participant 身份与角色绑定的合同在 [Project 模块合同](./spec/project.md)，执行者配置在 [Agent 模块合同](./spec/agent.md)，评审席位独立性在 [Run 模块合同](./spec/run.md)，冻结链在[连接合同](./spec/connections.md)。合同级细节的完整底稿与逐条裁决来源见 `.memo/design/participant-design-20260819.md`。

## 为什么存在

"机器上装了哪个 CLI"回答不了"这项工作该由谁、按什么方法做"。自动探索本地 Harness 只是解析链的最后一步——它知道这里有什么工具，不知道谁在工作、以什么人设出现、带着哪份方法论、是否有资格参与评审。把这些混成一团，就会出现三种熟悉的病：换个进程就像换了个人（结果无法归属）、评审席位形同虚设（同一个模型换个名字给自己投票）、以及 BYOA（bring your own agent）——手边正好有哪个工具就让哪个裸模型上，工作质量随手气波动。

Participant 存在的意义是把"谁"从"用什么跑"里独立出来：稳定的是参与者身份，变化的是它被实现的方式。新进程、新会话、备用尝试都不产生新的参与者；换成另一个参与者也不能靠复用同一套执行配置伪装成同一个人。

## 七件事分层

一个数字参与者由七件生命周期不同的事组成，不能压成一份大配置：

| 层 | 回答的问题 | 明确不回答 |
| --- | --- | --- |
| 参与者身份 | 谁参与、结果归于谁 | 怎样运行、拥有什么权限 |
| 项目角色 | 在这个 Project 承担什么职责 | 全局身份、物理能力 |
| 人设（persona） | 以什么风格表达与协作 | 能否完成、能访问什么 |
| 模型与特殊训练 | 行为能力来自哪个模型谱系 | 参与者身份和权限 |
| Skill（技能包） | 本次装载哪份可版本化的方法 | 自动授权工具、自动获得票权 |
| 执行者配置 | 模型、模式、环境、候选端口怎样组合 | 此刻哪台机器可运行 |
| 一次物理执行 | 这一次实际落在哪个端口、哪个现场 | 上层角色、验收或完成 |

调用前的 Trigger Preview 把这条链完整摊开：实际的参与者、人设、模型、技能包、执行配置、权限、预算和降级，一次看清再提交；冻结之后整条身份链不随后续变化漂移，结果沿链回溯到精确版本。

## 关键规则

- 参与者不拥有 Task 完成权、票权或委派权；它可以是提及目标、评审席位或结果作者，但这不授予任何命令权限。
- 人设不是安全策略，技能包不是权限，能力广告不是能力证明；外部档案（如 AIEOS 这类可移植人设）只按白名单导入并去敏，签名只证明有人签过，不证明可信。
- 角色是职责绑定，不是权限包；权限与预算上限另行冻结，换人换绑不改写活动执行。
- 技能有三态：声明会（自称）、实际可用（已安装可回读）、本次已装载（冻结进执行规格）；只有最后一态才真正生效。
- 不同参与者身份不自动等于独立评审：第一阶段只证明逻辑分离，背后是否不同操作者、不同模型提供方，能认证的标 known、不能认证的标 unknown，不冒充。

## 专业化 Participant：告别 BYOA

评审是第一个必须专业化的岗位。今天的评审靠模型的自发判断，没有方法论——这正是 BYOA 的局限。解法是在确定参与者的阶段引入**专业化 Participant：模型 + 专用方法论 Skill**。

- **方法论是 Skill，不是 prompt 习惯。** 评审方法论（审查骨架、对抗核验、合同漂移检查这类审计方法）沉淀为带版本的技能包；评审参与者 = 稳定身份 + 该技能包（已装载态）+ 合适的模型与执行配置。
- **由此换来 BYOA 给不了的三件事**：可复现（凭证链冻结了是哪一版方法论查的）、可升级（方法论出新版，所有项目同步受益）、可审计（两次评审结论不同时，能回答是方法变了还是模型变了）。
- **与评审独立性正交叠加**：Gate 的评审席位绑定这类参与者，得到"有方法论且独立"的评审；专业化不改变票权规则，结论仍只是裁决输入。
- **自食其力**：HCTL2 自己的设计评审应最早切换到这个模式，替代各 harness 裸模型的自发评审。
- **商业化延长线**：将来"雇佣"外部数字员工，最先值得雇的就是带成熟方法论的评审者。远程参与者只保留三个协议面（发现档案、约定条款、执行端点），发现不等于信任、报价不等于预留、执行回执不等于结果；市场机制在真实场景明确前不设计。执行端点就是一个运行时 provider（合同见 [Agent 模块](./agent.md#运行时-provider)），provider 合同不含治理权威——数字员工"在哪跑"与"谁在工作"保持正交。
