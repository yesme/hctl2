# 契约测试矩阵

> 状态：验证文档 · 草案 v0.18.4<br>
> 本文列出十一族可观察行为的失败用例，不描述状态机、不新增约束；约束变更须先改 spec 再加用例。

交付测试检查可观察行为，不复述模块状态机。每族一个稳定的族标识符；模块新增约束必须在对应族里增加一个失败用例，而不是再建一份不变量文档。[参考用例 S1](./scenarios/S1-multi-unit.md) 引用本表用例的描述文本，不引用会随插入变化的序号。

### `CT-PROJECT` · Project / Room

- 注册确认事务激活 Repo 身份的同时创建唯一 Repo Room，待确认 Repo 不接受 Project/Task/Run；Repo 登记与工作副本的用例归 `CT-REPO`
- Project 分组与 Room anchor 可重建
- Scoped Room 闲置超过缺省天数未进「需要关注」时失败；系统自动以任一理由结案、或代人写理由时失败
- 有非终态 Run、写入型 Invocation、活动 Write Lease、待投递或结果未知的集成意图/发布评审意图或其他未决外部写副作用时归档 Project 拒绝，阻塞项列表能看见归 Repo 模块的租约与意图；仅开放 Task/Request 或未归档 Scoped Room 随归档转入只读，不被隐式终结
- CJK 输入、结构化引用、草稿/游标/未读、并发流隔离；时间线顺序以 chat server 给出的为准，治理引用只按事件 ID 冻结
- Repo Room 只把显式选中的来源链带入新 Project
- Scoped Room 回填和同根因 Request 去重；未回填且无显式结案（abandoned/no-decision/superseded 及理由）的 Scoped Room 归档拒绝
- Context 可解释、Room 历史可恢复（chat server 重同步 + 治理引用与冻结 digest 完整）
- chat server 不可用时，依赖 Room 来源、身份或 Context 当前回读的预览/命令 fail closed，不依赖这些读数的已接纳治理事实仍可使用
- Room–Server Binding 只接受未启用端到端加密的房间，HCTL 自建房间回读无 `m.room.encryption`；已绑定房间事后被加密与 chat server 不可用走同一条 fail-closed 规则并标为需要关注，换绑到未加密房间后恢复
- chat server 中的普通消息、反应或自动化不能成为命令；绑定未列明、actor 无法映射、source event/target/version 缺失的结构化动作同样拒绝
- 同一个 Matrix 用户动作分别从 Workbench 直连适配器和供应端事件适配器提交时，两条路径必须生成相同的命令摘要和结果。由 HCTL 服务或 bridge bot 发出的同形事件必须拒绝为 human 来源
- 模型 Participant 的 `@`/建议不能创建 Invocation 或 fan-out，human 批准后自动携带来源/Context
- 无法证明身份的 Invocation 撤权并终止，Retry 产生新调用且旧结果被拒绝
- 无 Run 返工是人发起的新 Room Invocation：原调用已结束、旧写权已结束、版本已保全、新执行满足选人策略与交付前置时，人明确选另一家获准 Agency 的参与者允许，因「原 Agency 仍在线」被拒时失败；开工包带人选中的精确版本与评论，要求带 HCTL Verdict 时失败
- mention 解析无唯一授权候选时明确失败，不按显示名模糊匹配或静默换人
- 原始消息、执行日志和模型总结不经「发布 Memo」命令不会成为 Memo
- 治理引用指向滚动纪要而非精确消息事件时拒绝
- Bundle 压缩条目缺 compressor/原文 digest 记录，或压缩了证据类内容时拒绝交付
- 萃取索引与纪要缓存删除后可完整重建且不丢事实；相关性门判定缺可审计记录时无效，未配置 small-brain 时以消息正文做路由拒绝
- 过期或被取代的 Memo 不进指针清单，显式引用除外
- 压缩片段或纪要条目的回源指针不是组装器赋予（例如由压缩模型输出）时，Bundle 拒绝交付
- Matrix 房间升级换 ID 后，换绑 Room–Server Binding 不改 Room 身份，旧事件引用与冻结 digest 仍可校验
- Room 名册换人只影响将来的调用，活动 Invocation 仍引用选入时的记录；活动 Run 的席位不能换施工者，改席位上的选入记录必须替代 Run；候选范围内的技术切换成功且不产生新席位与新票，超出选入记录的获准候选范围或切换后违反席位多样性声明时拒绝；Project 不持有成员名单，选入 Room 与席位选人不满足 Project 选人策略时拒绝
- 评审发布策略随 Execution Spec 冻结：Trigger Preview 未写明授权的是发布不是合入、策略缺仓库/绑定版本/发布目标规则/创建或更新/描述来源/审计公开范围任一项时拒绝；「须人显式确认」开关的值随授权冻结，之后改默认值不影响已接受的调用
- 平台评审评论线以精确 ChangeSet Revision 与评论标识冻结进 Context Manifest；评论被当作授权、契约或裁决时拒绝；显式不挂平台的仓库的 Manifest 没有这一项
- 必需材料未送达、摘要不符或只给在线控制面定位符时拒绝派发；已交付且可读的精确只读副本可作 pointer，必需正文预算内内联、超限给副本指针与分片建议，不能静默省略
- 授权本次材料集合不授予整库读权；试图读取治理记录库或其他 Project 的私有材料时拒绝；控制面离线仍能重读已交付副本，新增 recall 不可达则报缺口、不假报无此版本
- 归属者已终态但 Result Proposal 准入窗口未关闭时不能丢 Bundle；两者均满足后按保留策略丢弃正文，仍可查引用、摘要、来源、策略与丢弃事实，不报告可重放
- 同一份文字分别登记为代码 Artifact 与治理材料 Artifact 时按登记用途解析来源；未登记文件不成为 Artifact，材料 Git 中新增正文但未准入时不自动成为 Memo 或推进版本

### `CT-TASK` · Task / Kanban

- 外部卡片只改变 stage 或 health 时，Task lifecycle 和当前 Task Revision 必须保持不变；Kanban lane 只重新计算投影
- 非法 move/complete 拒绝
- Task 依赖归源：HCTL 写回依赖、另存依赖对象或为跨源记依赖时失败；源上有未关闭的阻塞方而卡片与合并板不投影时失败；父卡完成预览不列未完成子卡时失败；源无依赖语义时因缺依赖而阻拦时失败
- local state version 与 remote revision 不混用，过期邻项移动重算
- 本地 adoption 不要求伪造 Task–Backend Binding，外部 adoption 混用 Task–Backend Binding 版本时拒绝
- 未采纳契约使 Start/Complete fail-closed，明确 divergence 后新增 drift 仍使旧预览失效
- active Run 尚未结束时 terminal intent 拒绝；活动 Run 期间采纳契约推进 current 后，Run reducer 的「完成 Task」按契约分歧拒绝，不静默完成新 Revision
- Workbench、CLI、已获准的 Vikunja Done 和正常完成 Run reducer 必须生成同一种“完成 Task”命令，并经过相同准入
- Result Proposal 或单独观察到的外部关闭态提交该命令时必须拒绝
- Vikunja Done event 缺 doer 映射、前后变化、remote revision/updated version、当前回读或规范幂等 tuple 时只追加 Snapshot；重复/迟到 webhook 不重复完成
- provider Done 请求遇到无契约、活动 Run、证据不足或新 drift 时保持外部 Done + HCTL 开放并返回类型化结果，不回滚 provider、不伪造 Receipt
- 同一规范实体跨 Project/connection/placement 不得产生第二个 Task，禁用绑定也不释放映射；家所在的源停用后 Task 与认领保留、标需要关注，人重新接通同一实体后仍是原 Task，被静默取消或换成新 Task 时失败；换成另一实体却保留原 Task 身份时失败
- 任务源按仓库绑零到多个：未显式同意就绑了缺省源或建了卡时失败；启用看板的 Project 没有源引用、只开聊天室的 Project 被要求选源、只过身份与快照的绑定被选作缺省源、仓库缺省建议变化后既有 Project 的源引用或卡被搬动、同一 provider + account + scope 解析出两个活跃绑定时失败；注册与启用看板的两层选择可在同一预览确认；跨源的相对移动拒绝
- 认领分两路：适配器自选 Project 认领非缺省源或无锚点源的卡时失败；人显式认领无原生 Project 锚点的卡被拒时失败；认领把卡搬到缺省源、改写实体键、或在本控制面产生第二张 Task 时失败；认领后拿外源分组改写 Project 归属或去外源补建分组时失败
- 合并板被当作权威表写入时失败；未认领的卡不上板时失败
- 另一控制面的自动写回触发本控制面完成或本控制面的 Run 完成时失败；本控制面的写回冒充人的动作或缺控制面与 Task 标识时失败；人的原生 Done 因「是别人的卡」被拒时失败；无条件写入的后端假报成功时失败——未确认不报成功，能确认的照常收口
- Project 分组 anchor 在删除、重绑和重建后保持稳定；锚点只在 Project 源引用所指的绑定里建，在别的源里建了分组锚点、或跨源归组去读外源分组时失败；原生 UI 把卡片移到源里另一分组时，HCTL 保留原 `project_id`，只追加 Snapshot，不冻结采纳、启动、完成或字段写入——为此冻结时失败；需要当前回读的动作仍按前置拒绝
- Project 分组映射（父任务/milestone/标签降级）有测试
- 无契约 Task 的看板终态只是 content 投影，完成命令仍需先升格契约
- 验收项缺校验等级时「采纳契约」预览失效
- `mechanical` 验收项只以转述证据提交，或证据通道低于验收策略要求时，「完成 Task」拒绝；Receipt 逐项记录校验等级与实际判定者
- 同一 `mechanical` 验收项、其余条件满足：契约允许旁路（`adapter_event`）时以旁路证据提交通过；同一证据在只认直报（`unmediated`）的项上拒绝，不因参与者一侧加固与否改判；「完成 Task」把所有机械项一律收紧成只认直报时失败
- 契约冻结要求远端检查或远端合入时，本地测试成功或本地 ref 前移不能顶替；契约只接受自己的 Integration Receipt 时，外部合并不能顶替；事先声明接受精确平台集成证据且 Repo 回读核验版本、目标与结果匹配时，该机械项通过，但仍需本控制面的完成命令与其余验收项
- 验收契约未要求代码集成的 Task（例如只交付已登记工件、由人验收）完成时不要求 Integration Receipt；要求集成时按事先采纳的契约核自己的 Integration Receipt 或 Repo 核验的精确平台集成 Evidence，不接受 merged 字样、他人凭证或模型自述直接顶替
- 契约未声明接受外部集成证据，或已声明但精确源版本、平台目标、实际合入结果任一不符时完成拒绝；新 Task Revision 增加声明后不改旧契约，绑定旧 Revision 的 Run 仍不得静默按新契约完成；其余 gate/human 项未满足时不能仅凭平台合入通过
- Task/契约创建前正文已存而准入前崩溃，恢复同一命令只产生一个 Task Revision；准入后后端建卡确认丢失，按原关联键回读，不再建卡；材料保存成功不等于契约采纳或 Task 完成

### `CT-RUN` · Run / Workflow

- Workflow Revision 不通过 schema、Profile 或图结构校验时，编译必须拒绝
- 绑定 Task 的卡在源上被未关闭的阻塞方挡住而启动预览不列出、或未经人显式确认即启动时失败；预览把阻塞当作自动拒绝时失败
- 预算耗尽后仍创建新派工或新 Attempt、或未声明「超限即取消」却取消正在跑的派工时失败；追加预算不经 Request 直接放行时失败；Agency 报不全的用量被当作零计入时失败
- lint 票数检查：法定票数大于必需评审席位数时登记拒绝；两席要求与材料相同、未声明互异、法定票数二的图登记通过并附「可能合成一票」提示，被拒时失败；同一席位模板展开的两席仅凭模板相同被判同键拒绝时失败；登记结果不列出可能合成一票的席位与可选处理时失败；lint 结果替代启动预览的实际候选计算、或 lint 用与计票不同的键时失败；启动时按全部获准候选与已冻结材料计算，只有最多可能通过票数不足才拒绝，实际配置暂同但仍有合法不同键的可能时不据此拒绝，交付内容未知不当相同；投票时按实际配置摘要与交付内容摘要共同去重
- 返工的新 Attempt 未沿冻结的选入记录派工、技术故障时换了选入记录、工种或 Agency 而不是替代 Run、「到了义务截止」被当作切换条件时失败；开工包缺被驳回的评审对象或必用的 Verdict 正文、为凑齐包伪造 Verdict 或 ChangeSet、旧版本提案计入新版本 Gate、远端后续派工收到的仍是旧版本引用时失败
- Run 绑定超过一个 Task Revision 时，启动必须拒绝
- 已绑定 workflow engine 执行的状态只能由 control 命令推进
- Dagu UI/API 直接 Start/Stop/Retry/Reschedule/Approve/Reject/Edit/Rename/Delete 时只标记 Run–Engine Binding 分歧，不倒推 Run 命令、Verdict 或 Receipt；停止路径若未先持久化 intent 与撤权则不能冒充 HCTL Cancel 成功
- 超时与候选切换只依据控制面记录的 Obligation deadline
- 引擎停报进度（绑定分歧待对账）期间，或依据缓存、迟到事件和旧游标观察创建新 Obligation 时，创建必须拒绝；已经创建的义务照常验收与判决
- 派发确认回执丢失允许待启动→丢失并用新 Attempt 恢复，已交提案不被误当成功
- retry 只产生一个新 Obligation 并隔离旧 Seat/Attempt，候选耗尽和 Request expiry 产生明确的失败类型，所有 Run 过渡态可失败/替代
- dynamic fork 超出冻结 Seat 模板/recipient/基数/预算时拒绝
- placement 变更留下不可变审计
- Gate backup 改变参与者或任一 Context/Skill/policy ref 时拒绝，作者不能占必需 reviewer Seat
- quorum-unreachable 沿冻结失败边推进
- Run 正常完成只由治理记录的谓词决定；引擎报告的进度与治理记录不一致时标为分歧待对账，既不补足也不阻止谓词
- 失败/已取消/被替代 Run 不终结 Task，quorum/regate 和迟到结果拒绝
- 启动中 / 暂停中 / 取消中到达默认或声明的超时后进入需要关注并保留状态，不自动取消或替代
- 节点声明的外部机械事实前置：直报读不到时不派发并标需要关注；参与者、适配器旁路事件或模型转述的事实不满足前置，控制面自己的适配器或本机工具的直报满足；前置不创建 Obligation、不占席位
- 汇总仍要求返工、而再开一轮将超过声明的轮数上限时，按 quorum-unreachable 同路推进或创建 Request，不进入下一轮；最后一轮取得合格结果时照常通过
- 未声明增量评审时新 Revision 全量重评；声明时评审包带与上一版的差异指针
- `changes_requested` 分歧落点为契约时不进入语义返工、不自动替代，Task 标需要关注并给出采纳建议
- Artifact Revision 作评审对象仍成立，不经 Repo 模块转交
- 同一结果树、不同基线或不同版本身份不能复用旧票；同一获准版本只换提交包装时评审身份不变
- 同一平台账号的多个批准不增加内部席位票数；有效席位的 Result Proposal 仍可计票；接受外部评审的无 Run 契约不被强行送去 Gate
- 两个 Seat 各持合法的消费者 Bundle，投票时实际 Worker Profile 摘要与交付内容摘要均相同：法定票数为一、同组两席，通过先到与要求修改先到两种顺序得到同一结果——组在两票都准入或另一席已结束后才定，取最不利、按要求修改处理并标需要关注；法定票数为二、两席候选都只能落到同一键且材料已证相同时按确定不可达沿失败边推进、不签汇总凭证、两票留在裁决与审计记录；同组另一席仍可合法改用不同键时不得提前判不可达；一席已有有效裁决、另一席尚未派发且冻结引用不能证明键不同时不得签通过、不得撤该席；提案已冻结待准入时既不计票也不撤销；独立组够数提前结束后，被撤席位交回的提案只留历史，不补形成组、不改已签汇总；已结束的席位不再阻塞任何组已定；同组两席都已结束且无有效裁决时不形成票、不得签通过
- 未声明多样性时合法候选切换使两席同组按一票计；两席同配置而一席候选含不同配置并切换后成两票，之前不得提前判不可达；声明了席位多样性而选定记录或切换后不满足时拒绝；否决席无有效裁决而仍可产出时其余票已满不得签通过、不得撤销该席；其尝试失败时，义务有效、故障类型获准且候选、预算、截止允许时在同席位开备用尝试，故障类型未获准或预算、截止不允许时不切换；已交提案不切换，候选耗尽按类型化技术失败或 Request 而不按通过或驳回处理，已取消或被替代的席位不因此再派工
- 启动前按候选范围与席位要求已能证明最多可能通过票数少于法定票数时启动拒绝，交付内容未定时只警告不拒绝；运行中上界（含未定组里已有的有效裁决）少于法定票数时返回 quorum-unreachable，上界够时不得提前失败；最后一轮取得合格结果不因返工轮数用满而失败，还需下一轮时上限生效或 Request 保留；恢复后按已记录事实重算，不因远端未收齐而阻塞与它无关的组
- 席位多样性只有两项可声明：两票都引用同类直报不因此拒绝；同一 harness、不同合法 Worker Profile 且其余策略满足不因 harness 相同拒绝；已声明 Profile 互异却实际相同仍拒绝；删掉的两项不改去重键、重复组结算与计票；Agency 门后的内部重启不是候选切换、不凑新票
- 外部执行节点无达成判据声明时编译拒绝；产物依赖的边无生产节点、产出类型不匹配或悬空时拒绝；两个外部执行节点之间直接相连、不带产物引用的边拒绝，不因没写引用就算控制依赖；静态图有环时拒绝；至少一端是结构件的控制边、loop 重入、冻结模板的 dynamic fork 与引用尚未产生的上游产出的边都必须编译通过
- Workflow Revision 未声明关闭读回而「批准 Workflow」命令缺读回记录引用时拒绝；读回记录所引 Workflow Revision 摘要与本次批准不符、读回记录所引快照摘要与本次批准 Revision 所附快照不符、读回记录报新快照而实际交付的 Bundle 装旧快照、产出调用的 Bundle 含来源 Room 消息条目、产出调用带任何 Room 的消息读取权限、产出者在来源 Room 名册快照里、或声明读回须换 Worker Profile 而实际未换时都拒绝；声明关闭读回的批准照常通过，不带快照与产出来源也通过；只改「上下文」章节的新 Workflow Revision 编译出的节点、边与席位与旧版本相同，多出节点或义务即失败
- 登记时快照含三张清单以外的字段或条目种类时拒绝，直接文本来源记了提交者与内容摘要时通过；产出来源集合两次调用而读回用了其中一次的 Worker Profile 时拒绝；来源集合含调用 A（配置 X）、批准前最近一次调用 B（配置 Y）、读回用 Y 时通过；显式声明无模型产出调用时读回记录标注并通过；启用读回且声明了回避、来源缺失或引用无法解析时拒绝，补齐来源或撤回声明后通过；启用读回且声明了回避、登记传的是普通空集合而未显式声明无模型产出时不能批准；批准时采用来源集合 S，之后再提供 S′，原批准依据仍为 S，不被替换
- Gate Seat 的 Context Bundle 含本 Gate 其他 Seat 的裁决，或控制面附加的作者身份、作者所用 Worker Profile 标识时拒绝交付；被评对象自带的署名与历史评审材料不在此列
- Gate Receipt 缺逐票的选入记录引用、实际 Worker Profile 摘要、交付内容摘要、去重标记、逐条证据的通道等级或 token 用量（缺失须标 unknown）时不得签发
- Workflow 与三张清单保存成功但未登记/批准时不得启动；批准仍逐项比较登记、读回和实际交付 Bundle 中的图与快照原摘要，换成 Git 对象编号、材料定位符或最新清单时拒绝；仅材料后端迁址而精确字节与领域摘要不变时通过，R 批的产出来源与回避条件保持生效
- 公开审计只有摘要却拿它替代返工裁决正文时拒绝交付；预算内内联、超限已送达精确正文加指针和分片建议时通过；三个消费者共享材料条目不要求完整 Bundle 相同，不能以一个消费者的完整摘要准入另一消费者，计票仍按既有交付内容摘要判

### `CT-PARTICIPANT` · Participant / Terminal

- 未探测到声明能力时，绑定必须拒绝或降级
- Agency 申报的 Skill 引用与 digest 没有经 Agency 取得的直报核验报告时，Execution Spec 只能记 unknown，不得记 known；远程参与者有可核验报告时记 known，本机参与者只有申报时记 unknown；required Skill 缺失时解析失败
- 申报的 Skill digest 与核验回读不一致时不激活，拒绝结果列出不一致项
- Revision 或 digest 不匹配的 Result Proposal 必须拒绝
- 错派工、过期或撤销的授权的输入和结果必须拒绝；控制面记录进程或运行时代次、或要求 Agency 报告门后换了几次进程时失败
- 旧 writer 既不能证明已停止、也不能证明被限制在旧工作树与旧 ChangeSet 边界内时，本模块不得声称已隔离，Repo 模块因此不重授租约；证明已停止时，有权 human 授权的新调用可以在同一 ChangeSet 上取得新租约、继续产出新版本；只证明被限制在旧边界内时，后续执行用新 ChangeSet、原 ChangeSet 不重授；三态报告由 Agency 给、控制面核，控制面自己查进程、PTY 或目录时失败；写租约与保全的用例归 `CT-REPO`
- 冲突观测按来源证据仲裁
- Execution Chat 的错误归属者、错派工的输入和无 provenance Share 均拒绝
- 治理命令只有两类 actor 来源：映射到有权用户本人的 direct client/provider event，与只执行已冻结规则的边或已有 human 授权后续动作的 control 归约器（task-bound Run 正常完成的「完成 Task」、Gate 通过后的「合入 ChangeSet」、按冻结策略的「发布评审」，来源规则见[系统边界](./spec/system.md#命令与跨服务正确性)）；Workbench、CLI 与 provider adapter 产生相同 command envelope，Result Proposal 通道提交不了治理命令
- 每个 Worker Profile：模型取不到通用 control/human 凭据与集成权；在有效租约下读获准对象并向自己的源分支提交成立，持相应凭据单元按冻结范围交付该版本也成立；拿源分支推送权更新集成目标或扩大发布范围时拒绝。别人更新目标不产生自己的 Integration Receipt；按预期目标头/接受前移两种形态及保护条件判断，不一概当作漂移
- 声明了隔离效果的 Worker Profile：所声明项按 Agency 的承诺生效并记在派工上；已声明而 Agency 不承诺时不激活，拒绝结果列出缺项；未声明时照常启动、不记录为已生效；加固写成 OS 手段而非隔离效果、或未加固被记成已验证隔离时失败
- Agency 门后接替后要求控制面换派工、改规格或重新激活时失败；规格外改派却报同一派工继续时失败；旧执行体在门后发起新封存被放行时失败，已保管的待交结果被封死时失败（按原提案交回、控制面按原授权判）；控制面凭内部进程故障直接切换 Attempt 时失败，切换只在 Agency 报无法履约后按冻结规则
- 另一控制面对本租户派工的读取、订阅、输入、取消或结果收取在结构上不可达，不是“不算命令”而放行；Agency 门后搬动进程、会话或主机不改变派工引用，不产生放置审计；对派工终端的输入按 Execution Spec 输入策略处理
- `native_interactive_allowed` 下经 Agency 的原生客户端输入是有效运行时输入，该输入不能直接产生领域结果，其中的文字与“完成”不准入；Agency 未声明逐次输入记录能力时，还必须标明逐次 provenance 和物理单写者保证不完整
- `managed_single_writer` 下绕开有效输入授权的动作不得落到该派工；两个客户端同时持有同一目标的输入租约时失败，接管必须原子撤销旧租约；Agency 不能统一拦截全部写入时执行不得继续声称策略成立
- Agency 未声明事件游标能力时，不得把事件流当作完整持久 trace；重连后只能按可证明范围恢复观察
- Agency 对其声明的[恢复等级](./participant.md#terminal-场景)负责：不能按声明的等级证明连接对象未变时不得声称 exact attach，控制面自己核进程同一性时失败；缺失停止报告与退出码的派工不得报告为成功停止
- Agency 状态检测以低层来源覆盖仍有效的结构化 hook 证据时拒绝；Agency 不可达只记联系不上、不撤权、不延长授权，睡眠期间冻结的截止被顺延或等 Agency 回答才判时失败；截止已过记超时不记身份丢失；Agency 明确报无法履约被记成联系不上时失败；只有语义归属者或租约不能证明才进丢失
- Agency 自带的接管/单写者/"会话有效"记录被当作治理记录或替代租约/代次时拒绝
- 没有「代为执行工具并直报」能力的 Agency 转来的工具输出被记为直报时失败；控制面自己读平台或本机工具的直报因参与者未加固被降级时失败；证据等级系于物理代次回显、或 `toolbox_readback` 旧标识仍出现时失败；来源不符或已识别为伪造的报告不作为直报准入；租户隔离被当作同租户内模型不能冒充采集方的证明时失败
- control 签发连接票据、Agency 校验，观察、输入、Attempt 控制与安全输入权限分离；票据不经 Agency 校验就生效、票据含主机或终端 ID、控制面或前端绕过 Agency 直连门后的进程、PTY 或 API、工具或参与者绕过 Agency 直接向控制面报告、控制面存储出现门后地址时失败
- Agency 更新名册后活动派工或已接受的引用悄悄变成新条款、新版本未经显式命令被接受、冻结引用把 unknown 记成 known、控制面记录 Agency 的安装位置或逐主机清单时失败
- 控制面记录待命参数或会话状态时失败；同一参与者再次派工复用上次的授权或租约时失败；两条同工种选入记录被合成一个会话时失败；会话文件可恢复被当作旧执行仍成立时失败
- 一个租户的凭据对另一租户可见时失败；模型取得通用凭据或目标集成权的底线用例见上条 Worker Profile 行
- attach 只接通道，不能恢复 Run/Invocation 语义
- attach/replay、IME/背压/慢客户端隔离
- 未标注证据通道的 Evidence 按转述处理；转述不能通过重新标注升级为高证据类
- 同一工种在两个 Room 或两个 Run 里选出的是两条记录，不共享身份；`@` 在 Room 里解析不到只存在于某个 Run 席位上的施工者；`repo_scope` 只读调用从 Repo Room 名册选人，没有选入记录的调用拒绝
- 不带通用现场对象或现场代次、但派工引用/原授权/语义归属/租约/结果摘要均匹配时可按原授权处理；生产目录改变本身不要求替代执行，错派工或语义归属不匹配仍拒绝；成果已保管而原工作树已删不单独成为拒收理由

### `CT-REPO` · Repo / Change

- 人显式登记仓库及平台绑定，不要求代码树身份文件或先挂接工作副本；无提交的仓库也能登记；同一注册命令重投返回原 Repo 与唯一 Repo Room，出现第二份登记即失败；人显式在同 Repo 开两个 Project 时分别授权，不能共用或互相替代授权；平台迁移按显式换绑且活动意图仍用旧版本，不从 URL、目录或共同提交推断合并身份
- 第二个写入者请求同一 ChangeSet 的活动租约时必须拒绝；新旧租约交接时 Repo 模块撤权、Participant 隔离、确认前不重授
- 无法证明旧 writer 已被隔离时默认保全并隔离旧 Git 工作树，不自动重授租约；接管、采用或丢弃缺少有权 human 显式确认时拒绝，失败清理不丢唯一未封存/未跟踪修改
- 返工或另一台机器上的重新物化来源不是已封存并获准交付的 ChangeSet Revision、开工包里出现未封存字节、显式不挂平台时被要求先推送才能重建时失败；从获准来源取得并确认送达通过，同一版本多个获准副本任一可用
- 旧执行体（E1）卡住期间已在本地封存待交，Agency 改派 E2 接替后 E1 回来：E1 以当前派工名义的新封存在门后被拒，已封存的待交结果仍按原提案交回供对账，能否准入按原授权与既有处理判；把它一律封死或一律放行都失败
- 未经 Project 或 Run 准入的提案不产生获准 ChangeSet Revision；Git 封存完成但归属者在准入前被取消或替代时，不产生可供下游消费的版本，也不触发发布评审；平台上出现的提交不是准入
- 同一获准版本只换提交包装（内容与基线相同）时 review_subject_digest 不变；基线或结果树变化时是新 Revision，旧 Verdict 失效；结果树相同不是充分条件
- 同一获准集成意图与匹配的合并结果：回读只有旁路或转述证据时不能签 Integration Receipt；换成匹配的直报回读（`hctl2-tool` 或平台适配器读到的合并提交与目标头）且其余条件齐备才可签，Receipt 记回读证据的通道等级
- 本地/远端集成都先持久 integration intent，由 `hctl2-tool`/平台适配器执行、`hctl2-tool` readback；预期目标头形态下的目标头竞争、确认回执状态未知、换绑或远端合并回执丢失时不得签成功 Integration Receipt，同一意图重试只得同一结果
- 源版本不变、其余前置满足、目标从 A 前移到 B：预期目标头形态拒绝；事前已选接受目标前移形态则成功，Receipt 记实际目标头 B；保护规则变化另按快照判定，不能替代形态判定
- 本控制面同一目标（供应端目标引用及 ref）已有待决集成意图（任一形态）时，提交另一意图（不论形态）拒绝；前一意图终态后，同一目标的下一意图是新的授权并可成功
- 有权 human actor 预览残留后的显式封存不经 Invocation/Attempt，由 Repo 模块按该命令准入为 ChangeSet Revision；封存意图重试同一关联键返回同一结果；`hctl2-tool` 已写出但未准入的树或提交不是获准版本
- 关掉客户端后，获准结果仍按已冻结的评审发布策略发布，actor 信封沿用授权它的那次 human 提交；开关打开的仓库改为待处理、由人预览后提交
- 「已开启自动合并」「已进合并队列」「请求已接受」都不算已合入，Receipt 只在回读到合并提交与目标头后签发；Receipt 记实际目标头
- 绑定声明「不能保证预期目标头」而 actor 未显式选择「接受目标前移」形态时，集成意图拒绝；执行时不得由回读结果倒推放行
- 目标开了「要求与目标同步」，在预览与执行之间变化时仍按冻结的目标保护快照接受或拒绝，不凭「同步开关为真」或「几个检查为绿」通过；保护条件与快照不一致时拒绝或标需要关注
- 显式不挂平台的 Repo 的本地目标 ref 正被某个工作树检出时默认拒绝，返回精确工作树路径与「切离后重试」的恢复动作；人切离后重试同一意图成立；显式放行只推进 ref、不更新该工作树
- PR 被改投另一目标分支、关闭或重开时只更新映射状态并标需要关注，不对错误目标写 Receipt
- 推送成功但创建 PR 的确认丢失、更新 PR 后确认丢失时，按原意图与关联键回读、不重复创建；旧 Revision 的迟到重试不能覆盖新 Revision 的分支或映射
- 提前授权的发布评审只发布本次已获准产出；换仓库、换绑定、换发布地点或扩大发布范围须重新授权；Result Proposal 换发布地点时拒绝
- 平台批准、控制面自己写回的批准、重复事件、无法映射的动作各走正确的来源规则：批准只是外部评审证据，自写回事件排除，重复/迟到/乱序得到相同结果，无法映射只形成 Snapshot；「已合并」通知无匹配意图时只作外部事实，可按契约触发本控制面的核验，不倒补意图或补签自己的 Integration Receipt
- 获准 Git 交付不因执行地点不在控制面就拒绝；参与者无凭据但有获准中转时可交付，没有可达路径时不得报告已发布；PR 与合并仍须相应平台权限，源推送成功不能冒充评审请求已建立
- 契约冻结要求远端检查时本地成功不能顶替；契约要求合入远端 ref 时本地 ref 前移不能顶替；能力缺失使命令等待、拒绝或标需要关注，不改契约
- 显式不挂平台的 Repo 走受限路径：机械项只以本地事实为证据，集成只面向本地目标；之后绑定平台不改 Repo 身份、既有 Revision 与 Receipt，进行中的意图沿用原绑定版本
- 注册只在本地的仓库时缺省绑定本地平台：control 先持久化注册意图，有权限一方建仓，持 Git 凭据单元默认只推当前 HEAD 所在分支（无分支时取默认分支），其余 ref 须显式选择；不配置工作副本 remote 也能完成登记；没有提交时只建仓不推；私有保管引用、未准入 ChangeSet 分支和未显式发布的治理材料不随初始推送；平台上已有同名分支时不强制覆盖；结果未知时按关联键回读、不重复建仓；本地平台不可用时注册保持待确认，不改走不挂平台的路径；待确认阶段放弃注册时已建的平台仓库记为残留、不自动删除
- 平台由人声明并固定服务实例与平台仓库稳定标识；标识缺失时不能完成该绑定，远端 URL 不代替标识；辅助证据冲突时由人确认，不替人另猜身份；无平台仓库使用人显式登记的记录，不补共同根提交判据
- 人声明来自外部平台的仓库绑定该外部平台，本地平台不建镜像；绑定或换绑到本地平台的请求拒绝；人显式选择不挂平台时走受限路径，不因远端辅助证据改判
- 绑定了平台的 Repo 提交面向本地目标的集成意图时拒绝；本地平台上的评审请求、保护快照、授权形态与恢复按与外部平台相同的规则判定，本地平台停机时依赖平台回读的命令同样拒绝，随包不豁免
- 本地平台绑定的「检查」只声明为外部状态写回：契约要求的机械项以 `hctl2-tool` 回读的本地测试事实为证据，control 写回的提交状态不单独构成证据
- 结果未知按目标分：本地意图只回读本地事实、不等 PR；远端意图确定未投递的可重投，可能已写的保持未知并继续占用冲突范围，本地已有同一结果树也不解锁
- 平台失联时本地物化与封存继续，面向本地目标的集成只对显式不挂平台的 Repo 继续；发布评审、读 PR 状态与远端合入拒绝；平台丢失后不凭 Git 提交重建 Receipt
- 两控制面共用对象库时独立本地引用或平台源分支撞名，在写入前拒绝；非相交引用、独立工作树可并行；旧分支仍存在而已无有效写者或待决意图时，不凭分支名拒绝新授权，已有成果仍须保管
- 本地意图固定目标 A：写前解析不到 A 或只提供同名 B 时拒绝，可能已写却无法确认时保持原意图未知并占原冲突范围，不能改写 B；同路径新 clone 不证明目标连续，有证据证明 A 迁址时按原意图处理
- 两控制面各有同平台目标的待决意图时不加跨控制面锁；平台确认别人合法合入，双方分别核冻结条件，不当成违规或自己的授权：预期目标头不符拒绝，接受前移且其余条件匹配继续；无自己意图时不签自己的 Integration Receipt
- 契约事先接受平台精确集成事实时，Repo 回读源版本、实际结果与目标后向 Task 供 Evidence；squash/rebase 只用祖先关系、merged 标签或他人凭证不能证明精确结果，核不准即拒绝作该项证据
- 审计公开范围未授权全文时，不因代码库私有就发布私有治理全文；集成前不得关联「已集成」凭证，新版本不得显示旧批准，正文不可取不声称可读；获准关联固定来源控制面、精确版本、裁决/凭证引用摘要及允许公开结论，缺任一项拒绝写回
- 关联写回失败时集成仍成功、写回待同步；该写回已被列为冻结的必需交付项时 Task 不完成，未列时不因此阻止其余条件已满足的完成，不因写回失败临时加门；无平台路径不声称存在 PR 关联，普通 clone 不含私有审计副本，显式导出只交付获准范围

### `CT-CONNECTION` · 连接 / 端口

- 每条模块连接都必须固定来源引用、摘要和唯一绑定；缺任一项时目标准入必须拒绝
- Run/Invocation 冻结精确 Context Manifest ref+digest，每个实际 consumer 冻结对应 Context Bundle ref+digest，权限过滤、来源版本或预算变化使旧预览失效
- client/port 连接与绑定分离；同一产品同时作客户端与 provider 时不能借一侧身份写另一侧事实
- actor provenance 不能由 payload 自报
- dispatch/result 迟到拒绝
- 外部副作用的确认回执未知时不重复执行，adapter 也不写 Receipt
- provider 离线时，不要求当前回读的查询/命令可继续，要求当前 head/revision/租约/回读的准入统一 fail closed
- Harness 绕过受控端口的 API 写能力被拒绝，带外 drift 只形成 Snapshot/观测而不是结果
- Dagu、Vikunja、Herdr、Gitea 的私有对象 ID 或状态被提升为 HCTL 稳定身份、权限或完成判定时拒绝
- 新 provider/adapter 未通过对应模块契约测试时不得产生 Port–Provider Binding；换绑不能改写活动 Run、Task、Room、派工或集成意图的冻结绑定
- Project 或 Run 准入提案与 Repo 模块准入 ChangeSet Revision 在同一控制面事务；`hctl2-tool` 封存回读先于准入，缺任一步不产生获准版本
- Execution Spec 的评审发布策略作为字段冻结；Result Proposal 提供策略之外的发布地点或内容时拒绝
- Repo 模块不接收 Result Proposal；参与者直接向 Repo 模块提交版本或集成命令时拒绝
- 派工 outbox 携带物理或端点代次、Execution Spec 含接入方式或物理字段组、Result Proposal 头含运行时或代次栅栏时拒绝；规格与 Proposal 只带派工引用与语义引用；连接约束总表与四步写成两套话时失败，四步是顺序的权威
- 派工 outbox 携带旧 `control_writer_generation` 时租户拒绝；控制面甲读取、订阅、输入、取消或收取乙租户的派工时在结构上不可达，不需要门口逐次核对
- Attempt 归属的版本按 Run Manifest 冻结进 Execution Spec 的评审发布策略发布，发布 outbox 挂在 Run 准入提案的事务上；席位不能自行提交发布命令，但持凭据单元可执行获准源版本交付
- 既有 content 迁移必须显式预览、导出、导入并回读校验；普通换绑不得冒充无损迁移或热切换
- 客户端无等级：Workbench 通过 provider 通道执行的消息/卡片/终端动作与原生客户端同语义，通过 command service 的动作与 CLI 同语义；Workbench 不得依赖 provider 私有导航或对象模型获得隐藏权限
- provider event 只有模块绑定明确列出且 actor/target/version/idempotency/freshness 齐全时可成为 human command request；否则只能成为 content/Snapshot/运行时观测
- 飞书、Slack、Discord 等 Chat 互通只经 Matrix bridge 接入；HCTL 只校验 Matrix 事件与桥接身份映射，不注册逐平台 Chat adapter
- 材料引用只有摘要、没有可解析的控制面与范围时拒绝；绑定隐含范围可解析且摘要匹配时成立；后端迁址或索引重建后旧引用仍取回同一字节，不把后端目录混入冻结摘要
- 结果接收方只收到摘要不能确认字节保全；发送方保管至同一精确结果确认已保全。控制面恢复旧备份时按原授权与处理结果核验，原依据缺失走显式恢复，不凭候选或平台提交补授权
- 发布策略越到另一平台、未准入版本就发布、或以提案携带人命令时拒绝；内容在原冻结范围内获准后由 control 发一条发布意图，两段分别确认，推送成功但建请求未知时仅恢复未确认阶段

### `CT-SYSTEM` · 系统

- 同一用户级控制面存储只能有一个 control writer，第二 writer 拒绝
- 共用对象库的独立工作树可并行，不因同库整体互斥；冲突写权在旧写者停止或有效隔离得到证明前不重授，仅撤销逻辑权威或拒收旧结果而无物理隔离证据时拒绝。控制面重启不取得所有 clone 的锁，也不停止另一控制面的执行
- 命令幂等
- 危险动作（不可逆、产生外部权威副作用或扩大权限）未经确认的直接 Submit 拒绝；普通命令直接 Submit 与经 Preview 提交结果一致
- executor 越界拒绝：Git 交付由持相应凭据单元按冻结范围执行，PR 与平台合并仍须平台权限；lint/检查不经 `hctl2-tool` 意图回路，治理正文保存也不走 Repo 工具意图；以源分支权限更新目标或替控制面准入材料时拒绝
- 同一 human action 经 Workbench、CLI 或 provider adapter 进入时使用同一准入规则；重复、迟到和乱序 provider event 不产生第二份领域效果
- commit/确认回执各崩溃点回读
- schema migration、投影重建
- 对控制面存储执行一致性 backup、restore preview/apply、writer generation 重置与恢复后 content readback，每个首次消费的 content 服务器执行备份与恢复
- content 服务器宕机不抹掉已接纳事实，但依赖 provider 当前回读的命令 fail closed
- 从 Git 结晶回灌不得伪造未结晶判决
- 可重建的锁/缓存删除后可对账重建；尚未交付的唯一结果被当缓存删除时失败，只有接收方确认同版本字节已保全或人显式授权丢弃后才可清理；有独立可恢复副本的临时工作树可删，不要求原进程存活
- 一键启停下已消费服务器的启动顺序与健康检查
- 旧 generation（三种代次之一）与越权适配器拒绝
- 同一个人在两个控制面是两个 human actor：被归并、或一方的授权被当作另一方的授权时失败
- 远程控制面无认证连上 Agency 时拒绝；内部运行时被当作直连入口时拒绝；某个控制面退出或恢复导致共享 Agency 停机时失败，托管只影响本机随包服务
- 恢复推进 Agency 的代次或直读门后运行时、恢复等整个共享 Agency 对账、恢复删除了未确认意图与结果、恢复使别的租户失权、同一进程续做下一次派工沿用上次权限时失败；恢复只推进自己的写者代次并通知自己的租户、只等相关对账、保留未确认意图与结果、每次派工重新授权
- 权威地图仍写一人多机连同一控制面存储时失败：一份存储一个写者、多个前端连接它、一人可运行多个控制面
- 控制面进程直接调用 Agency 门后的运行时 API、约束层出现运行时适配或私有资源映射、进程内计算被当作工种派工并进 Proposal 通道时失败
- 等价对象的 JCS 规范摘要一致、内容篡改被 digest 校验拒绝
- 打包后的整窗启动/退出/升级和安全边界
- 材料存储不要求注册成 Repo 或另建 Room；人直接改材料 Git/ref 只产生候选，不推进准入/current；列版本使用治理记录，Git log 次序、候选或索引不能冒充获准历史；同字节可复用，不合并不同命令的领域版本
- 存入尚未持久保存字节或缺可恢复定位却返回成功时失败；取回逐项注入不存在、不可达、无权、摘要不符，必须返回不同结果；把正文摘要、完整 Revision 摘要和评审摘要互换时拒绝
- 已获准范围内封存遇控制面离线时可保存候选，未准入不得当获准版本；恢复按原授权、适用代次与精确结果处理，无原授权依据则显式恢复、不补批准
- 材料保存后、准入前崩溃：原命令重试返回原候选及一次准入结果；其间 GC 删除受保护候选时失败；准入前版本/权限/代次已变时拒绝，字节存在不证明获准
- 准入提交后响应丢失或镜像中断：同命令返回原领域结果，镜像继续待同步，不重新准入或重复副作用；记录还在而精确字节/定位丢失时，依赖命令暂停并要求显式恢复，不能填当前正文
- 旧逻辑写者不能推进治理记录或删除受保护正文；GC 只看 current 而删除待准入、待交付、在读快照或仍在保留期的历史时失败；多个前端写同一控制面仍经过同一逻辑写者
- 只备份记录、漏保留历史正文/定位/精确定义任一项时不能报告一致备份成功；同一快照承诺材料齐全、另有未准入候选时可通过。Git 副本可恢复字节，但不足以重建丢失的授权；恢复不改存储身份、不合并分叉记录
- 本地平台停机或未安装仍可存入、准入并读取本地治理材料；镜像未确认不能报告交付完成，镜像公开未准入私密候选时失败；旁路 ref 不能被当作权限隔离。平台数据库与代码 Git 各需自己的备份，材料镜像不冒充全部平台事实

### `CT-PACKAGING` · 扩展 / 打包

- 自声明 trust、有副作用的 discovery、未经用户配置的联网探测、静默 install/upgrade、非本地未认证 Dagu、renderer Node/raw IPC/远程脚本或不满足下述源码合规门禁时均拒绝
- 未声明的 capability/permission/scope、未声明的 IPC 或插件能力、远程运行时脚本/CDN 时拒绝；Electron 安全网形态下 renderer Node/raw IPC 同样拒绝
- 本地 Agency 参考实现缺配对认证、租户隔离、票据校验与转发、待交成果保管任一项却接受派工时失败；Herdr 只在交付文档与负例样本具名

### `CT-WORKBENCH-IA` · Workbench 信息架构

- 单 Project Overview 与全局「需要关注」都是可重建的只读导航投影，不产生新场景或写状态；Change 场景是 Repo 模块的场景，Overview 只投影它
- 打开入口按 repo 选择并统一映射到控制面连接（打开本地 repo = 连接或拉起本机控制面再定位仓库；远程入口隐藏或安全拒绝）
- 进入 Project 默认打开 Project Room，deep link 保留返回路径
- 同一 Request ID 跨 Room/Task/Run 聚合且不能从聚合面直接改状态
- 「创建 Project」命令提升预览允许删减、补充、去敏并显示来源回链
- Trigger Preview 展示实际执行者、Context/Skill、权限、预算和 fan-out
- 一个前端连两个控制面时把两份 Task 合成一份或丢了控制面来源时失败；第二期有权用户从远程前端对目标控制面预览并提交前置满足的治理命令时成功且只作用于目标控制面，无故拒绝失败；提交的治理动作丢失控制面来源或被当作本地动作时失败（按第二期跨机交付阶段验证，不要求第一期提前实现跨机）
- Workbench 不运行时，CLI、Matrix/Vikunja/Herdr 原生客户端、GitHub 页面与 `gh`、control 和已启动 Run 仍可独立工作，Change 场景对应的命令仍可达；安装 Workbench 不得增加公共命令服务尚未提供的 HCTL 命令

### `CT-WORKBENCH-INPUT` · Workbench 输入与无障碍

- Board 移动、Request 操作和 Run 浏览在 mouse/touch/keyboard/screen reader 下等价
- 输入优先级为 IME composition → 已聚焦 terminal → modal/composer → 当前场景 → 全局快捷键，任何上层快捷键都不能截获正在组合或发往 terminal 的输入

### `CT-PRODUCT` · 产品

- 用户十秒内能回答 Project 目标、Task 状态、Run 阻塞、所需动作、当前 Harness 和证据版本
- 正常成功保持安静
- HCTL2 仓库自举不使用隐藏的特例豁免或产品外补签事实
- 无 Run 路径、有契约的 Task、默认发布策略：从 ChangeSet 封存到完成凭证，人的预览不超过两次（合入、完成）；无契约卡只多一步采纳。发布评审的授权在封存之前的 Trigger Preview，不计入；显式确认开关的例外见下条
- 两条 B2 成功路径都成立：只在本地、缺省绑定本地平台的仓库，和受保护的 GitHub `main`；默认路径都是两次预览，不借 Gate 或特例权限过关
- 开了「发布评审须人显式确认」开关的仓库单独验收它的三次预览，不拿它给没开开关的仓库过关
- 显式不挂平台的受限路径另覆盖目标正被检出（人切离后重试）与确认丢失后的恢复
- 三条逃生口各走一遍：无契约卡只保留身份映射、来源与状态投影，不签完成凭证；采纳契约后完成的有 Task Completion Receipt；无 Run 路径与一票评审走到完成的都有可回溯的对象与凭证——没有一条路径「走完什么都不记」
- 某后端不响应时依赖它当前事实的命令按缓存猜、未确认的已发出动作被记成功、已确认的成功因断线改成未知、后端自愈被记成控制面的恢复动作时失败；依赖者拒绝、未确认记未知、已确认不改、自愈无感
